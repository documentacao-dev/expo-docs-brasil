## Entendendo development builds

Vamos começar entendendo o que são development builds e por que precisamos deles.

Um [development build](/develop/development-builds/introduction/) é uma versão de depuração do nosso projeto. Ele é otimizado para iterações rápidas durante a criação de um app. Ele contém a biblioteca [`expo-dev-client`](/versions/latest/sdk/dev-client/), que oferece um ambiente de desenvolvimento completo. Essa configuração nos permite integrar qualquer biblioteca nativa ou alterar o código dentro dos [diretórios nativos](/workflow/overview/#android-and-ios-native-projects), conforme a necessidade.

### Principais diferenças

> **Note:** Se você já conhece o [Expo Go](/get-started/set-up-your-environment/), pense em um development build como uma versão personalizável do Expo Go, feita para as necessidades específicas de um projeto.

| Recurso                           | Development builds                                                                                                                                                 | Expo Go                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| **Fase de desenvolvimento**       | Oferece a velocidade de iteração de um desenvolvimento web para apps mobile.                                                                                       | Permite iterar e testar rapidamente projetos com o Expo SDK usando o app cliente.                                             |
| **Colaboração**                   | Facilita os testes em equipe com um runtime nativo compartilhado.                                                                                                  | Compartilhamento fácil de projetos por QR codes em um dispositivo.                                                            |
| **Suporte a bibliotecas de terceiros** | Suporte completo a qualquer [biblioteca de terceiros](/workflow/using-libraries/#third-party-libraries), inclusive as que exigem código nativo personalizado. | Limitado às bibliotecas do Expo SDK, não é adequado para dependências nativas personalizadas.                                 |
| **Personalização**                | Personalização extensa com [config plugins](/config-plugins/introduction/) e acesso direto ao código nativo.                                                        | Personalização limitada, com foco nos recursos do Expo SDK e sem modificação direta do código nativo.                         |
| **Uso indicado**                  | Ideal para o desenvolvimento de apps completos voltados à publicação nas lojas, com um ambiente e ferramentas completos.                                           | Ideal para aprender, fazer protótipos e experimentar. Não é recomendado para apps em produção.                                |

## Instale a biblioteca expo-dev-client

Para preparar nosso projeto para um development build, vamos [`cd`](https://developer.mozilla.org/en-US/docs/Learn/Tools_and_testing/Understanding_client-side_tools/Command_line#basic_built-in_terminal_commands) até o diretório do projeto e rodar o comando a seguir para instalar a biblioteca:

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-dev-client'],
    yarn: ['$ yarn expo install expo-dev-client'],
    pnpm: ['$ pnpm expo install expo-dev-client'],
    bun: ['$ bun expo install expo-dev-client'],
  }}
/>

### Inicie o servidor de desenvolvimento

Rode `npx expo start` para iniciar o [servidor de desenvolvimento](/get-started/start-developing/#start-a-development-server):

<Terminal
  cmd={{
    npm: ['$ npx expo start'],
    yarn: ['$ yarn expo start'],
    pnpm: ['$ pnpm expo start'],
    bun: ['$ bun expo start'],
  }}
/>

Esse comando inicia o Metro bundler. Na janela do terminal, vemos o QR code seguido de `Metro:` e de uma URL de manifesto:

<ContentSpotlight
  alt="Servidor de desenvolvimento em execução"
  src="/static/images/tutorial/eas/configure-development-build-development-server.webp"
  className="max-w-[600px]"
/>

Vale notar as mudanças após instalar a biblioteca `expo-dev-client`:

- A URL de manifesto contém `__expo_url` junto com o scheme do app.
- O servidor de desenvolvimento agora funciona para um development build (em vez do Expo Go).

Como ainda não temos um development build instalado em nenhum dos nossos dispositivos ou em um emulador/simulador, ainda não podemos rodar o projeto.

</Step>

## Inicialize um development build

### Instale a EAS CLI

Precisamos instalar a ferramenta de interface de linha de comando (CLI) da EAS como dependência global na nossa máquina. Rode o comando a seguir:

<Terminal
  cmd={{
    npm: ['$ npm install --global eas-cli'],
    yarn: ['$ yarn global add eas-cli'],
    pnpm: ['$ pnpm add --global eas-cli'],
    bun: ['$ bun add --global eas-cli'],
  }}
/>

### Entre ou crie uma conta Expo

> Se você já tem uma conta Expo e está logado pela Expo CLI, pule esta etapa. Se não tiver uma conta Expo, [crie uma aqui](https://expo.dev/signup) e siga para o comando de login descrito abaixo.

Para fazer login, rode o comando a seguir:

<Terminal cmd={['$ eas login']} />

Esse comando pede o e-mail ou nome de usuário e a senha da nossa conta Expo para concluir o login.

### Inicialize e vincule o projeto ao Expo Services

Para qualquer projeto novo, o primeiro passo é inicializá-lo e vinculá-lo aos servidores da Expo. Rode o comando a seguir:

<Terminal cmd={['$ eas init']} />

Ao rodar, esse comando:

- Pergunta qual conta deve ser dona do projeto (quando temos mais de uma) e se queremos criar um projeto no Expo Services:

<Terminal
  cmd={[
    '# Output after running eas init',
    '✔ Which account should own this project? › your-username',
    '✔ Would you like to create a project for @your-username/sticker-smash? … yes',
    '✔ Created @your-username/sticker-smash',
    '✔ Project successfully linked (ID: XXXX-XX-XX-XXXX) (modified app.json)',
    '✔ Set the project icon from icon in your app config',
  ]}
/>

- Cria o projeto no Expo Services e fornece um link para ele, que podemos abrir no painel da Expo:

<ContentSpotlight
  alt="Novo projeto no painel da Expo"
  src="/static/images/tutorial/eas/configure-development-build-new-project.webp"
/>

- Gera um `projectId` único e vincula esse projeto do Expo Services ao app de exemplo na nossa máquina de desenvolvimento.
- Altera o **app.json** para incluir o [`extra.eas.projectId`](/versions/latest/sdk/constants/#easconfig) com o ID único criado e o [`owner`](/versions/latest/config/app/#owner) com o nome da conta dona do projeto.
- Envia o `icon` do **app.json** como ícone do projeto no painel da Expo, caso o projeto ainda não tenha um ícone.

<Collapsible summary={<>O que é o <CODE>projectId</CODE> no app.json?</>}>

Quando o `eas init` roda, ele associa um identificador único ao nosso projeto no **app.json**, em `extra.eas.projectId`. O valor dessa propriedade é usado para identificar nosso projeto nos servidores da Expo.

```json
{
  "extra": {
    "eas": {
      "projectId": "0cd3da2d-xxx-xxx-xxx-xxxxxxxxxx"
    }
  }
}
```

</Collapsible>

</Step>

## Configure o projeto para o Expo Build

Para preparar nosso projeto para o Expo Build, rode o comando a seguir:

<Terminal cmd={['$ eas build:configure']} />

Ao rodar, esse comando:

- Pede para escolher uma plataforma: **Android**, **iOS** ou **All**. Como estamos criando apps para Android e iOS, vamos escolher **All**.
- Cria o **eas.json** na raiz do diretório do projeto com a seguinte configuração:

```json eas.json
{
  "cli": {
    "version": ">= 24.12.1",
    "appVersionSource": "remote"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {
      "autoIncrement": true
    }
  },
  "submit": {
    "production": {}
  }
}
```

Esta é a configuração padrão do **eas.json** em um projeto novo. Ela faz duas coisas:

- Define a versão atual da EAS CLI.
- Adiciona três [perfis de build](/build/eas-json/#build-profiles): `development`, `preview` e `production`.

</Step>

<Collapsible summary="Explore melhor o perfil development">

O **eas.json** é um conjunto de diferentes perfis de build. Cada perfil é ajustado com configurações distintas para gerar tipos específicos de build. Esses perfis também podem incluir configurações específicas de plataforma, para Android ou iOS.

Por enquanto, nosso foco é o perfil `development`, que inclui a seguinte configuração:

- [`developmentClient`](/eas/json/#developmentclient): habilitado (`true`) para criar um build de depuração. Ele carrega o app usando a biblioteca `expo-dev-client`, que oferece ferramentas de desenvolvimento e gera um artefato de build para instalação em dispositivo ou emulador/simulador. Também permite usar o app no desenvolvimento local, já que suporta atualizar o JavaScript em tempo real.
- [`distribution`](/eas/json/#distribution): configurado como `internal` para indicar que queremos compartilhar o build internamente (em vez de enviá-lo às lojas de apps).

> **Note**: Os builds oferecem muitas opções de personalização, incluindo configurações específicas de plataforma e a possibilidade de estender configurações entre diferentes perfis de build. Saiba mais sobre [como personalizar perfis de build](/build/eas-json/#build-profiles).

</Collapsible>

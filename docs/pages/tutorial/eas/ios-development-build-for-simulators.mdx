Neste capítulo, vamos criar um development build que roda no iOS Simulator usando o Expo Build.

Development builds para o iOS Simulator são gerados no formato **.app**, diferente dos dispositivos iOS.

## Crie um perfil de build de simulador no eas.json \{#create-a-simulator-build-profile-in-easjson}

No **eas.json**, adicione um novo perfil de build chamado `ios-simulator` com a propriedade [`ios.simulator`](/eas/json/#simulator). Defina o valor dela como `true`:

{/* prettier-ignore */}
```json eas.json
{
  "build": {
    "development": {
      /* @hide ... */ /* @end */
    },
    /* @info The `simulator` property is required for iOS Simulator builds. */
    "ios-simulator": {
      "ios": {
        "simulator": true
      }
    }
    /* @end */
  }
}
```

Para um development build, é necessário definir as propriedades `developmentClient` e `distribution` no perfil. Para evitar repetição, podemos estender as propriedades do perfil `development`:

```json eas.json
{
  "ios-simulator": {
    /* @info The `extends` keyword inherits properties from the `development` profile. */
    "extends": "development",
    /* @end */
    "ios": {
      "simulator": true
    }
  }
}
```

## Development build para o iOS Simulator \{#development-build-for-ios-simulator}

<Step label="1">

### Crie \{#create}

Rode o comando `eas build` com `ios` como plataforma e `ios-simulator` como perfil de build:

<Terminal cmd={['$ eas build --platform ios --profile ios-simulator']} />

Esse comando nos faz as seguintes perguntas quando criamos o build pela primeira vez:

- **What would you like your iOS bundle identifier to be?** Pressione <kbd>Return</kbd> para escolher o valor padrão sugerido nesta pergunta. Isso vai adicionar o [`ios.bundleIdentifier`](/versions/latest/config/app/#bundleidentifier) no **app.json**.
- **iOS app only uses standard/exempt encryption?** Pressione <kbd>Y</kbd> para escolher o valor padrão sugerido nesta pergunta. Como nosso app não usa criptografia não isenta, a EAS CLI adiciona `ios.infoPlist.ITSAppUsesNonExemptEncryption: false` na [configuração do app](/workflow/configuration/). Esse valor controla a verificação de conformidade quando você publica o app no TestFlight ou na App Store. Se seu app usar criptografia não isenta, pressione <kbd>N</kbd> e confirme o próximo prompt. Nesse caso, a EAS CLI não altera a configuração do app. Você define o status da criptografia no App Store Connect.

Depois de responder às perguntas, o Expo Build entra na fila, e a EAS CLI fornece um link para ver os detalhes do build e acompanhar o progresso no painel da Expo:

<Collapsible summary="O que a página de detalhes do build contém?">

A página de detalhes do build mostra o tipo de build, o perfil, o ambiente, a versão do Expo SDK, a versão do app e o número do build. Ela também mostra o fingerprint, o hash do último commit e a identidade do dev ou do dono da conta que iniciou o build.

Na imagem acima, o status atual do **Build artifact** mostra que o build está em andamento. Ao terminar, essa seção vai oferecer a opção de baixar o build. Os **Logs** detalham cada etapa do processo de build iOS no Expo Build. Para não nos estendermos, não vamos explorar cada etapa aqui. Para saber mais, veja [processo de build iOS](/build-reference/ios-builds/).

</Collapsible>

<Collapsible summary="O que é o iOS bundle identifier?">

O `ios.bundleIdentifier` é um nome único do nosso app. Se publicarmos o app agora, a Apple App Store vai usar essa propriedade e o valor dela para identificar nosso app na loja.

Essa notação é definida como `host.owner.app-name`. Por exemplo, nosso app de exemplo tem `com.owner.stickersmash`, em que `com.owner` é o domínio e `stickersmash` é o nome do app.

</Collapsible>

</Step>

<Step label="2">

### Instale \{#install}

No terminal, quando o build terminar, a EAS CLI nos pergunta se queremos rodar o build em um iOS Simulator. Pressione <kbd>Y</kbd>.

<ContentSpotlight
  alt="A EAS CLI oferece automaticamente a opção de rodar um build no iOS Simulator"
  src="/static/images/tutorial/eas/ios-development-build-for-simulators-cli.webp"
  className="max-w-[800px]"
/>

<Collapsible summary="Alternativa: use o Expo Orbit">

Você pode usar o [Expo Orbit](https://expo.dev/orbit) para instalar o development build. Em **Build artifact** no painel da Expo, clique em **Open with Orbit** para instalar o development build no iOS Simulator.

</Collapsible>

</Step>

<Step label="3">

### Rode \{#run}

Inicie o servidor de desenvolvimento rodando o comando `npx expo start` no diretório do projeto:

<Terminal
  cmd={{
    npm: ['$ npx expo start'],
    yarn: ['$ yarn expo start'],
    pnpm: ['$ pnpm expo start'],
    bun: ['$ bun expo start'],
  }}
/>

Pressione <kbd>I</kbd> na janela do terminal para abrir o projeto no iOS Simulator.

</Step>

## Build de produção para Android \{#production-build-for-android}

Um [build de produção Android](/build/eas-json/#production-builds) tem o formato **.aab**, otimizado para distribuição na Google Play Store. Diferente dos builds **.apk**, arquivos **.aab** só podem ser distribuídos e instalados pela Google Play Store.

<Step label="1">

## Crie um build de produção \{#create-a-production-build}

Para criar um build de produção Android usando o perfil `production` padrão, abra o terminal e rode o comando a seguir. Como `production` está definido como perfil padrão no **eas.json**, não é preciso especificá-lo com a flag `--profile`.

<Terminal cmd={['$ eas build --platform android']} />

O comando acima coloca o build na fila. Repare no painel da Expo que a coluna **Version** mostra o version code incrementado automaticamente entre parênteses, por exemplo, `1.0.0 (2)`.

</Step>

## Release interno \{#internal-release}

Vamos definir a faixa (track) como `internal` no **eas.json**.

- Em `submit.production`, defina `track` como `internal`:

{/* prettier-ignore */}
```json
{
  /* @hide ... */ /* @end */
  "submit": {
    "production": {
      /* @info Set `track` to `internal`. */
      "android": {
        "track": "internal"
      }
      /* @end */
    }
  }
}
```

No trecho acima, adicionamos a propriedade [`track`](/eas/json/#track) e definindo o valor dela como `internal`, que também é o valor padrão. Com esse valor, o comando `eas submit` envia nosso build de produção e o publica para teste interno na Google Play Store.

- Agora rode o comando `eas submit` para publicar uma nova versão de teste interno:

<Terminal cmd={['$ eas submit --platform android']} />

- Esse comando vai criar automaticamente uma nova versão de teste interno no Google Play Console:

<ContentSpotlight
  alt="Release interno criado automaticamente no Google Play Console pelo Expo Submit"
  src="/static/images/tutorial/eas/play-store-18.png"
  className="max-w-[800px]"
/>

</Step>

<Step label="8">

## Release de produção \{#production-release}

Para fazer o release do app em produção:

- Altere o valor de `track` para `production` no **eas.json**:

```json
{
  /* @hide ... */ /* @end */
  "submit": {
    "production": {
      "android": {
        /* @info Change the track to `production`. */
        "track": "production"
        /* @end */
      }
    }
  }
}
```

- Também podemos usar o mesmo Expo Build que usamos para o release de teste interno. Rode o comando `eas submit` para publicar na Play Store:

<Terminal cmd={['$ eas submit --platform android']} />

- Para criar uma faixa e enviar nosso app para o processo de análise da Google Play Store, vá para **Test and release** > **Production** e, em **Releases**, selecione o build que queremos enviar para análise.

</Step>

<Step label="9">

## Release automatizado \{#automated-release}

Para os próximos releases, podemos simplificar o processo combinando a criação do build e o envio para a Play Store em uma única etapa, usando a flag [`--auto-submit`](/build/automate-submissions/) com o `eas build`:

<Terminal cmd={['$ eas build --platform android --auto-submit']} />

</Step>

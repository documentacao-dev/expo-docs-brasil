## Build de distribuição interna

Os builds de distribuição interna são ideais para compartilhar atualizações com os membros da equipe, permitindo que partes interessadas técnicas e não técnicas deem feedback diretamente. Diferente dos development builds, eles não exigem um servidor de desenvolvimento rodando, o que simplifica o processo de teste.

### Formas de distribuir um app internamente

Tanto o Google quanto a Apple oferecem mecanismos nativos para compartilhar apps internamente:

- **Android**: usando o beta do Google Play
- **iOS**: usando o TestFlight

No entanto, esses dois métodos tradicionais têm limitações. Por exemplo, o TestFlight permite apenas um build ativo por vez.

### Expo Build para uma distribuição mais rápida

O Expo Build acelera o processo. Ele cria links compartilháveis para os nossos builds e fornece instruções de uso. Ele tem uma configuração padrão pensada para facilitar a distribuição interna, oferecendo uma alternativa mais eficiente aos métodos tradicionais.

## Crie um build de distribuição interna

Para criar e distribuir um build com o Expo Build, precisamos seguir estes passos:

<Step label="1">

### Configure o perfil de build preview

Desde a configuração inicial no **eas.json**, já temos uma configuração padrão que inclui um perfil de build `preview`, pensado para a distribuição interna:

```json eas.json
{
  "build": {
    "preview": {
      /* @info The `distribution` in `preview` profile has its value set to `internal`. */
      "distribution": "internal"
      /* @end */
    }
  }
}
```

Isso é tudo que precisamos para criar nosso primeiro build de distribuição interna. O perfil de build `preview` do trecho acima tem a propriedade `distribution` com o valor `internal`. Esse valor nos permite compartilhar as URLs do build com qualquer pessoa, para que ela instale o app no próprio dispositivo sem precisar de um servidor de desenvolvimento para rodá-lo.

Como vimos nos capítulos anteriores, para builds que não são da loja de apps, o Android exige o formato **.apk** e o iOS exige o formato **.ipa**. Isso também vale para os builds de distribuição interna. Quando `distribution` está definido como `internal`, o Expo Build cria automaticamente o binário do app nesses formatos para os dispositivos.

</Step>

<Step label="2">

### Crie

Criar um build de distribuição interna exige [credenciais de assinatura do app](/app-signing/app-credentials/).

A assinatura de apps no Android não é restritiva e permite instalar qualquer arquivo **.apk** compatível.

Já a Apple tem regras mais rígidas para distribuição de apps em dispositivos iOS. Precisamos de um perfil de provisionamento ad hoc que liste explicitamente os dispositivos autorizados a rodar o app. Algumas organizações cujos apps atendem a requisitos específicos podem usar o [Apple Developer Enterprise Program](https://developer.apple.com/programs/enterprise/) para distribuir apps internamente para um público maior.

<Tabs>

<Tab label="Android">

- Use o perfil `preview` para iniciar um build Android:

<Terminal cmd={['$ eas build --platform android --profile preview']} />

- Como nosso build preview usa seu próprio Android Application ID, do capítulo anterior, a EAS CLI nos pede para **Generate a new Android Keystore**. Pressione <kbd>Y</kbd>.
- Esse comando dispara o Expo Build, e no painel da Expo podemos acompanhar o progresso do build:

</Tab>

<Tab label="iOS">

Apps assinados com um perfil de provisionamento ad hoc podem ser instalados por um dispositivo iOS cujo UDID esteja registrado no perfil de provisionamento.

- Para registrar mais dispositivos, use `eas device:create`. Esse comando registra um dispositivo iOS e nos dá uma URL ou QR code para compartilhar e registrar o dispositivo:

<Terminal cmd={['$ eas device:create']} />

- Esse comando registra um dispositivo iOS para a instalação do app, gerando uma URL (ou QR code) compartilhável para o registro do dispositivo.

  > **info** **Dica**: Esse comando permite registrar um dispositivo a qualquer momento. No entanto, só os builds criados depois do registro vão funcionar no dispositivo recém-adicionado.

  > **warning** **Em uma assinatura nova ou recém-renovada do Apple Developer Program, um dispositivo recém-registrado pode não ser instalável de imediato.** Registrar um dispositivo com a Expo não o registra na Apple. O dispositivo só é adicionado à Apple quando é incluído pela primeira vez em um build ou em uma reassinatura. Nesse tipo de assinatura, a Apple pode levar [de 24 a 72 horas](https://developer.apple.com/help/account/reference/device-registration-updates/) para processar o dispositivo antes que ele possa ser adicionado a um perfil de provisionamento. Se um build falhar logo depois de você registrar um dispositivo novo, aguarde a Apple concluir o processamento e rode o build de novo. Saiba mais sobre [gerenciar dispositivos](/build/internal-distribution/#managing-devices).

- Para criar o build preview, precisamos usar o perfil `preview` com o comando `eas build`:

<Terminal cmd={['$ eas build --platform ios --profile preview']} />

- Esse comando dispara o Expo Build, e no painel da Expo podemos acompanhar o progresso do build:

<ContentSpotlight
  alt="Detalhes e progresso do build preview iOS no painel da Expo"
  src="/static/images/tutorial/eas/internal-distribution-builds-ios-preview-build.webp"
  className="max-w-[800px]"
/>

<Collapsible summary={<>Método alternativo para registrar dispositivos usando <CODE>eas build:resign</CODE></>}>

O comando [`eas build:resign`](/app-signing/app-credentials/#re-signing-new-credentials) pode ser usado para reassinar um **.ipa** iOS existente com um novo perfil de provisionamento ad hoc, sem precisar de um build completo.

</Collapsible>

<Collapsible summary="Você está configurando o provisionamento empresarial?">

A assinatura do Apple Enterprise Program custa US$ 299 por ano, e [nem todas as organizações são elegíveis](https://developer.apple.com/programs/enterprise/). Por isso, você provavelmente vai usar o provisionamento ad hoc, que funciona com qualquer conta paga normal do Apple Developer.

Se você tiver uma [assinatura do Apple Developer Enterprise Program](https://developer.apple.com/programs/enterprise/), os usuários podem instalar seu app no dispositivo deles sem pré-registrar o UDID. Eles só precisam instalar o perfil no dispositivo e, então, podem acessar os builds existentes. Você vai precisar entrar com sua conta Apple Developer Enterprise durante o processo do `eas build` para configurar o provisionamento correto.

Se você distribuir seu app tanto pelo provisionamento empresarial quanto pela App Store, vai precisar de um bundle identifier distinto para cada contexto. Recomendamos uma destas opções:

- Em projetos gerados com a Expo CLI, use o [**app.config.js** para alternar identificadores dinamicamente](/tutorial/eas/multiple-app-variants/).
- Em [projetos React Native existentes](/bare/overview/), crie um `scheme` separado para cada bundle identifier e especifique o nome do scheme em perfis de build separados.

</Collapsible>

<Collapsible summary="Você está usando credenciais locais manuais?">

Se for o caso, confirme que seu **credentials.json** aponta para um perfil de provisionamento ad hoc ou empresarial que você gerou pelo Apple Developer Portal (atualize um **credentials.json** existente usado para outro tipo de distribuição ou substitua-o por um novo que aponte para o perfil de provisionamento certo). Atenção: a EAS CLI faz apenas uma validação limitada das suas credenciais locais, e você vai precisar cuidar do registro dos UDIDs dos dispositivos manualmente. Leia mais sobre [usar credenciais locais](/app-signing/local-credentials).

</Collapsible>

</Tab>

</Tabs>

</Step>

<Step label="3">

### Instale

Quando o build terminar, a seção Build artifact mostra que o build está concluído. Essa seção oferece os métodos disponíveis para rodar o build preview em um dispositivo Android ou iOS: o Expo Orbit e o botão Install.

- Abra a página de detalhes do build. Se estiver compartilhando o build com alguém, você pode enviar o link do build para essa pessoa. Ela vai conseguir abrir a página de detalhes do build ou os detalhes do artefato, que incluem o Expo Orbit.
- Conecte o dispositivo Android ou iOS à sua máquina por USB.
- Abra o app de barra de menus Orbit.
- Selecione o **Device** no app Orbit.
- Em **Build artifact**, clique em **Open with Orbit**.

<Collapsible summary="Alternativa: use Install e o QR code">

- Abra a página de detalhes do build. Se estiver compartilhando o build com alguém, você pode enviar o link da página do build. Ela vai conseguir abri-la e ver os detalhes do artefato, que incluem o Expo Orbit.
- Clique em **Install** na seção Build artifact para exibir o pop-up **Install on a test device**.
- Copie o link da seção **Send a link to a device** e envie-o para o dispositivo de teste.

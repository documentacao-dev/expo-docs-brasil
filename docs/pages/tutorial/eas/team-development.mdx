Updates geralmente corrigem pequenos bugs e enviam pequenas mudanças entre as publicações nas lojas de apps. Eles permitem atualizar as partes não nativas do nosso app de exemplo, como código JavaScript, estilos e imagens.

Neste capítulo, vamos usar o [Expo Update](/eas-update/introduction/) para compartilhar alterações com nossa equipe. Isso vai ajudar [nós e a equipe a compartilhar prévias](/review/overview/) da mudança com rapidez.

<Step label="1">

## Instale a biblioteca expo-updates \{#install-expo-updates-library}

Para inicializar nosso projeto e enviar um update, precisamos usar a biblioteca [`expo-updates`](/versions/latest/sdk/updates/). Rode o comando a seguir para instalá-la:

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-updates'],
    yarn: ['$ yarn expo install expo-updates'],
    pnpm: ['$ pnpm expo install expo-updates'],
    bun: ['$ bun expo install expo-updates'],
  }}
/>

</Step>

<Step label="2">

## Configure o Expo Update \{#configure-expo-update}

Para inicializar nosso projeto com o Expo Update, rode o comando a seguir:

<Terminal cmd={['$ eas update:configure']} />

Esse comando adiciona as propriedades [`updates`](/versions/latest/config/app/#updates) e [`runtimeVersion`](/eas-update/runtime-versions/#setting-runtimeversion) no **app.json**, que o nosso **app.config.js** lê por meio de `config`. Ele também adiciona um [`channel`](/eas/json/#channel) a cada perfil de build no **eas.json**:

{/* prettier-ignore */}
```json eas.json
{
  "build": {
    "development": {
      /* @hide ... */ /* @end */
      /* @info */
      "channel": "development"
      /* @end */
    },
    "ios-simulator": {
      /* @hide ... */ /* @end */
    },
    "preview": {
      /* @hide ... */ /* @end */
      /* @info */
      "channel": "preview"
      /* @end */
    },
    "production": {
      /* @hide ... */ /* @end */
      /* @info */
      "channel": "production"
      /* @end */
    }
  }
  /* @hide ... */ /* @end */
}
```

> **info** Nosso perfil `ios-simulator` estende o perfil `development`, então não faz sentido ter um `channel` separado para ele. Podemos remover com segurança o `ios-simulator.channel` do **eas.json**.

<Collapsible summary="E se o app.config.js não ler o app.json?">

Se seu **app.config.js** não usar os valores de `config` do **app.json**, a EAS CLI não consegue adicionar as propriedades `updates` e `runtimeVersion` para você. Em vez disso, ela imprime os valores para você adicioná-los manualmente ao **app.config.js**. Depois de adicioná-los, rode `eas update:configure` de novo para concluir a configuração.

</Collapsible>

<Collapsible summary="O que é um channel?">

[Channels](/eas-update/how-it-works/#conceptual-overview) são usados para agrupar builds. Se tivermos um build Android e um iOS, ambos publicados nas lojas, podemos dar aos dois um channel production. Depois, podemos dizer ao Expo Update para apontar para o channel production, e o update vai afetar todos os builds com esse channel.

</Collapsible>

</Step>

<Step label="3">

## Crie um development build \{#create-a-development-build}

Precisamos criar um novo development build, já que o último build não contém a biblioteca `expo-updates`. Rode o comando a seguir:

<Terminal cmd={['$ eas build --platform android --profile development']} />

> Estamos usando um development build para dispositivos Android para demonstrar os updates. No entanto, podemos usar `--platform all` ou `--platform ios` para criar um build para as duas plataformas ou só para iOS.

Depois que a nova versão do development build for criada, instale-a em um dispositivo.

</Step>

<Step label="4">

## Modifique o código JavaScript do app \{#modify-the-javascript-code-of-the-app}

Vamos modificar o código JavaScript do nosso app de exemplo. Se você não estiver usando o [app Sticker Smash](/tutorial/eas/introduction/#prerequisites), pode modificar qualquer parte do seu código para ver as mudanças no app.

Vamos alterar o texto do primeiro botão do nosso app de exemplo, que diz **Choose a photo**, para **Select a photo**.

```tsx src/app/(tabs)/index.tsx
<Button theme="primary" label="Select a photo" onPress={pickImageAsync} />
```

</Step>

<Step label="5">

## Publique um update \{#publish-an-update}

Em vez de criar um novo build para compartilhar essa mudança com a equipe para testes, vamos publicar um update:

<Terminal cmd={['$ eas update --channel development --message "Change first button label"']} />

No comando acima, usamos o channel `development`. Todo update está associado a um [nome de channel](/eas-update/how-it-works/#publishing-an-update). É parecido com cada commit que fazemos com o git, que está associado a uma branch do git.

Então, usamos o channel `development` no nosso perfil de build e publicamos um update nele. Isso diz ao Expo Update para entregar o update aos builds com o channel `development`. Quando criamos um channel do Expo Update, ele associa automaticamente o channel a uma branch com o mesmo nome.

Depois de publicar o update, a CLI imprime as informações dele.

<Step label="6">

## Veja o update ao vivo em um development build \{#preview-the-update-live-in-a-development-build}

Para ver o update ao vivo em um development build:

- Faça login na sua conta Expo dentro do development build.
- Abra a aba **Updates**.
- No Android, toque no card **Branch: development** e depois toque no update. No iOS, toque em **Open** ao lado do update com **Branch: development**.

</Step>

<Step label="7">

## Compartilhe mudanças com builds de prévia ou de produção \{#sharing-changes-with-preview-or-production-builds}

Os updates para builds que não são de desenvolvimento (prévia ou produção) são baixados automaticamente no dispositivo quando o app inicia e pede updates novos.

Qualquer membro da equipe que rodar o build de prévia ou de produção vai receber o update com as mudanças que enviarmos para essas branches específicas.

Por exemplo, para um build `preview`, podemos rodar:

<Terminal cmd={['$ eas update --channel preview --message "Change first button label"']} />

Aqui está um exemplo em que publicamos um update para o build `preview`. Para testar o update, feche o app à força e abra-o de novo duas vezes para baixar e ver as mudanças:

</Step>

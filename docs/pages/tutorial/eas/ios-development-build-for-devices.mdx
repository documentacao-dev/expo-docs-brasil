Neste capítulo, vamos criar um development build que roda em um dispositivo iOS usando o Expo Build.

Development builds para dispositivos iOS são gerados no formato **.ipa**, que é o padrão para instalar apps iOS.

<Prerequisites>
  <Requirement title="Conta de desenvolvedor Apple">
    Necessária para acessar as [credenciais](/app-signing/app-credentials/#ios) exigidas para assinar
    nosso app, já que cada build precisa ser assinado para comprovar que o app vem de uma origem
    confiável. O Expo Build ajuda a gerenciar essas credenciais.
  </Requirement>
  <Requirement title="Modo de Desenvolvedor ativado no iOS 16 ou superior">
    Instalar development builds no seu dispositivo exige que o Modo de Desenvolvedor esteja
    ativado. Se for a primeira vez ou se ele estiver desativado, veja como [ativar o Modo de
    Desenvolvedor](/guides/ios-developer-mode/).
  </Requirement>
</Prerequisites>

## Perfil de provisionamento

Para iniciar o desenvolvimento em um dispositivo iOS, precisamos:

- Registrar o dispositivo criando um novo [perfil de provisionamento](/app-signing/app-credentials/#provisioning-profiles).
- Baixar e instalar esse perfil no dispositivo.

<Step label="1">

### Registre um dispositivo iOS

Com a EAS CLI, rode o comando para registrar um novo dispositivo Apple:

<Terminal cmd={['$ eas device:create']} />

Esse comando nos faz as seguintes perguntas:

- **You're inside the project directory. Would you like to use the** **your-account-name** **account?** Pressione <kbd>Y</kbd>.
- **Apple ID.** Nesta etapa, digite seu Apple ID. Em seguida, a EAS CLI faz login na nossa conta de desenvolvedor Apple. Siga os passos na janela do terminal.
- **How would you like to register your devices?** Selecione **Website**, que gera uma URL de registro que pode ser aberta no dispositivo iOS.

> **info** **Dica**: Se você ou sua equipe tiverem vários dispositivos, pode compartilhar o link do perfil de provisionamento com eles para baixar e instalar o perfil.

</Step>

<Step label="2">

### Baixe e instale o perfil

No navegador de um dispositivo, abra o link fornecido na etapa anterior e toque no botão **Download Profile**.

<ContentSpotlight
  alt="Baixe o perfil de provisionamento"
  src="/static/images/tutorial/eas/ios-ad-hoc-01.jpg"
  className="max-w-[240px]"
/>

Abra o app **Settings** (Ajustes), que nos pede para registrar o dispositivo.

<ContentSpotlight
  alt="Instale o perfil de provisionamento"
  src="/static/images/tutorial/eas/ios-ad-hoc-02.jpg"
  className="max-w-[240px]"
/>

Toque em **Install** para registrar o dispositivo iOS.

<ContentSpotlight
  alt="Perfil de provisionamento instalado com sucesso"
  src="/static/images/tutorial/eas/ios-ad-hoc-03.jpg"
  className="max-w-[240px]"
/>

Depois que o perfil de provisionamento é instalado, o dispositivo nos redireciona de volta ao navegador, exibindo uma mensagem de sucesso que confirma a conclusão do processo.

</Step>

## Development build para dispositivo iOS

<Step label="1">

### Crie

Para criar um development build em um dispositivo iOS, confirme que, no perfil `build.development`:

- O `developmentClient` está definido como `true` no **eas.json**, o que já vem na configuração padrão.
- Depois, rode o comando `eas build` com `ios` como plataforma e `development` como perfil de build:

<Terminal cmd={['$ eas build --platform ios --profile development']} />

> **info** **Dica**: Na próxima vez que rodar o comando `eas build`, você também pode usar `-p` para especificar a plataforma. É a forma abreviada de `--platform`.

Esse comando nos faz as seguintes perguntas quando criamos o build pela primeira vez:

- **What would you like your iOS bundle identifier to be?** Pressione <kbd>Return</kbd> para escolher o valor padrão sugerido nesta pergunta. Isso vai adicionar o [`ios.bundleIdentifier`](/versions/latest/config/app/#bundleidentifier) no **app.json**, caso ele ainda não esteja definido.
- **Do you want to log in to your Apple account?** Como estamos criando um development build pela primeira vez, ele vai pedir para **Generate a new Apple Distribution Certificate**. Pressione <kbd>Y</kbd> nas duas vezes.
- **Select devices for the ad hoc build**. Esta é a parte principal, e por isso precisamos registrar um perfil de provisionamento antes. Aqui podemos selecionar um ou todos os dispositivos registrados e, depois, pressionar <kbd>Return</kbd> para instalar esse build neles mais tarde.

> **warning** **Em uma assinatura nova ou recém-renovada do Apple Developer Program, um dispositivo recém-registrado pode não ser instalável de imediato.** Registrar um dispositivo com a Expo não o registra na Apple. O dispositivo só é adicionado à Apple quando é incluído pela primeira vez em um build. Nesse tipo de assinatura, a Apple pode levar [de 24 a 72 horas](https://developer.apple.com/help/account/reference/device-registration-updates/) para processar o dispositivo antes que ele possa ser adicionado a um perfil de provisionamento. Por isso, um build pode falhar na primeira vez em que você incluir um dispositivo recém-registrado. Se isso acontecer, aguarde a Apple concluir o processamento e rode o build de novo.

> **info** **Somente se você pulou o capítulo do [iOS Simulator](/tutorial/eas/ios-development-build-for-simulators/):** a EAS CLI pergunta **iOS app only uses standard/exempt encryption?** Pressione <kbd>Y</kbd> para escolher o valor padrão sugerido nesta pergunta. Como nosso app não usa criptografia não isenta, a EAS CLI adiciona `ios.infoPlist.ITSAppUsesNonExemptEncryption: false` na [configuração do app](/workflow/configuration/). Esse valor controla a verificação de conformidade quando você publica o app no TestFlight ou na App Store. Se o seu app usar criptografia não isenta, pressione <kbd>N</kbd> e confirme o próximo prompt. Nesse caso, a EAS CLI não altera a configuração do app. Você define o status da criptografia no App Store Connect.

Depois de responder, o build entra na fila, e podemos acompanhar o progresso pelo link fornecido pela EAS CLI no painel da Expo:

<ContentSpotlight
  alt="Detalhes e progresso do development build iOS no painel da Expo"
  src="/static/images/tutorial/eas/ios-development-build-for-devices-details.webp"
  className="max-w-[800px]"
/>

<Collapsible summary="O que a página de detalhes do build contém?">

A página de detalhes do build mostra o tipo de build, o perfil, o ambiente, a versão do Expo SDK, a versão do app e o número do build. Ela também mostra o fingerprint, o hash do último commit e a identidade do dev ou do dono da conta que iniciou o build.

Na imagem acima, o status atual do **Build artifact** mostra que o build está em andamento. Ao terminar, essa seção vai oferecer a opção de baixar o build. Os **Logs** detalham cada etapa do processo de build iOS no Expo Build. Para não nos estendermos, não vamos explorar cada etapa aqui. Para saber mais, veja [processo de build iOS](/build-reference/ios-builds/).

</Collapsible>

<Collapsible summary="O que é o iOS bundle identifier?">

O `ios.bundleIdentifier` é um nome único do nosso app. Se publicarmos o app agora, a Apple App Store vai usar essa propriedade e o valor dela para identificar nosso app na loja.

Essa notação é definida como `host.owner.app-name`. Por exemplo, nosso app de exemplo tem `com.owner.stickersmash`, em que `com.owner` é o domínio e `stickersmash` é o nome do app.

</Collapsible>

</Step>

<Step label="2">

### Instale

Quando o build terminar, a seção Build artifact é atualizada, indicando que o build está concluído:

<ContentSpotlight
  alt="O Build artifact oferece a opção de baixar o development build para dispositivos iOS"
  src="/static/images/tutorial/eas/ios-development-build-for-devices-artifact.webp"
/>

Esta seção mostra os métodos disponíveis para rodar o development build em um dispositivo iOS: o Expo Orbit e o botão Install.

O [Expo Orbit](https://expo.dev/orbit) permite instalar o development build em um dispositivo iOS sem complicações. Para usar esse método:

- Conecte o dispositivo iOS à nossa máquina de desenvolvimento por USB.
- Abra o app de barra de menus Orbit.
- Selecione o **Device** no app Orbit.

<ContentSpotlight
  alt="Botão Open with Orbit no painel da Expo, em Build artifact"
  src="/static/images/tutorial/eas/ios-orbit.png"
  className="max-w-[300px]"
/>

- No painel da Expo, em **Build artifact**, clique em **Open with Orbit**.

Depois que o build é instalado, o app Orbit abre o development build no dispositivo.

<Collapsible summary="Alternativa: use o botão Install e o QR code">

O botão **Install** na seção **Build artifact** gera um QR code para uma instalação simples:

- Clique em **Install** para exibir um pop-up com o QR code.

<ContentSpotlight
  alt="O botão Install gera um QR code para instalar facilmente em dispositivos iOS"
  src="/static/images/tutorial/eas/ios-development-build-for-devices-qr-code.webp"
  className="max-w-[480px]"
/>

- Escaneie o QR code com a câmera do dispositivo iOS, abra o link e toque nele para baixar o development build no dispositivo.

</Collapsible>

</Step>

<Step label="3">

### Rode

Inicie o servidor de desenvolvimento rodando o comando `npx expo start` no diretório do projeto:

<Terminal
  cmd={{
    npm: ['$ npx expo start'],
    yarn: ['$ yarn expo start'],
    pnpm: ['$ pnpm expo start'],
    bun: ['$ bun expo start'],
  }}
/>

- No dispositivo, toque no ícone do app para abrir o development build.

<ContentSpotlight
  alt="Interface do launcher do development build em um dispositivo iOS"
  src="/static/images/tutorial/eas/ios-development-build-for-devices-launcher.webp"
  className="max-w-[240px]"
/>

- Use o recurso de sincronização de conta, garantindo que você esteja logado tanto na EAS CLI quanto no development build. Como já estamos logados na EAS CLI, o próximo passo é fazer login pela interface do seu development build.

<ContentSpotlight
  alt="Modal para fazer login na conta Expo no dispositivo iOS"
  src="/static/images/tutorial/eas/ios-development-build-for-devices-login.webp"
  className="max-w-[240px]"
/>

- Selecione, na lista em Development servers, o servidor que está rodando.

<ContentSpotlight
  alt="Servidor de desenvolvimento na lista em Development servers"
  src="/static/images/tutorial/eas/ios-development-build-for-devices-dev-servers.webp"
  className="max-w-[240px]"
/>

</Step>

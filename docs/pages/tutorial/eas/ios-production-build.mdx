## Build de produção para iOS

Um [build de produção para iOS](/build/eas-json/#production-builds) é otimizado para o App Store Connect da Apple, que permite distribuir builds para testadores pelo TestFlight e para usuários finais pela App Store. Esse tipo de build não pode ser instalado diretamente em um simulador ou dispositivo e só pode ser distribuído pelo App Store Connect.

<Step label="1">

## Crie um perfil de provisionamento de distribuição

Rode o comando `eas credentials` no terminal e depois responda aos prompts da EAS CLI da seguinte forma:

- **Select platform** iOS.
- **Which build profile do you want to configure?** Selecione production.
- **Do you want to log in to your Apple account?** Pressione <kbd>Y</kbd>. Isso faz login na nossa conta de desenvolvedor Apple.
- **What do you want to do?** Selecione **Build Credentials** e escolha **All: Set up all the required credentials to build your project**.
- Depois, ele pergunta se queremos reutilizar o Distribution Certificate anterior. Pressione <kbd>Y</kbd>.
- **Generate a new Apple Provisioning Profile?** Pressione <kbd>Y</kbd>. Esse será o perfil de provisionamento do app de produção.
- Depois que a EAS CLI configurar as credenciais, pressione <kbd>Ctrl</kbd> + <kbd>C</kbd> para sair da EAS CLI.

</Step>

<Step label="2">

## Crie um build de produção

Para criar um build de produção para iOS usando o perfil `production` padrão, abra o terminal e rode o comando a seguir. Como `production` está definido como perfil padrão no **eas.json**, não é preciso especificá-lo com a flag `--profile`.

<Terminal cmd={['$ eas build --platform ios']} />

> **info** **Somente se este for o seu primeiro build iOS deste projeto:** a EAS CLI pergunta **iOS app only uses standard/exempt encryption?** Pressione <kbd>Y</kbd> para escolher o valor padrão sugerido nesta pergunta. Como nosso app não usa criptografia não isenta, a EAS CLI adiciona `ios.infoPlist.ITSAppUsesNonExemptEncryption: false` na [configuração do app](/workflow/configuration/). Esse valor controla a verificação de conformidade quando você publica o app no TestFlight ou na App Store. Se o seu app usar criptografia não isenta, pressione <kbd>N</kbd> e confirme o próximo prompt. Nesse caso, a EAS CLI não altera a configuração do app. Você define o status da criptografia no App Store Connect.

O comando coloca o build na fila. Repare, no painel da Expo, que a coluna **Version** mostra o número de build incrementado automaticamente entre parênteses, por exemplo, `1.0.0 (2)`.

</Step>

<Step label="3">

## Envie o binário do app para a App Store

Para enviar o binário do app criado pelo nosso último Expo Build, rode o comando [`eas submit`](/submit/ios/):

<Terminal cmd={['$ eas submit --platform ios']} />

Depois de rodar esse comando, precisamos:

- **Select a build from EAS.** Vamos selecionar o ID do build mais recente.
- **Siga o prompt para fazer login na nossa conta Apple.** Quando ele perguntar **Reuse this App Store Connect API Key?**, pressione <kbd>Y</kbd>.

Isso vai iniciar o processo de envio.

</Step>

<Step label="4">

## Publique uma versão de teste interno

Depois que o processo de envio terminar, precisamos fazer login na conta de desenvolvedor Apple pelo navegador.

- Clique em **[Apps](https://appstoreconnect.apple.com/apps)** e localize o ícone do app.
- Clique no nome do app e, na barra de navegação, clique em **TestFlight**. Se o build acabou de ser enviado, pode levar alguns minutos para a Apple processá-lo antes que ele esteja disponível para distribuição pelo TestFlight.
- No App Store Connect, em **Internal Testing**, crie um grupo de teste. Isso vai nos permitir convidar usuários de teste.

<ContentSpotlight
  alt="Criar um grupo de usuários de teste no App Store Connect"
  src="/static/images/tutorial/eas/app-store-01.webp"
  className="max-w-[800px]"
/>

- Quando o grupo for criado, um e-mail será enviado a todos os usuários de teste.

<ContentSpotlight
  alt="E-mail enviado aos usuários de teste para o teste interno"
  src="/static/images/tutorial/eas/app-store-02.jpg"
  className="max-w-[240px]"
/>

- No e-mail, clique em **View in TestFlight**, aceite o convite e toque em **Install**.

<ContentSpotlight
  alt="App TestFlight mostrando o app para instalar"
  src="/static/images/tutorial/eas/app-store-03.jpg"
  className="max-w-[240px]"
/>

Depois disso, o app vai ser baixado no nosso dispositivo para podermos testá-lo.

> **info** Assim como no teste interno, também podemos criar um grupo para convidar testadores externos pelo TestFlight. Enquanto o teste interno tem um limite de 100 usuários, o TestFlight permite compartilhar uma versão de teste com até 10.000 testadores externos e oferece um link público para compartilhar. Para instruções passo a passo, veja [Distribuir um app iOS com o TestFlight](/submit/testflight/).

</Step>

<Step label="5">

## Envie o app para a App Store da Apple

Para preparar nosso app para envio à App Store, vá para a aba **App Store**:

- Preencha os metadados, forneça as capturas de tela de acordo com as diretrizes da Apple e também preencha os detalhes em **General**.

<ContentSpotlight
  alt="App Store Connect mostrando os detalhes do app e as capturas de tela"
  src="/static/images/tutorial/eas/app-store-04.png"
  className="max-w-[800px]"
/>

- Depois, selecione o build manualmente.

<ContentSpotlight
  alt="App Store Connect mostrando a seleção do build do app"
  src="/static/images/tutorial/eas/app-store-05.png"
  className="max-w-[800px]"
/>

> **Complete App Store listing**: Para preparar o app para a ficha na loja, veja [Criar recursos para a loja de apps](/guides/store-assets/) e aprenda a criar capturas de tela e prévias.

- Quando o app estiver pronto, clique em **Submit to App Review**. Depois disso, a Apple vai analisar nosso app e, se for aprovado, ele ficará disponível na App Store.

<ContentSpotlight
  alt="App Store Connect mostrando o envio do app para análise"
  src="/static/images/tutorial/eas/app-store-06.png"
  className="max-w-[800px]"
/>

</Step>

<Step label="6">

## Envios automatizados

Para os próximos lançamentos, podemos simplificar o processo combinando a criação do build e o envio para a App Store em uma única etapa, usando a flag [`--auto-submit`](/build/automate-submissions/) com o `eas build`:

<Terminal cmd={['$ eas build --platform ios --auto-submit']} />

> **info** Esse comando envia automaticamente seu build para o TestFlight, para teste interno, mas não envia o app para análise da App Store. Você ainda precisa promover manualmente o build do TestFlight para a App Store quando estiver pronto para o lançamento público. Para mais informações, veja [Comportamento padrão de envio para as lojas de apps](/build/automate-submissions/#default-submission-behavior-for-app-stores).

</Step>

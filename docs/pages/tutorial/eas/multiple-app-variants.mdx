Neste capítulo, vamos configurar nosso projeto para rodar vários tipos de build (development, preview, production) ao mesmo tempo em um único dispositivo. Essa configuração nos permite testar diferentes etapas do desenvolvimento do app sem precisar desinstalar e reinstalar versões diferentes.

Cada variante precisa de um Android Application ID e de um iOS Bundle Identifier exclusivos para permitir instalações simultâneas em um único dispositivo. Veja como os IDs são definidos no nosso arquivo **app.json**:

```json app.json
{
  "ios": {
    /* @info */
    "bundleIdentifier": "com.yourname.stickersmash"
    /* @end */
    /* @hide ... */ /* @end */
  },
  "android": {
    /* @info */
    "package": "com.yourname.stickersmash"
    /* @end */
    /* @hide ... */ /* @end */
  }
}
```

<Step label="1">

## Adicione o app.config.js para a configuração dinâmica

O **app.json** contém a configuração do app em um arquivo JSON. Ele é estático e não é ideal se quisermos usar [valores dinâmicos para certas propriedades](/workflow/configuration/#dynamic-configuration). Vamos adicionar Android Application IDs e iOS Bundle Identifiers diferentes para todos os perfis de build, com base em [variáveis de ambiente](/workflow/configuration/#switching-configuration-based-on-the-environment).

- Na raiz do projeto, crie um arquivo novo chamado **app.config.js**.
- No **app.config.js**, exporte uma função padrão que recebe `config` como argumento. Depois, vamos desestruturar o `config` para copiar todas as propriedades existentes do **app.json**.

```js app.config.js
export default ({ config }) => ({
  /* @info The `config` object copies all existing configuration from app.json file.*/
  ...config,
  /* @end */
});
```

</Step>

<Step label="2">

## Atualize os valores dinâmicos de acordo com o ambiente

Para identificar o tipo de build, vamos adicionar duas variáveis de ambiente chamadas `IS_DEV` e `IS_PREVIEW` para os perfis de build `development` e `preview` no **app.config.js**:

```js app.config.js
const IS_DEV = process.env.APP_VARIANT === 'development';
const IS_PREVIEW = process.env.APP_VARIANT === 'preview';
```

Depois, adicione duas funções que alteram dinamicamente o nome do app, o Android Application ID e o iOS Bundle Identifier:

```js app.config.js
const getUniqueIdentifier = () => {
  if (IS_DEV) {
    return 'com.yourname.stickersmash.dev';
  }

  if (IS_PREVIEW) {
    return 'com.yourname.stickersmash.preview';
  }

  return 'com.yourname.stickersmash';
};

const getAppName = () => {
  if (IS_DEV) {
    return 'StickerSmash (Dev)';
  }

  if (IS_PREVIEW) {
    return 'StickerSmash (Preview)';
  }

  return 'StickerSmash: Emoji Stickers';
};
```

Vamos usar `getAppName()` para atribuir valores dinâmicos de `name` ao app e `getUniqueIdentifier()` para diferenciar `android.package` e `ios.bundleIdentifier` nos builds de development e preview:

{/* prettier-ignore */}
```js app.config.js
export default ({ config }) => ({
  ...config,
  /* @info Using `getAppName()` for "name" property */
  name: getAppName(),
  /* @end */
  ios: {
    /* @info Include existing `ios` configuration from app.json */
    ...config.ios,
    /* @end */
    /* @info Using `getUniqueIdentifier()` for "bundleIdentifier" property */
    bundleIdentifier: getUniqueIdentifier(),
  },
  android: {
    /* @info Include existing `android` configuration from app.json */
    ...config.android,
    /* @end */
    /* @info Using `getUniqueIdentifier()` for "package" property */
    package: getUniqueIdentifier(),
  },
});
```

</Step>

<Step label="3">

## Configure o eas.json

No **eas.json**, adicione a variável de ambiente `APP_VARIANT`:

{/* prettier-ignore */}
```json eas.json|collapseHeight=440
{
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      /* @info Add `env.APP_VARIANT` to access the environment variable for the build profile*/
      "env": {
        "APP_VARIANT": "development"
      }
      /* @end */
    },
    "preview": {
      "distribution": "internal",
      /* @info Add `env.APP_VARIANT` to access the environment variable for the build profile*/
      "env": {
        "APP_VARIANT": "preview"
      }
      /* @end */
    }
    /* @hide ... */ /* @end */
  }
}
```

Rodar `eas build --profile development` agora vai definir `APP_VARIANT` como `development`.

> **Note**: Como alteramos o Android Application ID e o iOS Bundle Identifier, a EAS CLI vai nos pedir para gerar uma nova Keystore para Android e um novo perfil de provisionamento para iOS. Para saber mais sobre o que essas etapas incluem, veja o capítulo anterior.

Como nosso perfil de build `ios-simulator` estende `development`, essa configuração é aplicada automaticamente para os iOS Simulators.

</Step>

<Step label="4">

## Rode o servidor de desenvolvimento

> Depois que os builds forem concluídos, siga o mesmo procedimento dos capítulos anteriores para instalá-los em um dispositivo ou emulador/simulador.

Como identificamos nosso development build pela variável de ambiente `APP_VARIANT`, precisamos passá-la ao comando que inicia o servidor de desenvolvimento. Para isso, adicione um script `dev` no campo [`"scripts"`](https://docs.npmjs.com/cli/v10/using-npm/scripts) do **package.json** do projeto:

```json package.json
{
  "scripts": {
    "dev": "APP_VARIANT=development npx expo start"
  }
}
```

Rode o comando `npm run dev` para iniciar o servidor de desenvolvimento:

<Terminal
  cmd={{
    npm: ['$ npm run dev'],
    yarn: ['$ yarn run dev'],
    pnpm: ['$ pnpm run dev'],
    bun: ['$ bun run dev'],
  }}
/>

Esse script avalia o **app.config.js** localmente e carrega a variável de ambiente do perfil `development`.

Agora, nosso development build roda em Android e iOS. Ele exibe o nome do app modificado no **app.config.js**. Por exemplo, o development build abaixo está rodando em um iOS Simulator. Veja que o nome do app é **StickerSmash (Dev)**:

<ContentSpotlight
  alt="Variante de development rodando no iOS Simulator."

  className="max-w-[240px]"
/>

Agora você pode continuar usando o **app.json** para valores estáticos e o **app.config.js** para valores dinâmicos.

</Step>

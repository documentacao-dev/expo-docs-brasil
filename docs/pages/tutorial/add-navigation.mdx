## Noções básicas do Expo Router \{#expo-router-basics}

O Expo Router é um framework de roteamento baseado em arquivos para apps React Native e web. Ele gerencia a navegação entre telas e usa os mesmos componentes em várias plataformas. Para começar, precisamos conhecer as seguintes convenções:

- **Diretório app**: um diretório especial que contém apenas rotas e seus layouts. Qualquer arquivo adicionado a esse diretório vira uma tela dentro do nosso app nativo e uma página na web. No template padrão, ele fica em **src/app**.
- **Root layout**: o arquivo **src/app/\_layout.tsx**. Ele define elementos de interface compartilhados, como cabeçalhos e barras de abas, para que fiquem consistentes entre as diferentes rotas.
- **Convenções de nome de arquivo**: arquivos _index_, como **index.tsx**, têm o nome igual ao do diretório pai e não adicionam um segmento ao caminho. Por exemplo, o arquivo **index.tsx** no diretório **src/app** corresponde à rota `/`.
- Um arquivo de **rota** exporta um componente React como valor padrão. Ele pode usar a extensão `.js`, `.jsx`, `.ts` ou `.tsx`.
- Android, iOS e web compartilham uma estrutura de navegação unificada.

> A lista acima é suficiente para começarmos. Para ver a lista completa de recursos, consulte [Introdução ao Expo Router](/router/introduction/#key-features).

## Adicionar uma nova tela à pilha \{#add-a-new-screen-to-the-stack}

Vamos criar um novo arquivo chamado **about.tsx** dentro do diretório **src/app**. Ele exibe o nome da tela quando o usuário navega até a rota `/about`.

```tsx src/app/about.tsx|collapseHeight=300
import { Text, View, StyleSheet } from 'react-native';

export default function AboutScreen() {
  return (
    <View style={styles.container}>
      <Text style={styles.text}>About screen</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#25292e',
    justifyContent: 'center',
    alignItems: 'center',
  },
  text: {
    color: '#fff',
  },
});
```

Dentro de **src/app/\_layout.tsx**:

1. Adicione um componente `<Stack.Screen />` e uma prop `options` para atualizar o título da rota `/about`.
2. Atualize o título da rota `/index` para `Home` adicionando a prop `options`.

{/* prettier-ignore */}
```tsx src/app/_layout.tsx
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    /* @tutinfo Wrap screens inside `Stack` navigator. Add `options` prop to `/index` route. Add another `Stack.Screen` component to add `/about` route. */
    <Stack>
      <Stack.Screen name="index" options={{ title: 'Home' }} />
      <Stack.Screen name="about" options={{ title: 'About' }} />
    </Stack>
    /* @end */
  );
}
```

<Collapsible summary={<>O que é um <CODE>Stack</CODE>?</>}>

Um navegador de pilha (stack navigator) é a base para navegar entre diferentes telas de um app. No Android, uma rota empilhada é animada por cima da tela atual. No iOS, ela é animada a partir da direita. O Expo Router oferece um componente `Stack` para criar uma pilha de navegação e adicionar novas rotas.

## Navegar entre telas \{#navigate-between-screens}

Vamos usar o componente `Link` do Expo Router para navegar da rota `/index` até a rota `/about`. Ele é um componente React que renderiza um `<Text>` com uma prop `href` informada.

1. Importe o componente `Link` de `expo-router` dentro de **src/app/index.tsx**.
2. Adicione um componente `Link` depois do componente `<Text>` e passe a prop `href` com a rota `/about`.
3. Adicione um estilo com `fontSize`, `textDecorationLine` e `color` ao componente `Link`. Ele aceita as mesmas props do componente `<Text>`.

{/* prettier-ignore */}
```tsx src/app/index.tsx|collapseHeight=300
import { Text, View, StyleSheet } from 'react-native';
/* @tutinfo Import `Link` component from `expo-router`. */ import { Link } from 'expo-router'; /* @end */

export default function Index() {
  return (
    <View style={styles.container}>
      <Text style={styles.text}>Home screen</Text>
      /* @tutinfo Add `Link` component after `Text` component and pass the `href` prop with `/about` route. */
      <Link href="/about" style={styles.button}>
        Go to About screen
      </Link>
      /* @end */
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#25292e',
    alignItems: 'center',
    justifyContent: 'center',
  },
  text: {
    color: '#fff',
  },
  /* @tutinfo Add the style of `fontSize`, `textDecorationLine`, and `color` to `Link` component. */
  button: {
    fontSize: 20,
    textDecorationLine: 'underline',
    color: '#fff',
  },
  /* @end */
});
```

## Adicionar uma rota para páginas não encontradas \{#add-a-not-found-route}

Quando uma rota não existe, o Expo Router exibe uma tela padrão para ela. Podemos usar a rota `+not-found` para substituir essa tela por uma tela de fallback personalizada no celular e na web. O Expo Router usa um arquivo especial, **+not-found.tsx**, para tratar esse caso.

1. Crie um novo arquivo chamado **+not-found.tsx** dentro do diretório **src/app** para adicionar o componente `NotFoundScreen`.
2. Adicione a prop `options` do `Stack.Screen` para exibir um título de tela personalizado para essa rota.
3. Adicione um componente `Link` para navegar até a rota `/`, que é a nossa rota de fallback.

{/* prettier-ignore */}
```tsx src/app/+not-found.tsx
import { View, StyleSheet } from 'react-native';
import { Link, Stack } from 'expo-router';

export default function NotFoundScreen() {
  return (
    <>
      /* @tutinfo Add `Stack.Screen` component with `options` prop to update the title of `+not-found` route. */
      <Stack.Screen options={{ title: 'Oops! Not Found' }} />
      /* @end */
      <View style={styles.container}>
        /* @tutinfo Adding a fallback route allows the user to navigate to that screen. Here, the fallback route is Home screen. */
        <Link href="/" style={styles.button}>
          Go back to Home screen!
        </Link>
        /* @end */
      </View>
    </>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#25292e',
    justifyContent: 'center',
    alignItems: 'center',
  },

  button: {
    fontSize: 20,
    textDecorationLine: 'underline',
    color: '#fff',
  },
});
```

Para testar, acesse a URL `http://localhost:8081/123` no navegador, já que é fácil alterar o caminho da URL ali. O app deve exibir o componente `NotFoundScreen`:

## Adicionar um navegador de abas inferior \{#add-a-bottom-tab-navigator}

Neste ponto, a estrutura de arquivos do diretório **src/app** é a seguinte:

<FileTree
  files={[
    ['src/app/_layout.tsx', 'Root layout'],
    ['src/app/index.tsx', "corresponde à rota '/'"],
    ['src/app/about.tsx', "corresponde à rota '/about'"],
    ['src/app/+not-found.tsx', 'corresponde a qualquer rota 404'],
  ]}
/>

Vamos adicionar um navegador de abas inferior ao app e reaproveitar as telas Home e About existentes para criar um layout com abas. Esse é um padrão de navegação comum em muitos apps de redes sociais, como X e Bluesky. Também vamos usar o navegador de pilha no Root layout para que a rota `+not-found` seja exibida sobre quaisquer outros navegadores aninhados.

1. Dentro do diretório **src/app**, adicione um subdiretório **(tabs)**. Esse diretório especial é usado para agrupar rotas e exibi-las em uma barra de abas inferior.
2. Crie um arquivo **(tabs)/\_layout.tsx** dentro desse diretório. Ele será usado para definir o layout das abas, que é separado do Root layout.
3. Mova os arquivos **index.tsx** e **about.tsx** existentes para dentro do diretório **(tabs)**. A estrutura do diretório **src/app** ficará assim:

<FileTree
  files={[
    ['src/app/_layout.tsx', 'Root layout'],
    ['src/app/+not-found.tsx', 'corresponde a qualquer rota 404'],
    ['src/app/(tabs)/_layout.tsx', 'Tab layout'],
    ['src/app/(tabs)/index.tsx', "corresponde à rota '/'"],
    ['src/app/(tabs)/about.tsx', "corresponde à rota '/about'"],
  ]}
/>

Atualize o arquivo do Root layout para adicionar uma rota `(tabs)`:

{/* prettier-ignore */}
```tsx src/app/_layout.tsx
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    <Stack>
      /* @tutinfo This is how a tab navigator is nested inside a stack navigator, especially when the Root layout is composed of a parent stack navigator. We're also setting the `headerShown` option to `false` to hide the stack header for the `(tabs)` route. Otherwise, the header displays the route name `(tabs)` above the tabs. */
      <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
      /* @end */
    </Stack>
  );
}
```

Dentro de **(tabs)/\_layout.tsx**, adicione um componente `NativeTabs` para definir o layout da barra de abas inferior. [Abas nativas](/router/advanced/native-tabs/) usam a barra de abas nativa da plataforma no Android e no iOS:

{/* prettier-ignore */}
```tsx src/app/(tabs)/_layout.tsx
import { NativeTabs } from 'expo-router/native-tabs';

export default function TabLayout() {
  return (
    <NativeTabs>
      /* @tutinfo Each `NativeTabs.Trigger` adds a tab for the route in its `name` prop. `NativeTabs.Trigger.Label` sets the text of the tab. */
      <NativeTabs.Trigger name="index">
        <NativeTabs.Trigger.Label>Home</NativeTabs.Trigger.Label>
      </NativeTabs.Trigger>
      <NativeTabs.Trigger name="about">
        <NativeTabs.Trigger.Label>About</NativeTabs.Trigger.Label>
      </NativeTabs.Trigger>
      /* @end */
    </NativeTabs>
  );
}
```

As abas nativas não adicionam um cabeçalho às telas, então as telas Home e About não têm mais um. Na web, as abas aparecem como uma lista de rótulos no topo da página.

> **info** Na web, o console do navegador pode registrar um erro de hidratação ("A tree hydrated but some attributes of the server rendered HTML didn't match the client properties"). Esse é um problema conhecido do Expo Router com renderização no servidor ([expo/expo#52249](https://github.com/expo/expo/issues/52249)), e não um problema no código do tutorial. As abas continuam funcionando.

## Atualizar a aparência do navegador de abas inferior \{#update-bottom-tab-navigator-appearance}

No momento, o navegador de abas inferior não combina com o estilo do nosso app. Por exemplo, as abas não exibem ícones, e as cores da barra de abas não combinam com a cor de fundo do app.

Modifique o arquivo **src/app/(tabs)/\_layout.tsx** para adicionar ícones à barra de abas:

1. Adicione um componente `NativeTabs.Trigger.Icon` dentro de cada `NativeTabs.Trigger`. A prop `md` aceita um nome do [Material Symbols](https://fonts.google.com/icons) para Android. A prop `sf` aceita um nome do [SF Symbols](https://developer.apple.com/sf-symbols/) para iOS.
2. Passe um objeto com as chaves `default` e `selected` para a prop `sf`. O iOS exibe o ícone `selected` quando a aba está ativa.
3. Adicione a prop `tintColor` ao componente `NativeTabs` e defina o valor como `#ffd33d`. Isso muda a cor do ícone e do rótulo da aba ativa.

{/* prettier-ignore */}
```tsx src/app/(tabs)/_layout.tsx
import { NativeTabs } from 'expo-router/native-tabs';

export default function TabLayout() {
  return (
    <NativeTabs
      /* @tutinfo The `tintColor` prop changes the color of the active tab's icon and label. We will also use this color later in our app. */
      tintColor="#ffd33d"
      /* @end */
    >
      <NativeTabs.Trigger name="index">
        <NativeTabs.Trigger.Label>Home</NativeTabs.Trigger.Label>
        /* @tutinfo The `md` prop sets the icon on Android, and the `sf` prop sets the icon on iOS. */
        <NativeTabs.Trigger.Icon
          sf={{ default: 'house', selected: 'house.fill' }}
          md="home"
        />
        /* @end */
      </NativeTabs.Trigger>
      <NativeTabs.Trigger name="about">
        <NativeTabs.Trigger.Label>About</NativeTabs.Trigger.Label>
        /* @tutinfo */
        <NativeTabs.Trigger.Icon
          sf={{ default: 'info.circle', selected: 'info.circle.fill' }}
          md="info"
        />
        /* @end */
      </NativeTabs.Trigger>
    </NativeTabs>
  );
}
```

Os ícones não precisam de nenhuma etapa de instalação. No Android, a biblioteca `expo-symbols`, do template padrão, fornece os Material Symbols. No iOS, os SF Symbols fazem parte do sistema. Na web, as abas exibem apenas os rótulos.

Vamos também mudar a cor de fundo da barra de abas usando a prop `backgroundColor`:

```tsx src/app/(tabs)/_layout.tsx
<NativeTabs tintColor="#ffd33d" backgroundColor="#25292e">
```

A prop `backgroundColor` aplica `#25292e` à barra de abas no Android e na web. No iOS 26 e versões posteriores, `backgroundColor` não tem efeito: a barra de abas usa Liquid Glass, que acompanha a aparência clara ou escura do dispositivo.

## Atualizar as cores do ripple e do indicador no Android \{#update-the-ripple-and-indicator-colors-for-android}

No Android, a barra de abas ainda usa duas cores do tema padrão Material 3. Ao pressionar uma aba, aparece um efeito ripple. A aba ativa exibe um indicador atrás do seu ícone. Nenhuma dessas duas cores combina com a paleta do nosso app.

Adicione as props `indicatorColor` e `rippleColor` ao componente `NativeTabs` em **src/app/(tabs)/\_layout.tsx**:

{/* prettier-ignore */}
```tsx src/app/(tabs)/_layout.tsx
<NativeTabs
  tintColor="#ffd33d"
  backgroundColor="#25292e"
  /* @tutinfo Both colors use the yellow of the active tab, `#ffd33d`, with some transparency. */
  indicatorColor="rgba(255, 211, 61, 0.2)"
  rippleColor="rgba(255, 211, 61, 0.3)"
  /* @end */
>
```

No código acima:

- `indicatorColor` define a cor do indicador atrás da aba ativa no Android e a cor de fundo da aba ativa na web.
- `rippleColor` define a cor do efeito ripple que aparece quando o usuário pressiona uma aba no Android.

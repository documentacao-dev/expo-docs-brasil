> **info** Se você não tem um Mac ou um iPhone, pode testar o seu app iOS em um Simulador do iOS remoto com os Expo Simulators. [Conheça os Expo Simulators](/eas/simulators/introduction/).

Desenvolver o seu app diretamente no computador pode ser mais conveniente do que interagir o tempo todo com um iPhone ou iPad, principalmente quando a conexão de rede está lenta ou quando é necessária uma [conexão por túnel](/more/expo-cli/#tunneling) por causa das limitações da LAN.

Este guia explica como instalar o Simulador do iOS no seu Mac para desenvolver apps. Observe que o Simulador do iOS só pode ser instalado no macOS. Se você estiver desenvolvendo um app iOS em um computador com Windows ou Linux, precisará de um dispositivo iOS físico ou dos [Expo Simulators](/eas/simulators/introduction/).

## Limitações \{#limitations}

Embora o Simulador do iOS seja ótimo para o desenvolvimento rápido, ele tem algumas limitações. Listamos a seguir as principais diferenças que afetam as APIs do Expo. No entanto, consulte a [documentação da Apple](https://help.apple.com/simulator/mac/current/#/devb0244142d) para mais detalhes.

Os seguintes recursos de hardware não estão disponíveis no Simulador:

- Entrada de áudio
- Barômetro
- Câmera
- Suporte a movimento (acelerômetro e giroscópio)

O Simulador também suspende apps e processos em segundo plano no iOS 11 e versões posteriores.

## Solução de problemas \{#troubleshooting}

### A CLI parece travada ao abrir um Simulador \{#the-cli-seems-to-be-stuck-when-opening-a-simulator}

Às vezes, o Simulador do iOS não responde ao comando de abertura. Se parecer travado nesse prompt, inicie um simulador manualmente e rode o seu app de novo.

<Terminal
  cmd={[
    '# List the simulators installed on your Mac',
    '$ xcrun simctl list devices available',
    '',
    '# Start one of them by name',
    '$ xcrun simctl boot "iPhone 17"',
  ]}
/>

O Xcode 27 substitui o app Simulador pelo Device Hub. Rode `open -a DeviceHub` para abri-lo. Cada dispositivo em execução aparece na barra lateral. No Xcode 26, rode `open -a Simulator`.

<ContentSpotlight
  alt="Device Hub no macOS mostra um simulador iPhone 17 em execução na barra lateral."
  src="/static/images/ios-simulator/device-hub.webp"
/>

Você pode rodar mais de um simulador ao mesmo tempo. A CLI do Expo sempre usa o simulador aberto mais recentemente.

### O Simulador abriu, mas o app Expo Go não abre dentro dele \{#simulator-opened-but-the-expo-go-app-isnt-opening-inside-of-it}

Na primeira vez que você instalar o app no simulador, o iOS vai perguntar se você quer abrir o app Expo Go. Pode ser necessário interagir com o simulador (clicar em algum lugar, arrastar algo) para esse aviso aparecer e, então, pressionar **OK**.

### Como instalo uma versão específica do Expo Go? \{#how-do-i-install-a-specific-version-of-expo-go}

Você pode criar um projeto com a versão desejada do SDK e abri-lo em um simulador para instalar a versão correspondente do Expo Go.

<Terminal
  cmd={{
    npm: [
      '# Bootstrap an SDK 58 project',
      '$ npx create-expo-app --template blank@58',
      '',
      '# Open the app on a simulator to install the required Expo Go app',
      '$ npx expo start --ios',
    ],
    yarn: [
      '# Bootstrap an SDK 58 project',
      '$ yarn create expo-app --template blank@58',
      '',
      '# Open the app on a simulator to install the required Expo Go app',
      '$ yarn expo start --ios',
    ],
    pnpm: [
      '# Bootstrap an SDK 58 project',
      '$ pnpm create expo-app --template blank@58',
      '',
      '# Open the app on a simulator to install the required Expo Go app',
      '$ pnpm expo start --ios',
    ],
    bun: [
      '# Bootstrap an SDK 58 project',
      '$ bun create expo --template blank@58',
      '',
      '# Open the app on a simulator to install the required Expo Go app',
      '$ bun expo start --ios',
    ],
  }}
/>

Como alternativa, você pode baixar uma versão específica do Expo Go com a [CLI `expo-go`](https://www.npmjs.com/package/expo-go), passando a versão do SDK, ou usar `latest` para a versão mais recente do SDK. Esse comando baixa o app Expo Go para o diretório atual e o guarda em cache em **~/.expo**.

<Terminal
  cmd={{
    npm: ['$ npx expo-go download ios latest'],
    yarn: ['$ yarn dlx expo-go download ios latest'],
    pnpm: ['$ pnpm dlx expo-go download ios latest'],
    bun: ['$ bunx expo-go download ios latest'],
  }}
/>

### A CLI do Expo mostra uma mensagem de erro sobre o `xcrun`. O que faço? \{#expo-cli-is-printing-an-error-message-about-xcrun-what-do-i-do}

Para erros variados, tente o seguinte:

- Desinstale manualmente o Expo Go no seu simulador e reinstale pressionando <kbd>Shift</kbd> + <kbd>I</kbd> na interface de terminal da CLI do Expo e selecionando o simulador desejado.
- Se isso não resolver, selecione o simulador no Device Hub e escolha **Device** &gt; **Reset Content and Settings...**<br/>
  No app Simulador do Xcode 26, esse item de menu se chama **Erase All Content and Settings...**<br/>
  Isso vai reinicializar o seu simulador a partir de uma imagem em branco. Às vezes, isso é útil quando o computador está com pouca memória e o simulador não consegue armazenar alguns arquivos internos, deixando o dispositivo em um estado corrompido.

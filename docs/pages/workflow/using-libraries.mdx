Todo app vai inevitavelmente usar uma biblioteca de terceiros, por isso é importante entender como verificar se uma biblioteca é compatível com o seu projeto.

## Bibliotecas centrais do React Native

O React Native oferece um conjunto de primitivas integradas de que a maioria dos desenvolvedores vai precisar nos seus apps. Elas incluem componentes como `<ActivityIndicator>`, `<TextInput>`, `<Text>`, `<ScrollView>` e `<View>`. Eles estão listados em [Componentes e APIs principais](https://reactnative.dev/docs/components-and-apis) na documentação do React Native. Você também pode ver a [versão do React Native correspondente à sua versão do SDK do Expo](/versions/latest).

Para usar um componente ou API do React Native no seu projeto, importe-o do pacote `react-native` no seu código:

<SnackInline>

```tsx
import { Text, View } from 'react-native';

export default function App() {
  return (
    <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
      <Text>Hello, world!</Text>
    </View>
  );
}
```

</SnackInline>

## Bibliotecas do SDK do Expo

O SDK do Expo continua de onde as bibliotecas centrais do React Native param. Ele oferece acesso a muitas funcionalidades do dispositivo e do sistema, como áudio, leitura de códigos de barras, câmera, calendário, contatos, vídeo e assim por diante. Também adiciona outras bibliotecas poderosas, como atualizações, mapas, ferramentas de autenticação OAuth e mais. Para mais informações, veja como decidimos [o que entra no SDK do Expo](https://expo.fyi/whats-in-the-sdk).

Para usar uma biblioteca do SDK do Expo, encontre a que você procura na [referência da API](/versions/latest/) ou use a busca da documentação.

<ConfigReactNative>

Se você inicializou o seu app com `npx @react-native-community/cli@latest init` e ainda não tem o pacote `expo` instalado, veja o [guia de instalação dos módulos do Expo](/bare/installing-expo-modules) para mais informações.

</ConfigReactNative>

No topo de cada referência da API, você verá as etiquetas de compatibilidade com plataformas. Elas mostram com quais plataformas e ambientes a biblioteca é compatível. Por exemplo, as etiquetas de plataforma da biblioteca [`expo-device`](/versions/latest/sdk/device/) ficam assim:

O comando `npx expo install` escolhe uma versão da biblioteca compatível com o seu projeto e depois usa o gerenciador de pacotes JavaScript (como o npm) para instalá-la.

Em seguida, uma referência da API típica inclui:

- Informações de uso do config plugin, caso a biblioteca exija um config plugin.
- Um exemplo de código que mostra como usar a biblioteca.
- Uma seção da API que lista como importar a biblioteca, seguida de uma lista de hooks, props, tipos, métodos e classes que a biblioteca oferece.

> **Note**: se você usa TypeScript, pode ver as informações incluídas na seção da API no seu editor de código compatível com TypeScript (como o VS Code), com preenchimento automático.

## Bibliotecas de terceiros

### Encontrando uma biblioteca de terceiros

O [React Native Directory](https://reactnative.directory) é um banco de dados pesquisável de bibliotecas criado especificamente para o React Native. Se a biblioteca que você procura não for oferecida pelo React Native nem pelo SDK do Expo, este é o melhor lugar para começar a procurar uma biblioteca para o seu app.

Depois do React Native Directory, o [registro do npm](https://www.npmjs.com/) é o próximo melhor lugar. O registro do npm é a fonte definitiva de bibliotecas JavaScript, mas nem todas as bibliotecas listadas nele são compatíveis com o React Native. O React Native é um entre muitos ambientes de programação JavaScript, incluindo Node.js, navegadores web, Electron e outros, e o npm inclui bibliotecas que funcionam em todos esses ambientes. Qualquer biblioteca compatível com o React Native é compatível com o projeto Expo quando você cria um [development build](/workflow/overview/#development-builds). No entanto, ela pode não ser compatível com o app [Expo Go](https://expo.dev/go).

### Verificando a compatibilidade de uma biblioteca de terceiros

Use [development builds](/workflow/overview/#development-builds) do Expo para criar apps com qualidade de produção. Eles incluem todo o código nativo de que o seu projeto precisa para rodar. É uma ótima forma de testar o seu app antes de publicá-lo na App Store ou no Google Play. Você também pode incluir bibliotecas que exigem configuração dos projetos nativos (diretórios **android** e **ios**).

O Expo Go é um playground para estudantes e iniciantes testarem rapidamente o React Native. Ele não inclui todo o código nativo necessário para oferecer suporte a todas as bibliotecas, então é limitado e não serve para criar projetos de qualidade de produção. Você pode consultar o **React Native Directory** para encontrar uma biblioteca compatível com o Expo Go: visite o site e verifique se ela tem a etiqueta "✔️ Expo Go". Você também pode ativar o [filtro por Expo Go](https://reactnative.directory/?expoGo=true).

Para saber se uma nova dependência altera os diretórios do projeto nativo, você pode verificar o seguinte:

- A biblioteca inclui diretórios **android** ou **ios**?
- O README da biblioteca menciona vinculação (linking)?
- A biblioteca exige que você altere o **android/app/src/main/AndroidManifest.xml**, o **ios/Podfile** ou o **ios/Info.plist** para mudar a configuração do projeto?
- A biblioteca tem um [config plugin](/config-plugins/introduction/)?

**Se você respondeu sim a qualquer uma dessas perguntas,** então deve [criar um development build](/develop/development-builds/introduction/) para usar a biblioteca no seu projeto.

**Não está listada no diretório?** Você pode encontrar o projeto no GitHub. Uma forma simples de fazer isso é com `npx npm-home --github <nome-do-pacote>`. Por exemplo, para abrir a página do GitHub do `react-native-localize`, rode:

<Terminal
  cmd={{
    npm: ['$ npx npm-home --github react-native-localize'],
    yarn: ['$ yarn dlx npm-home --github react-native-localize'],
    pnpm: ['$ pnpm dlx npm-home --github react-native-localize'],
    bun: ['$ bunx npm-home --github react-native-localize'],
  }}
/>

> Se quiser ajuda para verificar a compatibilidade de uma biblioteca, [abra uma issue no repositório do React Native Directory](https://github.com/react-native-community/directory/issues/new/choose) e nos avise. Isso não ajuda só você: também ajuda outros desenvolvedores a terem uma resposta fácil no futuro!

### Instalando uma biblioteca de terceiros

> Recomendamos sempre usar `npx expo install` em vez de `npm install` ou `yarn add` diretamente, porque isso permite que a [CLI do Expo](/more/expo-cli/) escolha uma versão compatível da biblioteca quando possível e também avise sobre incompatibilidades conhecidas.

Depois de verificar que a biblioteca é compatível com o React Native, use a [CLI do Expo](/more/expo-cli/) para instalar o pacote:

<Terminal
  cmd={{
    npm: ['$ npx expo install @react-navigation/native'],
    yarn: ['$ yarn expo install @react-navigation/native'],
    pnpm: ['$ pnpm expo install @react-navigation/native'],
    bun: ['$ bun expo install @react-navigation/native'],
  }}
/>

Não deixe de seguir o site do projeto ou o README para quaisquer instruções adicionais de configuração e uso. Você pode chegar ao README rapidamente com este comando:

<Terminal
  cmd={{
    npm: ['$ npx npm-home @react-navigation/native'],
    yarn: ['$ yarn dlx npm-home @react-navigation/native'],
    pnpm: ['$ pnpm dlx npm-home @react-navigation/native'],
    bun: ['$ bunx npm-home @react-navigation/native'],
  }}
/>

Se o módulo precisar de configuração nativa adicional, você pode fazê-la usando [config plugins](/config-plugins/introduction/). Alguns pacotes exigem um config plugin, mas ainda não têm um. Nesse caso, você pode consultar a lista de [config plugins fora da árvore](https://github.com/expo/config-plugins/).

<ConfigReactNative>

Se o seu projeto não oferecer suporte ao [Expo Prebuild](/workflow/continuous-native-generation), você não poderá usar [config plugins](/config-plugins/introduction/). Você pode [adotar o Expo Prebuild](/guides/adopting-prebuild) ou configurar cada biblioteca manualmente, seguindo os guias de configuração adicional no site ou no README do respectivo módulo.

</ConfigReactNative>

### Excluindo uma biblioteca de terceiros das verificações de versão

Se você tiver uma versão específica de uma biblioteca de terceiros instalada e quiser que ela seja excluída das verificações de versão feitas pelo `npx expo install`, `npx expo-doctor` ou `npx expo start`, use a propriedade [`expo.install.exclude`](/versions/latest/config/package-json/#installexclude) no arquivo **package.json**.

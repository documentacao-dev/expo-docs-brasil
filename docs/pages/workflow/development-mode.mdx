Seu projeto sempre roda no modo **desenvolvimento** ou no modo **produção**. Por padrão, ao executar o projeto localmente com `npx expo start`, ele roda no modo de desenvolvimento, enquanto um projeto publicado (com `eas update`) ou qualquer app standalone roda no modo de produção.

O **modo de desenvolvimento** inclui avisos úteis e dá acesso a ferramentas que facilitam o desenvolvimento e a depuração. O **modo de produção** [minifica o seu código](/guides/customizing-metro/#minification) e reflete melhor o desempenho que o app terá nos dispositivos dos usuários finais. Vamos ver cada um desses modos com mais detalhes e aprender como alternar entre eles.

## Modo de desenvolvimento

O React Native inclui algumas ferramentas muito úteis para desenvolvimento: depuração remota de JavaScript no Chrome, live reload, hot reload e um inspetor de elementos parecido com o que você já usa no Chrome. Se quiser ver como usar essas ferramentas, veja [Depuração](/debugging/runtime-issues/).

O modo de desenvolvimento também faz validações enquanto o app está rodando, para mostrar avisos. Por exemplo, se você estiver usando uma propriedade descontinuada ou se esqueceu de passar a prop obrigatória para um componente. > **warning** **Isso tem um custo. Seu app roda mais devagar no modo de desenvolvimento.** <br /> Você pode ativar e desativar esse modo com o Expo CLI, veja [Modo de produção](#production-mode). Ao alternar, feche e reabra o app para que a mudança tenha efeito. **Sempre que for testar o desempenho do app, desative o modo de desenvolvimento**.

### Ver o menu do desenvolvedor

O menu dá acesso a vários recursos que facilitam bastante o desenvolvimento e a depuração. Para mais informações sobre como abri-lo no Android e no iOS, veja [Menu do desenvolvedor](/debugging/tools/#developer-menu).

## Modo de produção

O modo de produção é mais útil para duas coisas:

- Testar o desempenho do app, já que o modo de desenvolvimento deixa o app bem mais lento.
- Encontrar bugs que só aparecem em produção.

A forma mais fácil de simular como o projeto vai rodar nos dispositivos dos usuários finais é com o comando:

<Terminal
  cmd={{
    npm: ['$ npx expo start --no-dev --minify'],
    yarn: ['$ yarn expo start --no-dev --minify'],
    pnpm: ['$ pnpm expo start --no-dev --minify'],
    bun: ['$ bun expo start --no-dev --minify'],
  }}
/>

Ele executa o JavaScript do app no modo de produção (o que faz o Metro bundler definir a variável de ambiente `__DEV__` como `false`, entre algumas outras coisas). A flag `--minify` minifica o app e também elimina dados desnecessários, como comentários, formatação e código não utilizado. Se o seu app standalone apresentar erro ou travamento, executar o projeto com esse comando pode economizar bastante tempo para encontrar a causa raiz.

> **info** No modo de produção, os logs do console não aparecem no terminal do Expo CLI. Para acessá-los pelos logs nativos do dispositivo, veja [Ver logs do console no modo de produção](/workflow/logging/#view-console-logs-in-production-mode).

Para compilar o app por completo para produção, veja [Compilando para Android](/more/expo-cli/#compiling-android) e [Compilando para iOS](/more/expo-cli/#compiling-ios).

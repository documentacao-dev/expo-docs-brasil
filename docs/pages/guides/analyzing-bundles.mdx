O desempenho do bundle varia de acordo com a plataforma. Por exemplo, navegadores web não suportam bytecode pré-compilado, então o tamanho do bundle JavaScript é importante para melhorar o tempo de inicialização e o desempenho. Quanto menor o bundle, mais rápido ele pode ser baixado e interpretado.

## Analisando o tamanho do bundle com o Expo Atlas \{#analyzing-bundle-size-with-expo-atlas}

<ContentSpotlight alt="Página de visão geral do Expo Atlas." src="/static/images/atlas/atlas-overview.avif" />

As bibliotecas usadas em um projeto influenciam o tamanho do bundle JavaScript de produção. Você pode usar o [Expo Atlas](https://github.com/expo/expo-atlas#readme) para visualizar o bundle de produção e identificar quais bibliotecas contribuem para o tamanho do bundle.

### Usando o Atlas com `npx expo start` \{#using-atlas-with-npx-expo-start}

Você pode usar o Expo Atlas com o servidor de desenvolvimento local. Esse método permite que o Atlas seja atualizado sempre que você alterar qualquer código do projeto.

Depois que o app estiver rodando com o servidor de desenvolvimento local no Android, iOS e/ou web, você pode abrir o Atlas pelo [menu de plugins das ferramentas de desenvolvimento](/debugging/devtools-plugins/#using-a-dev-tools-plugin) usando <kbd>Shift</kbd> + <kbd>M</kbd>.

<Terminal
  cmd={{
    npm: ['# Start the local development server with Atlas', '$ EXPO_ATLAS=true npx expo start'],
    yarn: ['# Start the local development server with Atlas', '$ EXPO_ATLAS=true yarn expo start'],
    pnpm: ['# Start the local development server with Atlas', '$ EXPO_ATLAS=true pnpm expo start'],
    bun: ['# Start the local development server with Atlas', '$ EXPO_ATLAS=true bun expo start'],
  }}
/>

#### Mudando do modo de desenvolvimento para produção \{#changing-development-mode-to-production}

Por padrão, o Expo inicia o servidor de desenvolvimento local no [modo de desenvolvimento](/workflow/development-mode/#development-mode). O modo de desenvolvimento desativa algumas otimizações que estão ativas no [modo de produção](/workflow/development-mode/#production-mode). Você também pode iniciar o servidor de desenvolvimento local no modo de produção para obter uma representação mais precisa do tamanho do bundle de produção:

<Terminal
  cmd={{
    npm: [
      '# Run the local development server in production mode',
      '$ EXPO_ATLAS=true npx expo start --no-dev',
    ],
    yarn: [
      '# Run the local development server in production mode',
      '$ EXPO_ATLAS=true yarn expo start --no-dev',
    ],
    pnpm: [
      '# Run the local development server in production mode',
      '$ EXPO_ATLAS=true pnpm expo start --no-dev',
    ],
    bun: [
      '# Run the local development server in production mode',
      '$ EXPO_ATLAS=true bun expo start --no-dev',
    ],
  }}
/>

### Usando o Expo Atlas com `npx expo export` \{#using-expo-atlas-with-npx-expo-export}

Você também pode usar o Expo Atlas ao gerar um bundle de produção para o app ou para um Expo Update. Durante o export, o Atlas gera um arquivo **.expo/atlas.jsonl**, que você pode compartilhar e abrir sem precisar ter acesso ao projeto. Esse arquivo contém o código-fonte original e transformado de cada módulo empacotado, incluindo os valores das [variáveis de ambiente `EXPO_PUBLIC_`](/guides/environment-variables/) que foram embutidas. Trate esse arquivo como se fosse o código-fonte e compartilhe apenas com pessoas em quem você confia.

<Terminal
  cmd={{
    npm: [
      '# Export your app for all platforms',
      '$ EXPO_ATLAS=true npx expo export',
      '',
      '# Open the generated Expo Atlas file',
      '$ npx expo-atlas .expo/atlas.jsonl',
    ],
    yarn: [
      '# Export your app for all platforms',
      '$ EXPO_ATLAS=true yarn expo export',
      '',
      '# Open the generated Expo Atlas file',
      '$ yarn dlx expo-atlas .expo/atlas.jsonl',
    ],
    pnpm: [
      '# Export your app for all platforms',
      '$ EXPO_ATLAS=true pnpm expo export',
      '',
      '# Open the generated Expo Atlas file',
      '$ pnpm dlx expo-atlas .expo/atlas.jsonl',
    ],
    bun: [
      '# Export your app for all platforms',
      '$ EXPO_ATLAS=true bun expo export',
      '',
      '# Open the generated Expo Atlas file',
      '$ bunx expo-atlas .expo/atlas.jsonl',
    ],
  }}
/>

Você também pode especificar as plataformas que quer analisar com a opção `--platform`. O Expo Atlas coletará os dados apenas das plataformas exportadas.

### Analisando módulos transformados \{#analyzing-transformed-modules}

<ContentSpotlight alt="Página de módulo do Expo Atlas." src="/static/images/atlas/atlas-module.avif" />

No Atlas, segure <kbd>⌘ Cmd</kbd> e clique em um nó do grafo para ver os detalhes do módulo transformado. Esse recurso ajuda a entender como o módulo é transformado pelo Babel, quais módulos ele importa e quais módulos o importaram. Isso pode ser usado para rastrear a origem de um módulo ao longo do grafo de dependências.

## Analisando o tamanho do bundle com o source-map-explorer \{#analyzing-bundle-size-with-source-map-explorer}

> Método alternativo para o **SDK 50 e anteriores**.

Se você estiver usando o SDK 50 ou inferior, pode usar a biblioteca [`source-map-explorer`](https://www.npmjs.com/package/source-map-explorer) para visualizar e analisar o bundle JavaScript de produção.

<Step label="1">

Para usar o source map explorer, execute o comando a seguir para instalá-lo:

<Terminal
  cmd={{
    npm: ['$ npm install --save-dev source-map-explorer'],
    yarn: ['$ yarn add --dev source-map-explorer'],
    pnpm: ['$ pnpm add --save-dev source-map-explorer'],
    bun: ['$ bun add --dev source-map-explorer'],
  }}
/>

</Step>

<Step label="2">

Adicione um script ao **package.json** para executá-lo. Talvez seja preciso ajustar o caminho de entrada de acordo com a plataforma ou o SDK que você estiver usando. Para simplificar, o exemplo a seguir considera que o projeto usa o Expo SDK 50 e não usa a saída `server` do Expo Router.

```json package.json
{
  "scripts": {
    "analyze:web": "source-map-explorer 'dist/_expo/static/js/web/*.js' 'dist/_expo/static/js/web/*.js.map'",
    "analyze:ios": "source-map-explorer 'dist/_expo/static/js/ios/*.js' 'dist/_expo/static/js/ios/*.js.map'",
    "analyze:android": "source-map-explorer 'dist/_expo/static/js/android/*.js' 'dist/_expo/static/js/android/*.js.map'"
  }
}
```

Se você estiver usando a saída `server` do SDK 50 para web, use o seguinte para mapear os bundles web:

<Terminal
  cmd={{
    npm: [
      "$ npx source-map-explorer 'dist/client/_expo/static/js/web/*.js' 'dist/client/_expo/static/js/web/*.js.map'",
    ],
    yarn: [
      "$ yarn dlx source-map-explorer 'dist/client/_expo/static/js/web/*.js' 'dist/client/_expo/static/js/web/*.js.map'",
    ],
    pnpm: [
      "$ pnpm dlx source-map-explorer 'dist/client/_expo/static/js/web/*.js' 'dist/client/_expo/static/js/web/*.js.map'",
    ],
    bun: [
      "$ bunx source-map-explorer 'dist/client/_expo/static/js/web/*.js' 'dist/client/_expo/static/js/web/*.js.map'",
    ],
  }}
/>

Os bundles web são gerados no subdiretório **dist/client** para evitar expor o código do servidor ao cliente.

</Step>

<Step label="3">

Exporte o bundle JavaScript de produção incluindo a flag `--source-maps`, para que o source map explorer consiga ler os source maps. Para apps nativos que usam Hermes, você pode usar a opção `--no-bytecode` para desativar a geração de bytecode.

<Terminal
  cmd={{
    npm: [
      '$ npx expo export --source-maps --platform web',
      '',
      '# Native apps using Hermes can disable bytecode for analyzing the JavaScript bundle.',
      '$ npx expo export --source-maps --platform ios --no-bytecode',
    ],
    yarn: [
      '$ yarn expo export --source-maps --platform web',
      '',
      '# Native apps using Hermes can disable bytecode for analyzing the JavaScript bundle.',
      '$ yarn expo export --source-maps --platform ios --no-bytecode',
    ],
    pnpm: [
      '$ pnpm expo export --source-maps --platform web',
      '',
      '# Native apps using Hermes can disable bytecode for analyzing the JavaScript bundle.',
      '$ pnpm expo export --source-maps --platform ios --no-bytecode',
    ],
    bun: [
      '$ bun expo export --source-maps --platform web',
      '',
      '# Native apps using Hermes can disable bytecode for analyzing the JavaScript bundle.',
      '$ bun expo export --source-maps --platform ios --no-bytecode',
    ],
  }}
/>

Esse comando mostra no output os caminhos do bundle JavaScript e dos source maps. No próximo passo, você vai passar esses caminhos para o source map explorer.

> Evite publicar source maps em produção, pois eles podem causar problemas de segurança e de desempenho (o navegador vai baixar os mapas grandes).

</Step>

<Step label="4">

Execute o script para analisar o bundle:

<Terminal
  cmd={{
    npm: ['$ npm run analyze:web'],
    yarn: ['$ yarn run analyze:web'],
    pnpm: ['$ pnpm run analyze:web'],
    bun: ['$ bun run analyze:web'],
  }}
/>

Ao executar esse comando, você pode ver o seguinte erro:

```text
You must provide the URL of lib/mappings.wasm by calling SourceMapConsumer.initialize({ 'lib/mappings.wasm': ... }) before using SourceMapConsumer
```

Isso provavelmente se deve a um [problema conhecido](https://github.com/danvk/source-map-explorer/issues/247) no `source-map-explorer` no Node.js 18 e superiores. Para resolver, defina a variável de ambiente `NODE_OPTIONS=--no-experimental-fetch` antes de executar o script de análise.

</Step>

Você pode encontrar um aviso como `Unable to map 809/13787 bytes (5.87%)`. Isso acontece porque os source maps costumam excluir as definições do runtime do bundler (por exemplo, `__d(() => {}, [])`). Esse valor é consistente e não é motivo para preocupação.

## Lighthouse \{#lighthouse}

O Lighthouse é uma ótima forma de ver a velocidade, a acessibilidade e o desempenho do seu site. Você pode testar o projeto pela aba **Audit** do Chrome ou pela [CLI do Lighthouse](https://github.com/GoogleChrome/lighthouse#using-the-node-cli).

Depois de criar um build de produção com `npx expo export -p web` e servi-lo (usando `npx serve dist`, o deploy de produção ou um servidor personalizado), execute o Lighthouse com a URL em que o site está hospedado.

<Terminal
  cmd={{
    npm: [
      '# Install the lighthouse CLI',
      '$ npm install --global lighthouse',
      '',
      '# Run the lighthouse CLI for your site',
      '$ npx lighthouse <url> --view',
    ],
    yarn: [
      '# Install the lighthouse CLI',
      '$ yarn global add lighthouse',
      '',
      '# Run the lighthouse CLI for your site',
      '$ yarn dlx lighthouse <url> --view',
    ],
    pnpm: [
      '# Install the lighthouse CLI',
      '$ pnpm add --global lighthouse',
      '',
      '# Run the lighthouse CLI for your site',
      '$ pnpm dlx lighthouse <url> --view',
    ],
    bun: [
      '# Install the lighthouse CLI',
      '$ bun add --global lighthouse',
      '',
      '# Run the lighthouse CLI for your site',
      '$ bunx lighthouse <url> --view',
    ],
  }}
/>

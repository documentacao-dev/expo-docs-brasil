Uma feature flag (também chamada de _feature gate_) é um mecanismo que ativa e desativa funcionalidades remotamente. É uma forma segura de liberar gradualmente novas funcionalidades para os usuários do app, sem publicar código adicional. Você pode usá-las para testar em produção, fazer testes A/B ou lançar novos recursos do app, como elementos de interface.

## Serviços de feature flags \{#feature-flag-services}

As bibliotecas a seguir oferecem suporte a feature flags e funcionam sem configuração adicional com apps Expo que usam o [Continuous Native Generation (CNG)](/workflow/continuous-native-generation/) e [config plugins](/config-plugins/introduction/), para uma integração simples no app.

### PostHog \{#posthog}

O [PostHog](https://posthog.com/) é uma plataforma de análise de produto de código aberto que oferece um conjunto completo de feature flags, junto com análise de dados, gravações de sessão e testes A/B. Ele suporta toggles de funcionalidades em tempo real, com segmentação de usuários e a possibilidade de reverter funcionalidades instantaneamente. Por isso, é uma ótima escolha para equipes que querem análise e gerenciamento de funcionalidades em uma única plataforma. Ele inclui testes A/B e testes multivariados integrados, o que permite rodar experimentos diretamente pelas feature flags e acompanhar em detalhes a adoção e as métricas de desempenho das funcionalidades. O serviço também oferece suporte a bootstrap flags, que eliminam estados de carregamento e melhoram a experiência do usuário.

### Statsig \{#statsig}

O [Statsig](https://statsig.com/) é uma plataforma de gerenciamento de funcionalidades voltada ao desenvolvimento orientado a dados. Ela oferece análise estatística avançada, lançamentos graduais e segmentação sofisticada, além de métricas integradas e monitoramento de desempenho para os lançamentos de funcionalidades. A plataforma tem um SDK para React Native e Expo, com registro automático de eventos e configurações dinâmicas, o que a torna especialmente adequada para equipes focadas em experimentação rigorosa e tomada de decisão baseada em dados.

### LaunchDarkly \{#launchdarkly}

O [LaunchDarkly](https://launchdarkly.com/) é uma plataforma de gerenciamento de funcionalidades de nível empresarial, que permite ativar funcionalidades instantaneamente e fazer lançamentos segmentados. Ela tem controles completos no painel, segmentação avançada de usuários e ferramentas de experimentação com atualizações de flags em tempo real. O SDK inclui recursos avançados, como hooks para integração com React, identificação e modificação de contexto, logs completos, suporte a vários ambientes nos workflows de desenvolvimento, atributos privados para dados sensíveis e configuração de relay proxy para mais segurança e desempenho.

### Firebase Remote Config \{#firebase-remote-config}

O [Firebase Remote Config](https://firebase.google.com/docs/remote-config) é um serviço em nuvem que permite mudar a aparência e a funcionalidade do app sem exigir um update do app. Os valores do Remote Config são gerenciados pelo Firebase Console e acessados por uma API JavaScript, o que dá controle total sobre quando e como esses valores afetam o app. O serviço oferece segmentação condicional com base em propriedades do usuário, versões do app, atributos personalizados e atualizações em tempo real.

### Gates \{#gates}

O [Gates](https://usegates.app/) é um serviço de feature flags feito somente para apps Expo. O SDK avalia as flags no dispositivo, a partir de um snapshot salvo na última sincronização. Ler uma flag nunca faz uma requisição de rede, então as flags continuam funcionando offline. As regras podem ser aplicadas por plataforma, versão do app, versão de runtime do `expo-updates` e atributos do usuário, com lançamentos por porcentagem que se mantêm estáveis no dispositivo entre sessões. Um kill switch desativa uma flag em todos os ambientes na próxima sincronização. O SDK é apenas JavaScript e não exige um config plugin. Suas dependências peer `expo-application`, `expo-updates` e `@react-native-async-storage/async-storage` são módulos nativos, então um app que ainda não os inclui precisa de um novo build nativo. A CLI vincula o app a um projeto do Gates e instala o SDK com um único comando.

O cache de build é um recurso que acelera o `npx expo run:[android|ios]` ao armazenar builds remotamente em cache, com base no [fingerprint](/versions/latest/sdk/fingerprint/) do projeto.
Ao executar `npx expo run:[android|ios]`, o comando verifica se existe um build com um fingerprint correspondente. Se existir, ele baixa e abre esse build em vez de compilá-lo de novo. Caso contrário, o projeto é compilado normalmente e o binário resultante é enviado para o cache remoto para as próximas execuções.

## Usando o Expo Build como provedor de build \{#using-expo-build-as-a-build-provider}

Para usar o plugin de provedor do Expo Build, comece instalando o pacote `eas-build-cache-provider` como dependência de desenvolvimento:

<Tabs>

<Tab label="macOS/Linux">

<Terminal
  cmd={{
    npm: ['$ npx expo install eas-build-cache-provider --dev'],
    yarn: ['$ yarn expo install eas-build-cache-provider --dev'],
    pnpm: ['$ pnpm expo install eas-build-cache-provider --dev'],
    bun: ['$ bun expo install eas-build-cache-provider --dev'],
  }}
/>

</Tab>

<Tab label="Windows">

<Terminal
  cmd={{
    npm: ['$ npx expo install eas-build-cache-provider "--" --dev'],
    yarn: ['$ yarn expo install eas-build-cache-provider "--" --dev'],
    pnpm: ['$ pnpm expo install eas-build-cache-provider "--" --dev'],
    bun: ['$ bun expo install eas-build-cache-provider "--" --dev'],
  }}
/>

</Tab>

</Tabs>

Depois, atualize o **app.json** para incluir a propriedade `buildCacheProvider` e o provedor:

```json app.json
{
  "expo": {
    "buildCacheProvider": "eas"
    /* @hide ... */ /* @end */
  }
}
```

Você pode criar seu próprio provedor de cache exportando um plugin que implemente os seguintes métodos:

```ts
type BuildCacheProviderPlugin<T = any> = {
  /**
   * Try to fetch an existing build. Return its URL or null if missing.
   */
  resolveBuildCache(props: ResolveBuildCacheProps, options: T): Promise<string | null>;

  /**
   * Upload a new build binary. Return its URL or null on failure.
   */
  uploadBuildCache(props: UploadBuildCacheProps, options: T): Promise<string | null>;

  /**
   * (Optional) Customize the fingerprint hash algorithm.
   */
  calculateFingerprintHash?: (
    props: CalculateFingerprintHashProps,
    options: T
  ) => Promise<string | null>;
};

type ResolveBuildCacheProps = {
  projectRoot: string;
  platform: 'android' | 'ios';
  runOptions: RunOptions;
  fingerprintHash: string;
};
type UploadBuildCacheProps = {
  projectRoot: string;
  buildPath: string;
  runOptions: RunOptions;
  fingerprintHash: string;
  platform: 'android' | 'ios';
};
type CalculateFingerprintHashProps = {
  projectRoot: string;
  platform: 'android' | 'ios';
  runOptions: RunOptions;
};
```

Uma implementação de referência que usa GitHub Releases para armazenar builds em cache está disponível no [exemplo de provedor de cache de build](https://github.com/expo/examples/tree/master/with-github-remote-build-cache-provider).

## Limitações \{#limitations}

O provedor de cache de build é consultado apenas pelos comandos `npx expo run:[android|ios]` locais. Builds disparados com `eas build` não são afetados. Eles sempre geram artefatos novos e nunca acionam o plugin de provedor de cache.

Alguns builds locais também são ignorados:

- **Builds para dispositivo físico iOS.** Um build para dispositivo só é válido em aparelhos que correspondam ao seu provisioning profile, então reutilizá-lo entre máquinas ou dispositivos não é seguro. Por isso, o `npx expo run:ios` ignora tanto a busca no cache quanto o envio após o build quando o destino é um dispositivo físico. Apenas builds para o Simulador do iOS participam do cache.

Se você usa `appVersionSource: "remote"` no **eas.json**, lembre-se de que o `versionCode` (Android) e o `buildNumber` (iOS) ficam nos servidores da Expo, e não no código-fonte do projeto. Por isso, eles não fazem parte das entradas do fingerprint. Isso é adequado para o ciclo normal de desenvolvimento. As execuções locais de `npx expo run:*` não incrementam esses valores automaticamente, mas fique atento: um artefato em cache mantém o número de build que estava incorporado quando foi gerado originalmente.

## Criando um provedor de build personalizado \{#creating-a-custom-build-provider}

Comece criando um diretório **provider** para escrever o plugin de provedor em TypeScript e adicione um arquivo **provider.plugin.js** na raiz do projeto, que será o ponto de entrada do plugin.

<Step label="1">
### Crie o arquivo `provider/tsconfig.json` \{#create-a-providertsconfigjson-file}

```json provider/tsconfig.json
{
  "extends": "expo-module-scripts/tsconfig.plugin",
  "compilerOptions": {
    "outDir": "build",
    "rootDir": "src"
  },
  "include": ["./src"],
  "exclude": ["**/__mocks__/*", "**/__tests__/*"]
}
```

</Step>

<Step label="2">
### Crie o arquivo `provider/src/index.ts` para o plugin \{#create-a-providersrcindexts-file-for-your-plugin}

```ts provider/src/index.ts
import { type BuildCacheProviderPlugin } from '@expo/config';

const plugin: BuildCacheProviderPlugin = {
  resolveBuildCache: async () => {
    console.log('Searching for remote builds...');
    return null;
  },
  uploadBuildCache: async () => {
    console.log('Uploading build to remote...');
    return null;
  },
};

export default plugin;
```

</Step>

<Step label="3">
### Crie o arquivo `provider.plugin.js` no diretório raiz \{#create-an-providerpluginjs-file-in-the-root-directory}

```js provider.plugin.js
// This file configures the entry file for your plugin.
module.exports = require('./provider/build');
```

</Step>

<Step label="4">
### Compile o plugin de provedor \{#build-your-provider-plugin}

Na raiz do projeto, execute `npm run build provider` para iniciar o compilador TypeScript no modo watch.

</Step>

<Step label="5">
### Configure o projeto de exemplo para usar o plugin adicionando a seguinte linha ao arquivo `example/app.json`: \{#configure-your-example-project-to-use-your-plugin-by-adding-the-following-line-to-the-exampleappjson-file}

```json example/app.json
{
  "expo": {
    /* @hide ... */ /* @end */
    "buildCacheProvider": {
      "plugin": "./provider.plugin.js"
    }
  }
}
```

</Step>

<Step label="6">
### Teste o provedor \{#test-your-provider}
Ao executar o comando `npx expo run` dentro do diretório **example**, você deve ver no log as mensagens do console do plugin.

<Terminal
  cmd={[
    '# Navigate to the example directory',
    '$ cd example',
    '',
    '# Run the example on Android',
    '$ npx expo run:android',
    '',
    '# Run the example on iOS',
    '$ npx expo run:ios',
  ]}
/>

Pronto! Agora você tem um provedor de cache remoto de build para acelerar seus builds.

</Step>

### Passando opções personalizadas \{#passing-custom-options}

Para passar opções personalizadas ao plugin, use o campo `options`, que será repassado como segundo parâmetro das suas funções. Para isso, modifique o campo `buildCacheProvider` no **example/app.json**, como mostrado abaixo:

```json example/app.json
{
  "expo": {
    /* @hide ... */ /* @end */
    "buildCacheProvider": {
      "plugin": "./provider.plugin.js",
      "options": {
        "myCustomKey": "XXX-XXX-XXX"
      }
    }
  }
}
```

O [Convex](https://www.convex.dev/) é uma plataforma de backend para criar apps reativos, com banco de dados em tempo real, funções de servidor, armazenamento de arquivos, busca, agendamento e bibliotecas de cliente com tipagem segura, sem precisar gerenciar clusters, SQL ou ORMs.

A integração com o Expo Services pode criar e conectar o projeto do Convex para você, pela EAS CLI. Ela substitui as etapas manuais em que você instala o pacote, cria um time e um projeto no Convex, copia as URLs de deploy e configura as variáveis de ambiente do Expo Services.

<Prerequisites>
  <Requirement title="Conta Expo">
    Crie uma [conta Expo](https://expo.dev/signup).
  </Requirement>
  <Requirement title="EAS CLI">Instale a EAS CLI globalmente com `npm install -g eas-cli`.</Requirement>
  <Requirement title="Projeto Expo vinculado ao Expo Services">
    Crie um projeto Expo e vincule-o ao Expo Services com `eas init`.
  </Requirement>
</Prerequisites>

## Conecte o Convex ao Expo Services \{#connect-convex-with-expo-services}

<Step label="1">

### Execute o comando de integração da EAS CLI \{#run-the-eas-cli-integration-command}

No diretório do seu projeto Expo, execute:

<Terminal cmd={['$ eas integrations:convex:connect']} />

O comando vai pedir a região de deploy do Convex, o nome do projeto e o nome do time, quando for preciso. Ele só pede o nome do time quando precisa criar uma nova conexão de time no Convex.

Você também pode passar os valores explicitamente:

<Terminal
  cmd={[
    '$ eas integrations:convex:connect --region aws-us-east-1 --team-name "Your-team-name" --project-name "your-app"',
  ]}
/>

O comando de integração:

- Instala o pacote `convex` com `npx expo install convex`
- Cria uma conexão de time no Convex para sua conta Expo, ou reutiliza uma existente
- Cria um projeto e um deployment no Convex para o app Expo atual
- Grava `CONVEX_DEPLOY_KEY` e `EXPO_PUBLIC_CONVEX_URL` no **.env.local**
- Cria ou atualiza a variável de ambiente `EXPO_PUBLIC_CONVEX_URL` do projeto no Expo Services para os ambientes de produção, preview e desenvolvimento
- Envia um convite para seu e-mail verificado, para que você possa assumir o time do Convex e abrir o painel do Convex

</Step>

<Step label="2">

### Inicie o Convex localmente \{#start-convex-locally}

Quando o comando de integração terminar, inicie o servidor de desenvolvimento do Convex:

<Terminal
  cmd={{
    npm: ['$ npx convex dev'],
    yarn: ['$ yarn dlx convex dev'],
    pnpm: ['$ pnpm dlx convex dev'],
    bun: ['$ bunx convex dev'],
  }}
/>

Isso cria a pasta local **convex**, caso seu projeto ainda não tenha uma, gera os arquivos de API tipados e sincroniza suas funções do Convex com o deployment enquanto o servidor estiver rodando.

</Step>

<Step label="3">

### Adicione o provedor do Convex \{#add-a-convex-provider}

Crie um cliente do Convex com a URL de deployment que a integração do Expo Services gravou no **.env.local** e, em seguida, envolva seu app com `ConvexProvider`.

Em um projeto com Expo Router, atualize o **src/app/\_layout.tsx**:

```tsx src/app/_layout.tsx
import { ConvexProvider, ConvexReactClient } from 'convex/react';
import { Stack } from 'expo-router';

const convex = new ConvexReactClient(process.env.EXPO_PUBLIC_CONVEX_URL!, {
  unsavedChangesWarning: false,
});

export default function RootLayout() {
  return (
    <ConvexProvider client={convex}>
      <Stack />
    </ConvexProvider>
  );
}
```

</Step>

<Step label="4">

### Consulte o Convex no seu app \{#query-convex-from-your-app}

Adicione uma função de consulta na pasta **convex**:

```ts convex/tasks.ts
import { query } from './_generated/server';

export const get = query({
  args: {},
  handler: async ctx => {
    return await ctx.db.query('tasks').collect();
  },
});
```

Depois, chame-a no seu app com `useQuery`:

```tsx src/app/index.tsx
import { api } from '@/convex/_generated/api';
import { useQuery } from 'convex/react';
import { Text, View } from 'react-native';

export default function Index() {
  const tasks = useQuery(api.tasks.get);

  return (
    <View>
      {tasks?.map(task => (
        <Text key={task._id}>{task.text}</Text>
      ))}
    </View>
  );
}
```

</Step>

## Gerencie a integração \{#manage-the-integration}

Use estes comandos para inspecionar ou gerenciar a integração com o Convex depois:

<Terminal
  cmd={[
    '$ eas integrations:convex:project',
    '$ eas integrations:convex:dashboard',
    '$ eas integrations:convex:team',
    '$ eas integrations:convex:team:invite',
  ]}
/>

Se você remover o vínculo com `eas integrations:convex:project:delete` ou `eas integrations:convex:team:delete`, o Expo Services remove os metadados da integração. Esses comandos não apagam recursos no Convex.

## Solução de problemas \{#troubleshooting}

### Aceite um convite de time enviado para outro e-mail \{#accept-a-team-invite-sent-to-a-different-email}

O convite para o time do Convex é enviado para o e-mail verificado da sua conta Expo, mas o Convex só permite entrar com Google ou GitHub. Se o e-mail do Google ou do GitHub for diferente, a página do convite informa que o endereço de e-mail convidado não foi adicionado à sua conta do Convex. Se você sair dessa página, ficará em outra conta do Convex, que não contém seu projeto.

<ContentSpotlight
  alt="Página de convite do Convex mostrando que o endereço de e-mail associado ao convite do time não foi adicionado à sua conta"
  src="/static/images/guides/convex-invite-email-mismatch.webp"
/>

Para aceitar o convite a partir da sua conta do Convex existente:

1. Na página do convite (ou nas configurações de perfil do painel do Convex), clique em **Add email** e informe o endereço de e-mail convidado.
2. Abra o e-mail de verificação que o Convex envia para esse endereço e confirme-o.
3. Volte ao link do convite e recarregue a página, ou saia da conta e abra o link do convite novamente.
4. Aceite o convite. O time e o projeto agora aparecem na sua conta do Convex.

> **info** O fluxo pode parecer ter falhado depois da verificação do e-mail. A página do convite só é atualizada depois que você a recarregar ou reabrir.

A Expo CLI usa o [Metro](https://metrobundler.dev/) durante o [`npx expo start`](/more/expo-cli/#develop) e o [`npx expo export`](/more/expo-cli/#exporting) para fazer o bundle do seu código JavaScript e dos seus assets. O Metro foi criado e otimizado para React Native e é usado em apps de grande escala, como o Facebook e o Instagram.

## Personalização \{#customizing}

Você pode personalizar o bundler Metro criando um arquivo **metro.config.js** na raiz do projeto. Esse arquivo deve exportar uma [configuração do Metro](https://metrobundler.dev/docs/configuration/) que estende o [`expo/metro-config`](https://github.com/expo/expo/tree/main/packages/@expo/metro-config). Importe `expo/metro-config` em vez de `@expo/metro-config` para garantir a consistência de versões.

Execute o comando a seguir para gerar o arquivo de template:

<Terminal
  cmd={{
    npm: ['$ npx expo customize metro.config.js'],
    yarn: ['$ yarn expo customize metro.config.js'],
    pnpm: ['$ pnpm expo customize metro.config.js'],
    bun: ['$ bun expo customize metro.config.js'],
  }}
/>

O arquivo **metro.config.js** fica assim:

```js metro.config.js
const { getDefaultConfig } = require('expo/metro-config');

const config = getDefaultConfig(__dirname);

module.exports = config;
```

Veja a [documentação do **metro.config.js**](/versions/latest/config/metro) para mais informações.

> **info** O Expo bloqueia algumas opções de configuração do Metro para evitar que projetos quebrem. Nem toda opção aceita pelo Metro original pode ser personalizada ou tem suporte. O Expo também não oferece suporte ao carregamento de configurações do Metro a partir de arquivos YAML (descontinuado no projeto original) nem de configurações localizadas fora do seu repositório.

## Assets \{#assets}

O Metro resolve os arquivos como código-fonte ou como assets. O código-fonte é JavaScript, TypeScript, JSON e outros arquivos usados pelo seu app. [Assets](/develop/user-interface/assets/) são imagens, fontes e outros arquivos que não devem ser transformados pelo Metro. Para dar conta de bases de código grandes, o Metro exige que todas as extensões, tanto de código-fonte quanto de assets, sejam definidas explicitamente antes de iniciar o bundler. Isso é feito adicionando as opções `resolver.sourceExts` e `resolver.assetExts` na configuração do Metro. Por padrão, as seguintes extensões são incluídas:

- [`resolver.assetExts`](https://github.com/facebook/metro/blob/7028b7f51074f9ceef22258a8643d0f90de2388b/packages/metro-config/src/defaults/defaults.js#L15)
- [`resolver.sourceExts`](https://github.com/facebook/metro/blob/7028b7f51074f9ceef22258a8643d0f90de2388b/packages/metro-config/src/defaults/defaults.js#L53)

### Adicionando mais extensões de arquivo ao `assetExts` \{#adding-more-file-extensions-to-assetexts}

A personalização mais comum é incluir extensões extras de assets no Metro.

No arquivo **metro.config.js**, adicione a extensão do arquivo (sem o `.` inicial) ao array `resolver.assetExts`:

```js metro.config.js
const { getDefaultConfig } = require('expo/metro-config');

const config = getDefaultConfig(__dirname);

config.resolver.assetExts.push(
  // Adds support for `.db` files for SQLite databases
  'db'
);

module.exports = config;
```

## Aliases \{#aliases}

Às vezes você quer que um import seja redirecionado para outro módulo ou arquivo. Isso se chama alias. Por causa da forma como o Metro faz o bundle para várias plataformas ao mesmo tempo, recomendamos usar um resolver personalizado para lidar com os aliases.

No exemplo a seguir, vamos adicionar um alias de `old-module` para `new-module`:

```js metro.config.js
const { getDefaultConfig } = require('expo/metro-config');

/** @type {import('expo/metro-config').MetroConfig} */
const config = getDefaultConfig(__dirname);

const ALIASES = {
  'old-module': 'new-module',
};

config.resolver.resolveRequest = (context, moduleName, platform) => {
  // Ensure you call the default resolver.
  return context.resolveRequest(
    context,
    // Use an alias if one exists.
    ALIASES[moduleName] ?? moduleName,
    platform
  );
};

module.exports = config;
```

Se quiser aplicar o alias apenas em uma plataforma específica, você pode verificar o argumento `platform`:

```js metro.config.js
config.resolver.resolveRequest = (context, moduleName, platform) => {
  if (platform === 'web') {
    // The alias will only be used when bundling for the web.
    return context.resolveRequest(context, ALIASES[moduleName] ?? moduleName, platform);
  }
  // Ensure you call the default resolver.
  return context.resolveRequest(context, moduleName, platform);
};
```

As mudanças vão aparecer na próxima vez que você reiniciar o servidor de desenvolvimento. As resoluções nunca são armazenadas em cache e não precisam da flag `--clear` para serem atualizadas. Se você usar um sistema baseado em transformação, como o `babel-plugin-module-resolver`, precisará limpar o cache para ver as mudanças aplicadas.

## Observação e varredura de arquivos \{#file-watching-and-crawling}

A partir do **SDK 56**, o mapa de arquivos do Expo passa a oferecer suporte a acesso ao sistema de arquivos sob demanda. Na prática, isso significa que seu `watchFolders` não precisa mais incluir todos os módulos que o app empacota, e projetos que usam symlinks para dependências fora da raiz do projeto agora são resolvidos corretamente.

O sistema de arquivos sob demanda é controlado pela flag [`experiments.onDemandFilesystem`](/versions/v56.0.0/config/app/#ondemandfilesystem) no seu [app config](/workflow/configuration/) e vem ativado por padrão.

## Divisão do bundle \{#bundle-splitting}

A Expo CLI divide os bundles automaticamente com base em imports assíncronos (somente web).

Essa técnica pode ser usada com o Expo Router para dividir automaticamente o bundle com base nos arquivos de rota da pasta **app**. Ela carrega apenas o código necessário para a rota atual e adia o carregamento de JavaScript adicional até que o usuário navegue para outras páginas. Veja [Async Routes](/router/web/async-routes) para mais informações.

## Suporte à web \{#web-support}

A Expo CLI tem suporte para fazer o bundle de sites usando o Metro. É o mesmo bundler usado nos apps nativos, e foi projetado para ser universal entre plataformas. Ele é o bundler recomendado para projetos web.

### Expo webpack e Expo Metro \{#expo-webpack-versus-expo-metro}

Se você escreveu seu site antes usando o `@expo/webpack-adapter`, que foi descontinuado, veja o [guia de migração](/router/migrate/from-expo-webpack) e a [tabela comparativa](/router/migrate/from-expo-webpack#expo-cli).

### Adicionando suporte à web ao Metro \{#adding-web-support-to-metro}

Modifique seu [app config](/workflow/configuration) para ativar o recurso usando o campo `expo.web.bundler`:

```json app.json
{
  "expo": {
    "web": {
      "bundler": "metro"
    }
  }
}
```

#### Desenvolvimento \{#development}

Para iniciar o servidor de desenvolvimento, execute o comando a seguir:

<Terminal
  cmd={{
    npm: ['$ npx expo start --web'],
    yarn: ['$ yarn expo start --web'],
    pnpm: ['$ pnpm expo start --web'],
    bun: ['$ bun expo start --web'],
  }}
/>

Como alternativa, pressione <kbd>W</kbd> na interface do terminal da Expo CLI.

#### Arquivos estáticos \{#static-files}

A implementação do Metro no Expo oferece suporte a arquivos estáticos servidos pelo servidor de desenvolvimento. Basta colocá-los na pasta **public/** na raiz do projeto. É semelhante a vários outros frameworks web.

Ao exportar com `npx expo export`, o conteúdo da pasta **public** é copiado para a pasta **dist/**. Isso significa que seu app pode buscar esses assets em relação à URL do host. O exemplo mais comum é o **public/favicon.ico**, usado pelos sites para exibir o ícone da aba.

Você pode substituir o **index.html** padrão do Metro web criando um arquivo **public/index.html** no seu projeto.

No futuro, isso vai funcionar de forma universal em todas as plataformas com a hospedagem de updates do Expo. Atualmente, o recurso é exclusivo da web e depende do host estático usado pelo app nativo. Por exemplo, os updates do serviço legado do Expo não oferecem suporte a esse recurso.

> **warning** Alguns caminhos, como `/assets`, são reservados pelo Metro. Evite colocar arquivos em **public/assets/** ou em outros caminhos reservados. Veja [Caminhos reservados](/router/reference/reserved-paths/) para a lista completa.

## TypeScript \{#typescript}

A configuração do Metro no Expo oferece suporte aos campos `compilerOptions.paths` e `compilerOptions.baseUrl` do arquivo **tsconfig.json** (ou **jsconfig.json**) do projeto. Isso habilita imports absolutos e aliases no projeto. Veja o guia de [TypeScript](/guides/typescript) para mais informações.

Este recurso exige configuração adicional em [projetos React Native existentes](/bare/overview/). Veja o [guia de configuração do Metro](/versions/latest/config/metro#existing-react-native-apps) para mais informações.

[Resend](https://resend.com/) é uma plataforma de API de e-mail criada para desenvolvedores. Ela permite enviar, receber e gerenciar e-mails de forma programática por meio de uma API. Você pode usá-la para enviar e-mails transacionais em casos como newsletters, e-mails de marketing e outros. A API também permite configurar webhooks para eventos de e-mail, gerenciar domínios para entregabilidade e receber e-mails por meio de webhooks.

Este guia mostra os **passos essenciais para integrar o Resend ao seu projeto Expo e React Native**.

<Step label="1">

## Crie uma chave de API do Resend \{#create-a-resend-api-key}

Acesse o [painel do Resend](https://resend.com/api-keys) > **API Keys** e clique em **Create API Key** para gerar uma chave de API.

Depois de gerar a chave de API, salve-a no arquivo **.env.local** do seu projeto Expo:

```shell .env.local
RESEND_API_KEY=YOUR_RESEND_API_KEY
```

> **Note:** Não faça commit do arquivo **.env.local** no seu Sistema de Controle de Versão (VCS), como o Git. A chave de API é sensível e não deve ser exposta ao público. Você precisa adicionar o arquivo ao seu **.gitignore** para ignorá-lo.

</Step>

<Step label="2">

## Instale o SDK do Resend \{#install-resend-sdk}

No seu projeto Expo, instale o SDK do Resend com o comando a seguir:

<Terminal
  cmd={{
    npm: ['$ npx expo install resend'],
    yarn: ['$ yarn expo install resend'],
    pnpm: ['$ pnpm expo install resend'],
    bun: ['$ bun expo install resend'],
  }}
/>

O SDK do Resend é uma biblioteca exclusiva para servidor. Ela permite enviar e-mails a partir do código do lado do servidor do seu app. Como este guia usa [API Routes](/router/web/api-routes/) para processar os envios de e-mail, você precisa instalar o resend como parte do seu projeto Expo.

</Step>

<Step label="3">

## Ative e crie uma API route \{#enable-and-create-an-api-route}

Para usar API Routes no seu projeto Expo, defina `web.output` como `server` no arquivo de [app config](/workflow/configuration/):

```json app.json
{
  "web": {
    "output": "server"
  }
}
```

Em seguida, [crie uma API route](/router/web/api-routes/#create-an-api-route) para processar os envios de e-mail. Dentro do diretório **src/app**, crie um arquivo novo chamado **api/audience+api.ts**. A extensão `+api.ts` é usada pelo Expo Router para identificar o arquivo como uma API Route. Para testar a integração, você pode adicionar o código mínimo abaixo, que envia um e-mail para um destinatário usando o SDK do Resend:

```tsx src/app/api/audience+api.ts
import { Resend } from 'resend';

const resend = new Resend(process.env.RESEND_API_KEY);

export async function POST(request: Request) {
  const body = await request.json();
  const { email } = body;

  if (!email) {
    return Response.json({ success: false });
  }

  await resend.contacts.create({
    email: email,
    // Provide dynamic values on your own
    firstName: 'Steve',
    lastName: 'Wozniak',
    unsubscribed: false,
  });

  return Response.json({ success: true });
}
```

No trecho de código acima, a [função de requisição](/router/web/api-routes/#request-body) `POST` é executada quando a rota `/api/audience` é encontrada. A função recebe um objeto `Request` como argumento, que contém o corpo da requisição HTTP. Em seguida, a função extrai o `email` do corpo da requisição e o envia para a API do Resend para adicioná-lo à audiência.

</Step>

<Step label="4">

## Adicione uma URL base \{#add-a-base-url}

Para que a API route fique acessível pelo seu app Expo, adicione a URL base como uma variável de ambiente no seu projeto Expo. Inclua o código a seguir no seu arquivo **.env.local**:

```shell .env.local
EXPO_PUBLIC_BASE_URL=https://example-resend.expo.app # Deployed URL via Expo Hosting
EXPO_PUBLIC_BASE_URL_LOCAL=http://localhost:8081 # Only required for testing locally
```

Para testar a integração do Resend localmente, use `EXPO_PUBLIC_BASE_URL_LOCAL` para apontar para o seu servidor de desenvolvimento local, cuja URL é exibida quando você executa `npx expo start`. Mais adiante neste guia, quando você fizer o deploy do app no Expo Hosting, atualize `EXPO_PUBLIC_BASE_URL` para a URL publicada.

Observe que apenas variáveis com o prefixo `EXPO_PUBLIC_` podem ser usadas no código do frontend. Assim, você pode ter as variáveis acima e a chave de API do Resend no mesmo arquivo **.env**, mas `RESEND_API_KEY` só fica acessível no código do lado do servidor (ou seja, nos arquivos que terminam em **+api**).

</Step>

<Step label="5">

## Adicione um formulário ao seu projeto Expo \{#add-a-form-to-your-expo-project}

O exemplo a seguir mostra um formulário simples para coletar endereços de e-mail dos usuários do app. Em um cenário real, você deve adicionar validação e tratamento de erros ao formulário. Por exemplo, o código a seguir é adicionado ao arquivo **src/app/index.tsx**:

```tsx src/app/index.tsx
import { useRef, useState } from 'react';
import { Alert, Pressable, StyleSheet, Text, TextInput, View } from 'react-native';

export default function Index() {
  const [email, setEmail] = useState('');
  const inputRef = useRef<TextInput>(null);

  const handleSubmit = async () => {
    if (!email) {
      alert('Email is required.');
      return;
    }

    if (inputRef.current) {
      inputRef.current.blur();
    }

    try {
      const response = await fetch(
        `${process.env.EXPO_PUBLIC_BASE_URL_LOCAL}/api/audience`, // Switch to `EXPO_PUBLIC_BASE_URL` after deploying to Expo Hosting
        {
          method: 'POST',
          body: JSON.stringify({ email }),
        }
      );

      // You can handle other response validations here.

      await response.json();

      Alert.alert('Success', 'Email sent successfully.', [
        {
          text: 'Continue',
        },
      ]);
    } catch (error) {
      alert('Something went wrong.');
      console.error(error);
    }
  };

  return (
    <View style={styles.container}>
      <TextInput
        placeholder="Email"
        value={email}
        onChangeText={setEmail}
        ref={inputRef}
        autoCapitalize="none"
        keyboardType="email-address"
        style={styles.input}
      />
      <Pressable style={styles.button} onPress={handleSubmit}>
        <Text style={styles.buttonText}>Send email</Text>
      </Pressable>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
  },
  input: {
    borderWidth: 1,
    borderColor: 'gray',
    padding: 10,
    width: '60%',
    height: '6%',
    borderRadius: 10,
    marginBottom: 10,
    margin: 20,
  },
  button: {
    padding: 10,
    backgroundColor: '#000000',
    borderRadius: 10,
  },
  buttonText: {
    color: 'white',
    textAlign: 'center',
  },
});
```

</Step>

<Step label="6">

## Faça o deploy da API route no Expo Hosting \{#deploy-the-api-route-to-expo-hosting}

Para tornar a API route (`/api/audience`) acessível por uma URL, você pode fazer o deploy dela no [Expo Hosting](/eas/hosting/get-started/).

1. Execute o comando a seguir para exportar os assets da web e da API. Os arquivos exportados são salvos dentro de um diretório **dist**, e a API route faz parte desse diretório:

<Terminal
  cmd={{
    npm: ['$ npx expo export --platform web'],
    yarn: ['$ yarn expo export --platform web'],
    pnpm: ['$ pnpm expo export --platform web'],
    bun: ['$ bun expo export --platform web'],
  }}
/>

2. Execute o comando a seguir para criar um deploy de produção no Expo Hosting:

<Terminal cmd={['$ eas deploy --prod']} />

O comando `eas deploy --prod` vai:

- Criar automaticamente um projeto do Expo Services, caso você ainda não tenha um
- Pedir que você escolha a URL de preview do seu projeto. Confira se essa URL é a mesma do valor de `EXPO_PUBLIC_BASE_URL` no seu arquivo **.env.local**. Isso fará a API route ficar acessível pelo seu app Expo quando estiver publicado em produção

> **Note:** Antes do deploy, você precisa usar `EXPO_PUBLIC_BASE_URL` como o domínio hospedado no seu formulário (**src/app/index.tsx**).

</Step>

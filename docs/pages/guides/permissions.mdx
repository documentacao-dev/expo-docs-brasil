Quando você desenvolve um app nativo que precisa acessar informações potencialmente sensíveis do dispositivo do usuário, como localização ou contatos, o app precisa pedir a permissão do usuário antes. Por exemplo, para acessar a biblioteca de mídia do usuário, o app precisa executar [`MediaLibrary.requestPermissionsAsync()`](/versions/latest/sdk/media-library#medialibraryrequestpermissionsasyncwriteonly-granularpermissions).

Permissões em apps standalone e em [development builds](/develop/development-builds/introduction/) exigem configuração nativa no momento do build antes de poderem ser solicitadas pelo código JavaScript em tempo de execução. Isso não é necessário ao testar projetos no app [Expo Go](https://expo.dev/go).

> Se você não configurar nem explicar as permissões nativas corretamente, **seu app pode ser rejeitado ou removido das lojas**.

## Android \{#android}

As permissões são configuradas com as chaves [`android.permissions`](/versions/latest/config/app/#permissions) e [`android.blockedPermissions`](/versions/latest/config/app/#blockedpermissions) no seu [app config](/workflow/configuration/).

A maioria das permissões é adicionada automaticamente pelas bibliotecas que você usa, seja com [config plugins](/config-plugins/plugins/#creating-a-config-plugin), seja com um **AndroidManifest.xml** no nível do pacote. Você só precisa usar `android.permissions` para adicionar permissões extras que não vêm por padrão em uma biblioteca.

```json app.json
{
  "android": {
    "permissions": ["android.permission.SCHEDULE_EXACT_ALARM"]
  }
}
```

A única forma de remover permissões adicionadas por arquivos **AndroidManifest.xml** no nível do pacote é bloqueá-las com a propriedade [`android.blockedPermissions`](/versions/latest/config/app/#blockedpermissions). Para isso, informe o **nome completo da permissão**. Por exemplo, se você quiser remover as permissões de gravação de áudio adicionadas pelo `expo-camera`:

```json app.json
{
  "android": {
    "blockedPermissions": ["android.permission.RECORD_AUDIO"]
  }
}
```

- Veja [`android.permissions`](/versions/latest/config/app/#permissions) para saber quais permissões estão incluídas no [template de prebuild](/workflow/continuous-native-generation#templates) padrão.
- Apps que usam permissões _dangerous_ ou _signature_ sem motivos válidos **podem ser rejeitados pelo Google**. Siga as [boas práticas de permissões do Android](https://developer.android.com/training/permissions/usage-notes) ao enviar o seu app.
- [Todas as `Manifest.permissions` do Android disponíveis](https://developer.android.com/reference/android/Manifest.permission).

<ConfigReactNative>

Modifique o **AndroidManifest.xml** para excluir permissões específicas: adicione o atributo `tools:node="remove"` a uma tag `<use-permission>` para garantir que ela seja removida, mesmo que esteja incluída no **AndroidManifest.xml** de uma biblioteca.

```xml
<manifest xmlns:tools="http://schemas.android.com/tools">
  <uses-permission tools:node="remove" android:name="android.permission.ACCESS_FINE_LOCATION" />
</manifest>
```

> Você precisa definir o atributo `xmlns:tools` em `<manifest>` antes de usar o atributo `tools:node` nas permissões.

</ConfigReactNative>

## iOS \{#ios}

O seu app iOS pode pedir permissões do sistema ao usuário. Por exemplo, para usar a câmera do dispositivo ou acessar as fotos, a Apple exige uma explicação de como o seu app usa esses dados. A maioria dos pacotes fornece automaticamente um texto padrão para uma determinada permissão, com [config plugins](/config-plugins/introduction/). Essas mensagens padrão provavelmente precisarão ser adaptadas ao seu caso de uso para que o app seja aceito na App Store.

Para definir as mensagens de permissão, use a chave [`ios.infoPlist`](/versions/latest/config/app/#infoplist) no seu [app config](/workflow/configuration/), por exemplo:

```json app.json
{
  "ios": {
    "infoPlist": {
      "NSCameraUsageDescription": "This app uses the camera to scan barcodes on event tickets."
    }
  }
}
```

Muitas dessas propriedades também podem ser configuradas diretamente pelas propriedades do [config plugin](/config-plugins/introduction/) da biblioteca que as adiciona. Por exemplo, com o [`expo-media-library`](/versions/latest/sdk/media-library) você pode configurar as mensagens de permissão de fotos assim:

```json app.json
{
  "plugins": [
    [
      "expo-media-library",
      {
        "photosPermission": "Allow $(PRODUCT_NAME) to access your photos.",
        "savePhotosPermission": "Allow $(PRODUCT_NAME) to save photos."
      }
    ]
  ]
}
```

Para mostrar a mensagem de permissão no idioma do usuário, adicione a chave de descrição de uso correspondente, como `NSCameraUsageDescription`, no objeto `ios` de cada arquivo de locale. Veja [Traduzir metadados do app](/guides/localization/#translating-app-metadata) para a configuração e um exemplo.

- Alterações no **Info.plist** não podem ser enviadas por OTA. Elas só são publicadas quando você envia um novo binário nativo, por exemplo, com o [`eas build`](/build/introduction).
- As [recomendações oficiais da Apple para mensagens de permissão](https://developer.apple.com/design/human-interface-guidelines/privacy#Requesting-permission).
- [Todas as propriedades disponíveis do **Info.plist**](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/CocoaKeys.html).

<ConfigReactNative>

Adicione e altere os valores das mensagens de permissão diretamente no arquivo **Info.plist**. Recomendamos fazer isso diretamente no Xcode, para ter o autocompletar.

</ConfigReactNative>

## Web \{#web}

Na web, permissões como `Camera` e `Location` só podem ser solicitadas em um [contexto seguro](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts#When_is_a_context_considered_secure), por exemplo, usando `https://` ou `http://localhost`. Essa limitação é semelhante às permissões do manifest do Android e às mensagens de uso do **Info.plist** no iOS, e existe para aumentar a privacidade.

## Redefinir permissões \{#resetting-permissions}

Muitas vezes, você quer testar o que acontece quando o usuário recusa uma permissão, para garantir que o app reaja bem. Uma restrição do sistema operacional, tanto no Android quanto no iOS, impede que o app peça a mesma permissão mais de uma vez (imagine como seria irritante para o usuário ser solicitado repetidamente depois de recusar). Para testar diferentes fluxos envolvendo permissões durante o desenvolvimento, pode ser necessário desinstalar e reinstalar o app nativo.

Ao testar no [Expo Go](https://expo.dev/go), você pode excluir o app e instalá-lo de novo executando `npx expo start` e pressionando <kbd>I</kbd> ou <kbd>A</kbd> na interface de terminal da [Expo CLI](/more/expo-cli/).

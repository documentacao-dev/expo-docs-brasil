A nova API do `expo-media-library`, baseada em classes, agora é estável. A API legada está disponível em `expo-media-library/legacy`. Migre para o import da raiz `expo-media-library` para aproveitar a nova API e as correções futuras.

A nova API substitui o estilo baseado em funções `MediaLibrary.getAssetsAsync({ ... })` pelas classes `Asset`, `Album` e `Query`. Álbuns e assets agora são representados como instâncias de classe que guardam apenas o ID do asset nativo. As propriedades do asset são getters assíncronos, em vez de campos pré-carregados. `Query` substitui a função `getAssetsAsync` por um padrão de builder encadeável.

## Instalação \{#installation}

Instale o pacote compatível com o SDK:

<Terminal cmd={['$ npx expo install expo-media-library']} />

## Importando a nova API \{#importing-the-new-api}

Importe de `expo-media-library`:

```ts
import { Asset, Album, Query } from 'expo-media-library';
```

## Assets \{#assets}

### Crie um asset a partir de um arquivo \{#create-an-asset-from-a-file}

```ts
// Before
await MediaLibrary.saveToLibraryAsync(localUri);
// or, to get a reference back:
const asset = await MediaLibrary.createAssetAsync(localUri);

// After
const asset = await Asset.create(localUri);
```

`saveToLibraryAsync` não está disponível na nova API. Use `Asset.create`, que salva o arquivo na biblioteca e retorna uma instância de `Asset`.

### Consulte assets \{#query-assets}

```ts
// Before
const { assets } = await MediaLibrary.getAssetsAsync({
  mediaType: MediaLibrary.MediaType.photo,
  first: 20,
  sortBy: [['creationTime', false]],
});

// After
const assets = await new Query()
  .eq(AssetField.MEDIA_TYPE, MediaType.IMAGE)
  .limit(20)
  .orderBy({ key: AssetField.CREATION_TIME, ascending: false })
  .exe();
```

`Query` retorna diretamente um array de instâncias de `Asset`. Não há o wrapper `assets` nem `endCursor`. A paginação é feita encadeando `.limit()` e `.offset()`.

### Leia as propriedades do asset \{#read-asset-properties}

```ts
// Before
const info = await MediaLibrary.getAssetInfoAsync(asset);
console.log(info.filename, info.width, info.height);

// After, individual getters
const filename = await asset.getFilename();
const width = await asset.getWidth();
const height = await asset.getHeight();
const mediaType = await asset.getMediaType();

// After, all properties at once
const info = await asset.getInfo();
```

As propriedades são acessadas por getters assíncronos, em vez de campos pré-carregados. Use `getInfo()` para obter todas as propriedades de uma vez, como um objeto `AssetInfo`.

### Leia os dados EXIF \{#read-exif-data}

```ts
// Before
const info = await MediaLibrary.getAssetInfoAsync(asset);
const exif = info.exif;

// After
const exif = await asset.getExif();
```

### Exclua assets \{#delete-assets}

```ts
// Before
await MediaLibrary.deleteAssetsAsync([asset]);

// After, single asset
await asset.delete();

// After, multiple assets
await Asset.delete([asset1, asset2]);
```

### Use assets legados junto com a nova API \{#use-legacy-assets-alongside-the-new-api}

> Se possível, migre seu app para usar a nova API do início ao fim. As funções auxiliares abaixo são destinadas a migrações graduais, em que as duas APIs são usadas ao mesmo tempo.

Se você tem um objeto `Asset` legado na memória e precisa de uma nova instância de `Asset`, use `asset.uri` no iOS (que já é uma URI `ph://` aceita pela nova API) e `getAssetContentUriAsync` no Android, para converter o ID numérico do MediaStore em uma URI `content://`.

```ts
import { Asset } from 'expo-media-library';
import * as LegacyMediaLibrary from 'expo-media-library/legacy';
import { Platform } from 'react-native';

async function toNewAsset(legacyAsset: LegacyMediaLibrary.Asset): Promise<Asset> {
  switch (Platform.OS) {
    case 'ios':
      return new Asset(legacyAsset.uri);
    case 'android': {
      const contentUri = await LegacyMediaLibrary.getAssetContentUriAsync(legacyAsset);
      return new Asset(contentUri);
    }
    default:
      throw new Error(`Unsupported platform: ${Platform.OS}`);
  }
}
```

Se seu app armazena IDs de assets retornados pela API legada (por exemplo, em um banco de dados), converta-os antes de criar instâncias de `Asset`. No iOS, adicione o prefixo `ph://` ao ID legado. No Android, use `getAssetContentUriAsync` para resolver o ID numérico do MediaStore em uma URI `content://`.

```ts
async function convertStoredId(legacyId: string): Promise<Asset> {
  switch (Platform.OS) {
    case 'ios':
      return new Asset(`ph://${legacyId}`);
    case 'android': {
      const contentUri = await LegacyMediaLibrary.getAssetContentUriAsync(legacyId);
      return new Asset(contentUri);
    }
    default:
      throw new Error(`Unsupported platform: ${Platform.OS}`);
  }
}
```

## Álbuns \{#albums}

### Obtenha um álbum pelo nome \{#get-an-album-by-name}

```ts
// Before
const album = await MediaLibrary.getAlbumAsync('MyAlbum');

// After
const album = await Album.get('MyAlbum');
if (album) {
  // album found
}
```

### Obtenha todos os álbuns \{#get-all-albums}

```ts
// Before
const albums = await MediaLibrary.getAlbumsAsync();

// After
const albums = await Album.getAll();
```

### Crie um álbum \{#create-an-album}

```ts
// Before
const album = await MediaLibrary.createAlbumAsync('MyNewAlbum', asset, false);

// After
const album = await Album.create('MyNewAlbum', [asset]);
```

### Obtenha todos os assets de um álbum \{#get-all-assets-in-an-album}

```ts
// Before
const { assets } = await MediaLibrary.getAssetsAsync({ album: album.id });

// After
const assets = await album.getAssets();
```

### Obtenha o título do álbum \{#get-album-title}

```ts
// Before, title was a synchronous property but required fetching the full album object first
const album = await MediaLibrary.getAlbumAsync('MyAlbum');
console.log(album.title);

// After
const title = await album.getTitle();
```

### Adicione assets a um álbum \{#add-assets-to-an-album}

```ts
// Before
await MediaLibrary.addAssetsToAlbumAsync([asset], album, false);

// After
await album.add([asset]);
```

### Remova assets de um álbum (somente iOS) \{#remove-assets-from-an-album-ios-only}

```ts
// Before
await MediaLibrary.removeAssetsFromAlbumAsync(assets, album);

// After
await album.removeAssets(assets);
```

### Exclua um álbum \{#delete-an-album}

```ts
// Before
await MediaLibrary.deleteAlbumsAsync([album], false);

// After, single album
await album.delete();

// After, multiple albums
await Album.delete([album1, album2]);
```

## Permissões \{#permissions}

Os hooks e funções de permissão continuam disponíveis com os mesmos nomes. A única mudança é que `presentPermissionsPickerAsync` foi renomeada para `presentPermissionsPicker`.

```ts
// Before
await MediaLibrary.presentPermissionsPickerAsync(mediaTypes);

// After
await presentPermissionsPicker(mediaTypes);
```

`requestPermissionsAsync`, `getPermissionsAsync` e `usePermissions` não mudaram.

## Escutando alterações \{#listening-for-changes}

```ts
// Before
const subscription = MediaLibrary.addListener(event => { ... });
subscription.remove();

// After
const subscription = addListener(event => { ... });
subscription.remove();

// Remove all listeners at once
removeAllListeners();
```

O formato do evento do listener não mudou.

## Mudanças incompatíveis de comportamento \{#breaking-semantic-changes}

- As propriedades do asset agora são getters assíncronos (`getFilename()`, `getWidth()`, ...), em vez de campos síncronos em um objeto de resultado. Use `asset.getInfo()` para obter todas as propriedades de uma vez.
- O sufixo `Async` foi removido. A biblioteca inteira é assíncrona.
- `Query` substitui o objeto de opções de `getAssetsAsync`. Não existem mais `endCursor` nem `hasNextPage`. Use `.limit()` e `.offset()` para paginação.
- As operações em álbuns e assets agora são métodos das instâncias de `Album` e `Asset`, em vez de funções avulsas que recebem um ID ou uma referência.
- `saveToLibraryAsync` foi substituída por `Asset.create`, que retorna uma instância de `Asset`.
- `getMomentsAsync`, `albumNeedsMigrationAsync` e `migrateAlbumIfNeededAsync` foram removidas, sem substituto. Você pode apagar com segurança as chamadas a essas funções.

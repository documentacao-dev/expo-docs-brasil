Todo campo tem um valor atual, como o texto em um campo de texto, a posição de um switch ou a opção selecionada em um picker. Um **componente controlado** mantém esse valor em um state que você gerencia. O campo exibe o que o state contém, e cada alteração feita pelo usuário atualiza esse state. Esse state é a única fonte da verdade.

Componentes controlados combinam uma prop que define o valor com um callback que informa as alterações. Esta página foca no [`TextInput`](https://reactnative.dev/docs/textinput), o componente do React Native para digitar texto, porque é em um campo de texto que controlar o valor é mais útil e mais difícil de acertar. Para `Switch`, `Checkbox` e `Picker`, veja [Controlar outros componentes](#control-other-components).

## Controlar um campo de texto \{#control-a-text-input}

O componente `TextInput` do React Native é não controlado por padrão. Ele mantém o texto internamente e funciona sem a prop [`value`](https://reactnative.dev/docs/textinput#value). Ao passar `value`, ele passa a ser controlado. A partir daí, o React força o campo nativo a seguir essa prop.

O exemplo a seguir mantém um nome no state. `value` exibe o state, e [`onChangeText`](https://reactnative.dev/docs/textinput#onchangetext) o atualiza a cada tecla digitada:

```tsx
import { useState } from 'react';
import { TextInput } from 'react-native';

export default function NameInput() {
  const [name, setName] = useState('');

  return <TextInput value={name} onChangeText={setName} placeholder="Name" />;
}
```

No React Native, esse ciclo de atualização é assíncrono: cada atualização faz uma ida e volta pela thread JavaScript. Uma tecla digitada atualiza primeiro o campo nativo e só depois dispara `onChangeText`. A atualização do state provoca um novo render, e o novo valor volta para o campo nativo. Na web, o React reconcilia os inputs de forma síncrona com o DOM. A maioria dos problemas com campos controlados vem dessa ida e volta.

Se você já escreveu [campos controlados para a web](https://react.dev/reference/react-dom/components/input#controlling-an-input-with-a-state-variable), três coisas mudam no React Native:

- O handler de alteração usual é `onChangeText`, que recebe o novo texto diretamente em vez de um objeto de evento.
- O React Native não tem o [`preventDefault`](https://developer.mozilla.org/en-US/docs/Web/API/Event/preventDefault), então você não consegue bloquear uma tecla antes de ela aparecer. Em vez disso, trate o texto em `onChangeText` e passe o resultado de volta por `value`.
- A atualização é assíncrona, então o campo reflete o state com um ciclo de atraso.

O exemplo a seguir mostra o mesmo campo nas duas plataformas:

```tsx
// Web (react-dom)
<input value={text} onChange={event => setText(event.target.value)} />

// React Native
<TextInput value={text} onChangeText={setText} />
```

## Escolher entre campos controlados e não controlados \{#choose-between-controlled-and-uncontrolled-inputs}

Um campo controlado é útil quando algo precisa reagir a cada tecla: validar em tempo real, contar caracteres, habilitar o botão de envio só depois que o campo estiver válido ou formatar o texto enquanto o usuário digita.

Um campo não controlado é útil quando você só precisa do valor no fim da interação, como quando o usuário envia uma busca. Ele também evita um re-render a cada tecla. Para montar um, defina o texto inicial com a prop [`defaultValue`](https://reactnative.dev/docs/textinput#defaultvalue) e leia o valor final com a prop [`onSubmitEditing`](https://reactnative.dev/docs/textinput#onsubmitediting):

```tsx
import { TextInput } from 'react-native';

export default function SearchInput({ onSearch }: { onSearch: (query: string) => void }) {
  return (
    <TextInput
      defaultValue=""
      onSubmitEditing={event => onSearch(event.nativeEvent.text)}
      placeholder="Search"
      returnKeyType="search"
    />
  );
}
```

A tabela a seguir compara campos controlados e não controlados:

|                          | Controlado                                | Não controlado                                                                                           |
| ------------------------ | ----------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| O valor fica em          | state do React                            | O campo nativo                                                                                           |
| Definido com             | `value` e `onChangeText`                  | `defaultValue`                                                                                           |
| Lido com                 | state do React                            | `onChangeText`, `onSubmitEditing`, [`onEndEditing`](https://reactnative.dev/docs/textinput#onendediting) |
| Re-renders por tecla     | Sim                                       | Não                                                                                                      |
| Use quando               | Validação em tempo real, formatação, UI dependente | Caixas de busca, formulários lidos no envio                                                     |

### Formatar o campo enquanto o usuário digita \{#format-input-as-users-type}

Para formatar um texto como número de telefone, valor monetário ou data enquanto o usuário digita, transforme a string dentro de `onChangeText` e guarde o resultado formatado de volta no state.

O exemplo a seguir formata um número de telefone enquanto o usuário digita:

```tsx
import { useState } from 'react';
import { TextInput } from 'react-native';

function formatPhone(input: string) {
  const digits = input.replace(/\D/g, '').slice(0, 10);
  if (digits.length <= 3) return digits;
  if (digits.length <= 6) return `(${digits.slice(0, 3)}) ${digits.slice(3)}`;
  return `(${digits.slice(0, 3)}) ${digits.slice(3, 6)}-${digits.slice(6)}`;
}

export default function PhoneInput() {
  const [phone, setPhone] = useState('');

  return (
    <TextInput
      value={phone}
      onChangeText={text => setPhone(formatPhone(text))}
      keyboardType="phone-pad"
      placeholder="(555) 123-4567"
    />
  );
}
```

Como a string formatada é diferente do que o usuário digitou, o campo mostra brevemente o texto original entre os passos 2 e 5 do diagrama acima.

### Restringir o que o usuário pode digitar \{#restrict-what-users-can-type}

A formatação reescreve a string inteira. Restringir a entrada remove caracteres, com a mesma lógica. Deixe `onChangeText` disparar, remova os caracteres indesejados e envie o valor limpo de volta por `value`.

O exemplo a seguir mantém apenas dígitos no campo:

```tsx
<TextInput
  value={amount}
  onChangeText={text => setAmount(text.replace(/[^0-9]/g, ''))}
  keyboardType="number-pad"
/>
```

Para limites de tamanho e campos somente leitura, prefira as props [`maxLength`](https://reactnative.dev/docs/textinput#maxlength) e [`editable`](https://reactnative.dev/docs/textinput#editable). Elas são aplicadas no lado nativo e não causam piscadas:

```tsx
// Cap the length
<TextInput value={code} onChangeText={setCode} maxLength={6} />

// Prevent all edits
<TextInput value={value} editable={false} />
```

Definir [`keyboardType`](https://reactnative.dev/docs/textinput#keyboardtype) (por exemplo, `number-pad`, `decimal-pad` ou `phone-pad`) mostra um teclado correspondente, mas não impõe nada: teclados físicos e textos colados ainda podem inserir outros caracteres, então mantenha o filtro em `onChangeText`.

### Forçar letras maiúsculas \{#force-uppercase-input}

Forçar maiúsculas segue o mesmo padrão da formatação. Combine a transformação com [`autoCapitalize`](https://reactnative.dev/docs/textinput#autocapitalize) para que o teclado da tela já gere letras maiúsculas desde o início.

O exemplo a seguir guarda um código de cupom em maiúsculas:

```tsx
<TextInput
  value={code}
  onChangeText={text => setCode(text.toUpperCase())}
  autoCapitalize="characters"
  placeholder="COUPON"
/>
```

### Manter o cursor no lugar durante a formatação \{#keep-the-cursor-in-place-while-formatting}

Antes da [New Architecture](/guides/new-architecture/) do React Native, reformatar o valor dentro de `onChangeText` levava o cursor para o fim do campo, o que dificultava edições no meio do texto.

Em apps React Native e Expo que usam a New Architecture, digitar no meio do campo mantém o cursor no lugar desde que `onChangeText` repasse o texto sem alterações. Quando ele repassa um texto transformado, o campo nativo precisa mapear a posição antiga do cursor na nova string, e esse mapeamento pode falhar quando a transformação insere ou remove caracteres.

Para manter o cursor estável durante a formatação:

- Prefira props nativas, como `maxLength` e `editable`, em vez de reimplementá-las em JavaScript. Veja [Restringir o que o usuário pode digitar](#restrict-what-users-can-type).
- Use uma biblioteca de máscara que faça os cálculos do cursor por você. Veja [Quando usar uma biblioteca](#when-to-use-a-library).
- Leve a formatação para a thread de UI. Veja [Remover a piscada da formatação com worklets](#remove-formatting-flicker-with-worklets).

### Remover a piscada da formatação com worklets \{#remove-formatting-flicker-with-worklets}

A formatação em JavaScript passa pelo state e por um re-render antes de o campo nativo ser atualizado, então o campo pode mostrar brevemente o texto original antes de o valor formatado substituí-lo. O [`TextInput`](/versions/latest/sdk/ui/universal/textinput/) universal, de [`@expo/ui`](/versions/latest/sdk/ui/), elimina esse caminho de ida e volta. Seu `value` é um objeto de state observável criado com `useNativeState`, e `onChangeText` pode ser um worklet que roda de forma síncrona na thread de UI. O valor formatado aparece no mesmo frame da tecla digitada.

O diagrama a seguir mostra a mesma tecla digitada no caminho dos worklets:

O exemplo a seguir formata um número de telefone na thread de UI enquanto o usuário digita. Ele requer:

- `@expo/ui`: o `TextInput` universal está disponível a partir da SDK 56. Veja as [instruções de instalação](/versions/latest/sdk/ui/universal/textinput/#installation).
- [`react-native-worklets`](https://docs.swmansion.com/react-native-worklets/): as funções worklet precisam do seu runtime.

```tsx
import { Host, TextInput, useNativeState } from '@expo/ui';
import { useCallback } from 'react';

function formatPhone(input: string) {
  'worklet';
  const digits = input.replace(/\D/g, '').slice(0, 10);
  if (digits.length <= 3) return digits;
  if (digits.length <= 6) return `(${digits.slice(0, 3)}) ${digits.slice(3)}`;
  return `(${digits.slice(0, 3)}) ${digits.slice(3, 6)}-${digits.slice(6)}`;
}

export default function PhoneMaskExample() {
  const phone = useNativeState('');
  const selection = useNativeState({ start: 0, end: 0 });

  const handleChangeText = useCallback(
    (value: string) => {
      'worklet';
      const formatted = formatPhone(value);
      if (formatted !== value) {
        phone.value = formatted;
        // Snaps to end for demo. Real masks need smarter cursor handling.
        selection.value = { start: formatted.length, end: formatted.length };
      }
    },
    [phone, selection]
  );

  return (
    <Host matchContents={{ vertical: true }}>
      <TextInput
        value={phone}
        selection={selection}
        keyboardType="phone-pad"
        placeholder="(555) 123-4567"
        onChangeText={handleChangeText}
      />
    </Host>
  );
}
```

A verificação `formatted !== value` pula a reescrita quando a formatação não altera o texto. Quando a máscara reescreve a string, atualize `selection.value` junto com `phone.value`. Caso contrário, o cursor deixa de acompanhar o texto reescrito, e a digitação rápida coloca os caracteres na posição errada. Levar o cursor para o fim é o comportamento correto mais simples quando o usuário digita no final do campo. Uma máscara de produção que aceite edições no meio do texto precisa de um tratamento de cursor mais elaborado.

Os campos de texto específicos de cada plataforma do `@expo/ui` oferecem os mesmos padrões de componente controlado e de worklet. Veja os exemplos de campo de texto controlado para [Jetpack Compose](/versions/latest/sdk/ui/jetpack-compose/textfield/#controlled-text-field) e [SwiftUI](/versions/latest/sdk/ui/swift-ui/textfield/#controlled-text-field), e o [exemplo de máscara com worklet](/versions/latest/sdk/ui/universal/textinput/#worklet-masking) para o `TextInput` universal.

## Quando usar uma biblioteca \{#when-to-use-a-library}

Uma formatação feita à mão funciona para um ou dois campos. Uma biblioteca cuida dos cálculos do cursor e das regras de localização em casos especiais, como números de telefone internacionais, separadores de moeda, números de cartão de crédito e datas:

- Para máscaras: [`react-native-mask-input`](https://github.com/CaioQuirinoMedeiros/react-native-mask-input) ou [`react-native-mask-text`](https://github.com/akinncar/react-native-mask-text).
- Para state e validação de formulários com muitos campos: [React Hook Form](https://react-hook-form.com/) ou [Formik](https://formik.org/docs/guides/react-native). Com o React Hook Form, envolva o `TextInput` no componente `Controller`, porque `register` não se vincula a campos nativos.

## Controlar outros componentes \{#control-other-components}

O padrão de componente controlado vai além dos campos de texto. Qualquer componente que combine uma prop de valor com um callback de alteração segue o mesmo padrão do `TextInput`.

O [`Switch`](https://reactnative.dev/docs/switch) é o exemplo mais rigoroso. O `TextInput` entra no modo controlado quando você passa `value`, mas o `Switch` é sempre controlado. A menos que `onValueChange` atualize a prop `value`, o switch volta ao valor que você passou. Você pode passar o state para `value` e atualizá-lo em `onValueChange`, que informa um booleano em vez de uma string:

```tsx
import { useState } from 'react';
import { Switch } from 'react-native';

export default function NotificationsToggle() {
  const [enabled, setEnabled] = useState(false);

  return <Switch value={enabled} onValueChange={setEnabled} />;
}
```

O mesmo padrão aparece em outros componentes:

- [`RefreshControl`](https://reactnative.dev/docs/refreshcontrol) trata `refreshing` como uma prop controlada. Defina como `true` dentro de `onRefresh` e volte para `false` quando a atualização terminar. Se ela nunca mudar, o indicador para imediatamente.
- O [`Checkbox`](/versions/latest/sdk/checkbox/) do `expo-checkbox` combina `value` com `onValueChange`.
- O [`Picker`](/versions/latest/sdk/picker/) do `@react-native-picker/picker` combina `selectedValue` com `onValueChange`.

Esses componentes emitem um único valor discreto por interação, então os problemas de cursor e de piscada que vêm com a formatação de texto não se aplicam.

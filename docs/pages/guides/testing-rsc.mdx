> **important** Este guia se refere ao recurso [experimental](/more/release-statuses/#experimental) React Server Components, que ainda está em desenvolvimento.

React Server Components (RSC) é um novo recurso do React que permite criar componentes que são renderizados no servidor e podem ser hidratados no cliente. Este guia traz detalhes sobre como escrever testes unitários para RSC no seu projeto.

## Testes com Jest \{#jest-testing}

React Server Components rodam no Node.js. Isso significa que o Jest, sozinho, consegue emular de perto o ambiente de renderização no servidor. Já os testes baseados em cliente exigem um preset do Jest para se comunicar entre o Node.js e um navegador web.

### Configuração \{#setup}

Enquanto a renderização de servidor padrão é exclusiva da web, o RSC universal do Expo inclui renderizadores de servidor personalizados para cada plataforma. Isso significa que extensões de arquivo específicas de plataforma são compatíveis. Por exemplo, ao escrever Server Components para um app iOS, extensões específicas de plataforma, como **\*.ios.js** e **\*.native.ts**, serão resolvidas.

O `jest-expo` oferece alguns presets diferentes para testar Server Components:

| Executor                | Descrição                                                                                      |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `jest-expo/rsc/android` | Um executor exclusivo do Android para RSC. Usa arquivos **\*.android.js**, **\*.native.js** e **\*.js**. |
| `jest-expo/rsc/ios`     | Um executor exclusivo do iOS para RSC. Usa arquivos **\*.ios.js**, **\*.native.js** e **\*.js**.         |
| `jest-expo/rsc/web`     | Um executor exclusivo da web para RSC. Usa arquivos **\*.web.js** e **\*.js**.                             |
| `jest-expo/rsc`         | Um executor combinado que reúne os executores acima.                                                |

Para configurar o Jest para RSC, crie um arquivo **jest-rsc.config.js** na raiz do projeto:

```js jest-rsc.config.js
module.exports = require('jest-expo/rsc/jest-preset');
```

Depois, você pode adicionar um script como `test:rsc` ao seu **package.json**:

```json package.json
{
  "scripts": {
    "test:rsc": "jest --config jest-rsc.config.js"
  }
}
```

### Escrevendo testes \{#writing-tests}

Os testes devem ser escritos em um diretório **\_\_rsc_tests\_\_** para impedir que o Jest execute os seus testes de cliente no servidor.

```tsx __rsc_tests__/my-component.test.ts
/// <reference types="jest-expo/rsc/expect" />

import { LinearGradient } from 'expo-linear-gradient';

it(`renders to RSC`, async () => {
  const jsx = (
    <LinearGradient
      colors={['cyan', '#ff00ff', 'rgba(0,0,0,0)', 'rgba(0,255,255,0.5)']}
      testID="gradient"
    />
  );

  await expect(jsx).toMatchFlight(`1:I["src/LinearGradient.tsx",[],"LinearGradient"]
0:["$","$L1",null,{"colors":["cyan","#ff00ff","rgba(0,0,0,0)","rgba(0,255,255,0.5)"],"testID":"gradient"},null]`);
});
```

Qualquer código que você importar nos seus arquivos de teste será executado no ambiente do servidor. Você pode importar módulos exclusivos de servidor, como `react-server` e `server-only`. Isso é útil para descobrir se uma biblioteca é compatível com RSC.

### Matchers personalizados do expect \{#custom-expect-matchers}

O `jest-expo` para RSC adiciona alguns matchers personalizados ao `expect` do Jest:

- `toMatchFlight`: renderiza um elemento JSX usando uma pseudoimplementação da renderização do Expo CLI e compara o resultado com uma string flight.
- `toMatchFlightSnapshot`: igual ao `toMatchFlight`, mas salva a string flight em um arquivo de snapshot.

Nos bastidores, esses métodos cuidam de parte da operação do framework necessária para renderizar RSC. O stream de renderização do componente é armazenado em buffer como uma string e comparado de uma só vez. Como alternativa, você pode consumir o stream manualmente para acompanhar o progresso da renderização.

Se um componente falhar ao renderizar, o matcher vai lançar um erro para fazer o teste falhar. Na prática, o renderizador de servidor gera uma linha `E:`, que é enviada ao cliente para ser lançada localmente para o usuário.

### Executando testes \{#running-tests}

Você pode executar os seus testes com o script `test:rsc`:

<Terminal cmd={['$ yarn test:rsc --watch']} />

Se você estiver usando o executor combinado, pode selecionar um projeto específico com a flag `--selectProjects`. O exemplo a seguir executa somente a plataforma web:

<Terminal cmd={['$ yarn test:rsc --watch --selectProjects rsc/web']} />

## Dicas \{#tips}

Use os módulos `server-only` e `client-only` para garantir que um módulo não seja importado no cliente ou no servidor:

```js my-module.js
import 'server-only';
```

O RSC oferece suporte a exports de pacotes por padrão. Você pode usar a condição `react-server` para alterar qual arquivo é importado de um módulo:

```json package.json
{
  "exports": {
    ".": {
      "react-server": "./index.react-server.js",
      "default": "./index.js"
    }
  }
}
```

Ao gerar o bundle para RSC, todos os módulos entram no bundle no modo React Server, e você pode optar por não fazer isso com a diretiva `"use client"`. Quando `"use client"` é encontrado, o módulo se torna uma referência assíncrona ao módulo do cliente.

`"use server"` não é o oposto de `"use client"`. Em vez disso, ela é usada para definir um arquivo de React Server Functions.

Você pode integrar a autenticação com Google ao app Expo usando qualquer uma das bibliotecas a seguir:

- [`react-native-nitro-google-signin`](https://react-native-nitro-google-sign-in.github.io): uma biblioteca que usa APIs nativas modernas.
- [`@react-native-google-signin/google-signin`](https://github.com/react-native-google-signin/google-signin): uma biblioteca amplamente usada.

As duas bibliotecas oferecem botões de login nativos e permitem autenticar o usuário (e obter autorização para usar as APIs do Google). Como elas exigem código nativo personalizado, você vai precisar usar um [config plugin](/config-plugins/introduction/) no [app config](/versions/latest/config/app/) e criar um development build.

## Escolhendo uma biblioteca \{#choosing-a-library}

Ao escolher entre as duas bibliotecas, considere as diferenças a seguir:

- `react-native-nitro-google-signin` inclui suporte ao **Android Credential Manager**.
- `@react-native-google-signin/google-signin` oferece as **APIs do Android Credential Manager como parte do plano pago**.

> **warning** O SDK legado do Google Sign-In para Android (parte de `com.google.android.gms:play-services-auth`) está descontinuado, e o Google recomenda migrar para o **Android Credential Manager**. Veja [Sobre a migração do Google Sign-In legado](https://developer.android.com/identity/sign-in/legacy-gsi-migration).

Este guia explica como configurar a biblioteca no projeto.

### Envie o app para a Google Play Store \{#upload-app-to-google-play-store}

Recomendamos enviar o app à Google Play Store se ele for rodar em produção. Você pode enviar o app às lojas para testes mesmo com o projeto ainda em desenvolvimento. Assim, você consegue testar o Google Sign In tanto quando o app é assinado pelo Expo Build para testes quanto quando é assinado pelo [Google Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756?hl=en) para o deploy na loja. ### Configure seu projeto no Firebase ou no Google Cloud Console \{#configure-your-firebase-or-google-cloud-console-project}

Consulte a documentação da biblioteca para um guia de configuração mais detalhado:

- [`react-native-nitro-google-signin`](https://react-native-nitro-google-sign-in.github.io/docs/setup/google-cloud)
- [`@react-native-google-signin/google-signin`](https://react-native-google-signin.github.io/docs/setting-up/get-config-file)

No Android, depois de enviar o app, você precisa informar os valores de fingerprint do certificado SHA-1 quando solicitado durante a configuração do projeto no Firebase ou no Google Cloud Console. Há dois tipos de valores que você pode informar:

- Fingerprint do **.apk** que você gerou (na máquina local ou usando o Expo Build). Você encontra o fingerprint do certificado SHA-1 no Google Play Console, em **Release** > **Setup** > **App Integrity** > **Upload key certificate**.
- Fingerprint(s) de um **app de produção** baixado da Play Store. Você encontra o(s) fingerprint(s) do certificado SHA-1 no Google Play Console, em **Release** > **Setup** > **App Integrity** > **App signing key certificate**.

#### Envie o google-services.json e o GoogleService-Info.plist para o Expo Services \{#upload-google-servicesjson-and-googleservice-infoplist-to-expo-services}

Se você usar o método do Firebase para Android e iOS (como visto nas seções acima), precisa garantir que o **google-services.json** e o **GoogleService-Info.plist** estejam disponíveis para o Expo Build na hora de gerar o app. Você pode versioná-los no repositório, porque os arquivos não devem conter valores sensíveis, ou pode tratá-los como segredos, adicioná-los ao **.gitignore** e usar o guia abaixo para disponibilizá-los ao Expo Build.

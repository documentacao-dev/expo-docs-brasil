Se você usa uma biblioteca nativa do iOS que utiliza APIs de "restricted reason", vai precisar configurar um manifesto de privacidade do iOS para declarar por que está incluindo código nativo que chama essas APIs.

Você encontra mais detalhes e uma lista das APIs de "required reason" na [documentação para desenvolvedores da Apple](https://developer.apple.com/documentation/bundleresources/privacy_manifest_files).

> **info** As informações e os passos deste guia ainda estão em desenvolvimento e podem mudar, por causa de novas ferramentas criadas para esse fim ou de novos requisitos da Apple.

## O que é um manifesto de privacidade? \{#what-is-a-privacy-manifest}

Um manifesto de privacidade é um arquivo chamado **PrivacyInfo.xcprivacy** incluído no seu projeto nativo do iOS. Esse arquivo serve para declarar por que o app inclui código nativo que chama certas APIs que a Apple considera sensíveis.

Atualmente, essas APIs incluem o acesso ao UserDefaults, ao timestamp de arquivos, ao horário de inicialização do sistema, ao espaço em disco e ao teclado ativo. A Apple considera essa uma lista aberta, que pode ser expandida no futuro.

## Configuração no app config \{#configuration-in-app-config}

Você pode incluir um manifesto de privacidade do iOS usando o campo `privacyManifests` em `expo.ios` no seu app config.

```json app.json
{
  "expo": {
    "name": "My App",
    "slug": "my-app",
    /* @hide ... */ /* @end */
    "ios": {
      "privacyManifests": {
        "NSPrivacyAccessedAPITypes": [
          {
            "NSPrivacyAccessedAPIType": "NSPrivacyAccessedAPICategoryUserDefaults",
            "NSPrivacyAccessedAPITypeReasons": ["CA92.1"]
          }
        ]
      }
    }
  }
}
```

Confirme que você atualizou as bibliotecas da Expo SDK para as versões mais recentes da sua SDK, usando `npx expo install --fix`.

### Incluir os motivos exigidos para pacotes da Expo SDK e outras bibliotecas de terceiros \{#including-required-reasons-for-expo-sdk-packages-and-other-third-party-libraries}

Até o momento, a Apple não interpreta corretamente todos os arquivos **PrivacyInfo** incluídos por dependências estáticas do CocoaPods (como os pacotes da Expo SDK e outras bibliotecas do ecossistema). Talvez você precise incluir os motivos exigidos para as APIs usadas por essas dependências no arquivo **PrivacyInfo.xcprivacy** do seu app ou na configuração do **app.json**.

Todos os pacotes da Expo SDK que usam APIs de "required reason" têm um arquivo **PrivacyInfo** incluído no diretório do pacote. Aqui está [um arquivo de exemplo](https://github.com/expo/expo/blob/main/packages/expo-application/ios/PrivacyInfo.xcprivacy) incluído na biblioteca `expo-application`.

Normalmente, você consegue identificar os motivos exigidos para as APIs usadas por outras bibliotecas de terceiros verificando se a biblioteca que você pretende usar tem um arquivo **PrivacyInfo.xcprivacy** no diretório **node_modules/nome_do_pacote/ios**. Se tiver, confira os valores de `NSPrivacyAccessedAPITypes` e `NSPrivacyAccessedAPITypeReasons` nesse arquivo e copie esses valores para a sua configuração.

Como alternativa, a Apple avisa os desenvolvedores depois que eles enviam um build sem os arquivos de manifesto de privacidade ou sem motivos específicos. Você pode esperar o e-mail de notificação da Apple e, então, incluir os motivos exigidos listados no e-mail no arquivo **PrivacyInfo.xcprivacy** do seu app (se você não usa o [CNG](/workflow/continuous-native-generation/)) ou na configuração do arquivo **app.json**.

## Testar o manifesto de privacidade \{#testing-the-privacy-manifest}

Você pode testar o manifesto de privacidade gerando o build do seu app e enviando-o, seja pelo processo de revisão da App Store, seja para a revisão externa do TestFlight. A Apple envia um e-mail em poucos minutos após o envio se o seu app estiver sem algum dos motivos exigidos para as APIs usadas.

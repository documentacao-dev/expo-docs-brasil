Apps Expo podem funcionar com qualquer serviço de notificações ou com qualquer um dos recursos de notificação oferecidos pelos sistemas operacionais Android e iOS. Mesmo que ainda não exista um pacote para determinado recurso, é possível escrever código nativo para acessá-lo pela [Expo Modules API](/modules/overview/), e as configurações nativas do projeto podem ser automatizadas com [config plugins](/config-plugins/introduction/). As opções a seguir oferecem integrações específicas para o Expo, incluindo config plugins quando necessário, para implementar notificações push no seu app:

> A biblioteca [`expo-notifications`](/versions/latest/sdk/notifications/) foi projetada e testada para funcionar com o serviço de notificações push do Expo e com notificações enviadas diretamente pelo FCM e pelo APNs. Alguns recursos avançados podem não ser compatíveis com provedores terceiros, pois eles geralmente têm seus próprios SDKs nativos e para React Native, otimizados para os seus serviços.

## Notificações push do Expo \{#expo-push-notifications}

O [Expo Notifications](/versions/latest/sdk/notifications/) oferece uma API unificada para lidar com notificações push no Android e no iOS. Ele se integra facilmente à sua conta Expo e é gratuito.

### Principais recursos \{#key-capabilities}

- Totalmente compatível com a biblioteca [`expo-notifications`](/versions/latest/sdk/notifications/)
- Inclui um painel do Expo para acompanhar a entrega de notificações ao FCM e ao APNs
- Permite testar notificações com a [Expo Notifications Tool](https://expo.dev/notifications)

### Considerações e limitações \{#considerations-and-limitations}

- A iOS Notification Service Extension, usada para adicionar conteúdo extra às notificações, como imagens, não está incluída formalmente. Mesmo assim, você pode adicioná-la usando um config plugin com código nativo e configuração personalizados ([exemplo](https://github.com/expo/expo/pull/36202)).
- Os volumes são limitados a 600 notificações por segundo por projeto.

[OneSignal](https://onesignal.com/) é uma plataforma de engajamento de clientes que oferece notificações push, mensagens dentro do app, SMS e serviços de e-mail para apps web e mobile. O OneSignal oferece suporte a mídia rica nas notificações e análise de engajamento. Ele inclui um [config plugin para Expo](https://github.com/OneSignal/onesignal-expo-plugin) para integração direta ao seu projeto Expo.

## Braze \{#braze}

O Braze oferece suporte a conteúdo rico em notificações, campanhas de notificações push e reenvio de notificações após falhas de entrega no Android. Ele fornece um [SDK para React Native](https://github.com/braze-inc/braze-react-native-sdk) e um [config plugin](https://github.com/braze-inc/braze-expo-plugin/tree/main). ## Customer.io \{#customerio}

[Customer.io](https://customer.io/) é uma plataforma de engajamento de clientes que permite criar workflows automatizados poderosos com notificações push, mensagens dentro do app, e-mail, SMS e outros canais. Seu construtor visual de workflows permite automatizar campanhas complexas e orientadas por dados em vários canais. O Customer.io oferece coleta de métricas no dispositivo, que pode ser usada para personalizar notificações push de acordo com o comportamento e as preferências dos usuários. Ele fornece um [plugin para Expo](https://github.com/customerio/customerio-expo-plugin) para integração direta com o seu projeto Expo, além de documentação para usar as notificações push do Customer.io junto com outros provedores.

## Envie notificações diretamente pelo FCM e pelo APNs \{#send-notifications-directly-via-fcm-and-apns}

Você pode optar por enviar notificações diretamente para as APIs de push das plataformas a partir do seu backend. Nesse caso, ainda é possível usar o [`expo-notifications`](/versions/latest/sdk/notifications/) para obter o token de push nativo e configurar as notificações separadamente para cada plataforma.

Embora o código do lado do cliente continue multiplataforma com o [`expo-notifications`](/versions/latest/sdk/notifications/), você precisará implementar a lógica do lado do servidor para interagir individualmente com as APIs do [FCM](https://firebase.google.com/docs/cloud-messaging) e do [APNs](https://developer.apple.com/documentation/usernotifications).

## Mensageria com React Native Firebase \{#react-native-firebase-messaging}

O [React Native Firebase](https://rnfirebase.io/) oferece um módulo de mensageria que permite usar o [Firebase Cloud Messaging (FCM)](https://firebase.google.com/docs/cloud-messaging) como um serviço unificado de notificações push para Android e iOS. Embora o FCM seja frequentemente associado a notificações Android, ele também oferece suporte ao iOS, roteando as mensagens pelo Apple Push Notification service (APNs) nos bastidores.

Essa abordagem é diferente de usar o FCM somente para notificações Android. Em vez disso, o SDK multiplataforma do Firebase cuida das notificações das duas plataformas por meio de um único serviço.

> Mesmo que o FCM trate as notificações das duas plataformas, as notificações do iOS ainda passam pelo APNs. O Firebase gerencia esse roteamento automaticamente. Saiba mais na [documentação de mensageria do React Native Firebase](https://rnfirebase.io/messaging/usage).

## Dicas e considerações importantes \{#tips-and-important-considerations}

- **Evite misturar implementações do lado do cliente**: serviços de notificação diferentes podem ter implementações conflitantes do lado do cliente. Use uma abordagem consistente para evitar possíveis problemas.
- **Notificações web**: as notificações do Expo não oferecem suporte a notificações web. No entanto, algumas soluções de terceiros podem oferecer esse recurso. Considere os requisitos do seu app ao escolher um serviço.
- **Gerenciamento de tokens**: registre tanto os tokens de push do Expo quanto os tokens nativos dos dispositivos no seu banco de dados. Isso oferece flexibilidade para integrações futuras, especialmente com ferramentas de marketing que enviam notificações diretamente pelo FCM ou pelo APNs.

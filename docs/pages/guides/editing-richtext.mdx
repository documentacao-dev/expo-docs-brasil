Muitos apps precisam permitir que os usuários digitem texto. Por exemplo, se você quer criar um app de mensagens ou de rede social, provavelmente vai depender bastante de campos de texto. O React Native tem um componente `<TextInput>` integrado para isso, que resolve muitos casos simples sem muito esforço.

No entanto, às vezes você precisa de mais flexibilidade. Pense em posts longos de redes sociais, apps de anotações ou editores de documentos. O ideal é permitir estilos de texto diferentes, listas, títulos, imagens incorporadas e muito mais. Isso se chama editor de texto rico, e é um problema difícil de resolver em qualquer lugar, inclusive no React Native.

Não existe uma solução padrão para isso no ecossistema do React Native. Este guia explora as abordagens disponíveis e suas vantagens e desvantagens. Para a maioria dos apps, comece com um editor nativo da Software Mansion: [`react-native-enriched-markdown`](https://github.com/software-mansion/enriched-markdown) para saída em markdown ou [`react-native-enriched-html`](https://github.com/software-mansion/react-native-enriched-html) para saída em HTML.

## Renderizar texto rico \{#render-rich-text}

Há muitas boas opções para exibir texto rico:

- Para conteúdo em markdown, você pode usar um renderizador de markdown, como o [`react-native-enriched-markdown`](https://github.com/software-mansion/enriched-markdown).

- Para conteúdo em HTML, você pode usar o [`@expo/html-elements`](https://www.npmjs.com/package/@expo/html-elements) ou uma webview ([`react-native-webview`](/versions/latest/sdk/webview/)).

- Para ter um formato personalizado e mais controle, você pode aproveitar componentes `<Text>` aninhados para renderizar estilos e layouts.

  ```jsx
  <TextInput>
    <Text>
      <Text style={{ fontWeight: 900 }}>Some bold text</Text>Some regular text
    </Text>
  </TextInput>
  ```

- Você também pode usar a [API de módulos do Expo](/modules/overview/) para escrever um componente renderizador personalizado com primitivas nativas da plataforma, usando bibliotecas de terceiros como o [Markwon](https://github.com/noties/Markwon) no Android e o `AttributedString` no iOS.

## Abordagens para editar texto rico \{#approaches-to-edit-rich-text}

Há algumas abordagens para fazer a renderização de texto rico funcionar. No entanto, todas têm limitações diferentes.

### Editores nativos \{#native-editors}

Um editor nativo renderiza e edita texto usando as APIs de texto da plataforma, em vez de uma webview. Ele oferece desempenho nativo e um comportamento de texto que combina com o restante do app. A Software Mansion mantém duas bibliotecas que seguem essa abordagem:

- [`react-native-enriched-markdown`](https://github.com/software-mansion/enriched-markdown) edita texto rico com saída em markdown no Android, iOS, macOS e Web. Ele também oferece SDKs nativos independentes para Android (Kotlin) e iOS (Swift).
- [`react-native-enriched-html`](https://github.com/software-mansion/react-native-enriched-html) oferece componentes nativos de entrada e exibição com saída em HTML no Android, iOS e web. Ele exige a [New Architecture](/guides/new-architecture/).

[`react-native-live-markdown`](https://github.com/Expensify/react-native-live-markdown) é outra opção nativa. É um substituto direto do `<TextInput>` que aplica formatação ao vivo em markdown a cada tecla digitada.

Você também pode envolver qualquer editor nativo de texto rico usando a [API de módulos do Expo](/modules/overview/), mas, se usar editores diferentes em cada plataforma, precisará unificar as APIs e os formatos de entrada.

> O texto rico costuma ser representado com [árvores de sintaxe abstrata](https://en.wikipedia.org/wiki/Abstract_syntax_tree). Por exemplo, uma lista com marcadores pode ser um nó do tipo `bulleted-list` com vários filhos do tipo `list-item`. Você pode converter HTML e markdown para um formato de AST adequado.

Também há um esforço para portar o editor lexical para Android e iOS e oferecer um wrapper para React Native. Para acompanhar o progresso, veja a [discussão do lexical sobre suporte ao React Native](https://github.com/facebook/lexical/discussions/2410).

### Editores baseados em webview \{#webview-based-editors}

Enquanto a maioria dos componentes de UI do React Native envolve primitivas nativas da plataforma, e por isso é rápida, performática e tem **sensação nativa**, os editores de texto rico baseados em webview seguem outra abordagem.

Eles envolvem um editor de texto rico feito para web, escrito em JavaScript, dentro de uma [`react-native-webview`](/versions/latest/sdk/webview/). Funciona em todas as plataformas (Android, iOS, Web) e pode aproveitar editores de texto rico populares disponíveis para a web, mas tem um custo de desempenho e de UX.

Você não vai conseguir usar componentes de UI nativos dentro do editor. Qualquer implementação de recursos como menções ou incorporação de imagens vai precisar duplicar funcionalidades e exigir um esforço significativo.

### Bibliotecas React Native existentes baseadas em webview \{#existing-webview-based-react-native-libraries}

Para um editor baseado em webview pronto, use o [`@10play/tentap-editor`](https://github.com/10play/10tap-editor). Ele é uma boa opção quando você precisa de um editor de texto rico básico, com configuração limitada, e não tem requisitos rígidos de desempenho ou de UX.

### Editor personalizado baseado em webview \{#custom-webview-based-editor}

Se você precisar de mais configurabilidade, pode criar uma biblioteca semelhante com um editor existente só para web. No entanto, você mesmo precisa cuidar da troca de mensagens e da implementação para a web. Isso dá acesso a todas as opções que o editor oferece e permite implementar mais recursos.

- [Quill](https://quilljs.com/)
- [lexical](https://github.com/facebook/lexical)
- [slate](https://github.com/ianstormtaylor/slate)

Você vai precisar usar troca de mensagens para passar texto e eventos `onChange` para a webview e dela. Como textos ricos costumam ficar longos, é melhor modelá-lo como um componente não controlado, para evitar lag a cada tecla digitada. Além disso, se você conseguir evitar serializar e enviar o estado inteiro a cada tecla, o desempenho também melhora.

## Construindo sobre o TextInput do React Native \{#building-on-top-of-react-native-textinput}

Nesta seção, vamos discutir se é possível ter um campo de entrada de texto rico completo para uso geral.

O React Native permite componentes `<Text>` aninhados e aceita que sejam usados como filhos de `<TextInput>` para renderizar e editar texto estilizado. Ele é síncrono com a nova arquitetura do React Native (o evento `onChange` dispara imediatamente após um novo caractere ser digitado no campo de texto).

Infelizmente, o componente `<TextInput>` foi feito para trabalhar com texto simples, e ele só retorna uma string no callback `onTextChange`. Essa é uma limitação significativa.

Veja um exemplo rápido. Vamos começar renderizando um campo de texto com o seguinte texto em negrito:

```jsx
<TextInput>
  <Text>
    {/* The following will render a bold text in this format: **aa**aa */}
    <Text style={{ fontWeight: 900 }}>aa</Text>aa
  </Text>
</TextInput>
```

Em seguida, vamos acrescentar uma quinta letra `a` ao campo de texto. A posição do cursor deveria determinar se a nova letra faz parte da parte em negrito ou não. Infelizmente, o callback retorna apenas `aaaaa`.

Existe uma prop adicional, `onSelectionChange`, que pode ser usada para obter essa informação. No entanto, ela torna a tarefa bem mais difícil. Inserir caracteres adicionais (como quebras de linha para listas ou marcadores) também dessincroniza a seleção.

Existem algumas tentativas de criar esse tipo de editor, como o [`markdown-editor`](https://github.com/shakogegia/markdown-editor) (sem manutenção ativa) e o [`rn-text-editor`](https://github.com/amjadbouhouch/rn-text-editor) (em beta), mas não existe nenhum pacote amplamente usado.

## Editores de markdown com marcadores de estilo visíveis \{#markdown-editors-with-visible-styling-markers}

Se usar markdown para estilizar o texto atende ao seu requisito, você pode renderizar o markdown em uma view separada, não editável, enquanto o usuário edita. Não é complexo criar isso por conta própria usando qualquer renderizador de markdown.

Essa experiência de edição atende bem a usuários avançados ou a apps de programação e tecnologia. Você também pode explorar a renderização de texto rico mostrando o markdown apenas no trecho de texto selecionado, ou outras abordagens híbridas.

## Resumo \{#summary}

Embora existam muitas opções para exibir texto rico, não há uma solução única para edição de texto rico no React Native. Para a maioria dos apps, comece com um dos [editores nativos](#native-editors) da Software Mansion.

Escolha um editor baseado em webview quando precisar de um recurso que só um editor web oferece. Construa sobre as primitivas do React Native apenas quando seus requisitos forem mínimos, pois você mesmo precisará lidar com seleção e formatação.

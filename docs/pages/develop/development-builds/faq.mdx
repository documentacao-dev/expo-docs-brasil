<FAQ>

## Saiba mais sobre development builds e Expo Go

<Collapsible summary="Diferença entre Expo Go e development builds">

O [Expo Go](https://expo.dev/go) é um app playground para estudantes e iniciantes começarem rapidamente. Ele vem com um conjunto fixo de bibliotecas nativas embutidas, então você pode escrever código JavaScript e ver as mudanças na hora, sem gerar um app nativo por conta própria. Um development build é um ambiente de desenvolvimento completo para trabalhar nos seus apps Expo de nível de produção.

</Collapsible>

<Collapsible summary="App nativo e bundle JavaScript">

O **app nativo** é o que você instala no seu aparelho. O Expo Go é um app nativo pronto que funciona como um playground: depois de instalado, não dá para alterá-lo. Para adicionar novas bibliotecas nativas ou mudar coisas como o nome e o ícone do app, você precisa gerar um app nativo próprio (um development build).

O **bundler JavaScript (`expo start`)** é onde ficam o código de UI e a lógica de negócio do seu app. Em apps de produção, existe um bundle **main.js** que vai junto com o próprio app. Em desenvolvimento, esse bundle JS é recarregado ao vivo a partir da sua máquina local. O papel principal do React Native é dar ao código JavaScript um jeito de acessar as APIs nativas (Image, Camera, Notifications e outras). No entanto, só podem ser usadas as APIs e bibliotecas que foram incluídas no **app nativo**.

</Collapsible>

## Por que usar um development build (ou seja, o que _não_ dá para fazer no Expo Go e por quê)

O Expo Go é um playground para estudantes e iniciantes entenderem o básico do React Native. Ele é limitado e não serve para projetos de nível de produção, então a maioria dos apps migra para development builds. Vale saber exatamente o que é _impossível_ no Expo Go e _por quê_, para decidir com conhecimento de causa quando e por que fazer essa mudança.

<Collapsible summary="Usar bibliotecas com código nativo que não estão no Expo Go">

Tome como exemplo o [`react-native-webview`](/versions/latest/sdk/webview/), uma biblioteca que tem código nativo, mas [está incluída no Expo Go](https://github.com/expo/expo/blob/main/apps/expo-go/package.json#L23). Quando você executa o comando `npx expo install react-native-webview` no projeto, ele instala a biblioteca no diretório **node_modules**, que inclui tanto o código JS quanto o código nativo. Mas o bundle JS que você está gerando usa _apenas_ o código JS. Depois, esse bundle JS é enviado ao Expo Go, e ele interage com o código nativo que já estava embutido no app.

Já quando você tenta usar uma biblioteca que não está incluída, por exemplo o [`react-native-firebase`](/guides/using-firebase/#using-react-native-firebase), você pode usar o código JS e recarregar o novo bundle no Expo Go, mas dá erro imediatamente, porque o código JS tenta chamar o código nativo do pacote React Native Firebase, que não existe no Expo Go. Não há como colocar o código nativo no app do Expo Go, a menos que ele já estivesse incluído no bundle enviado às lojas de apps.

</Collapsible>

<Collapsible summary="Testar mudanças no ícone, nome e splash screen do app">

Se você desenvolver seu app só no Expo Go, pode gerar uma versão para a loja que usará os valores e as imagens que você informou. Só não será possível testá-la no Expo Go.

Esses assets nativos vão junto com o bundle nativo e não podem ser alterados depois que o app é instalado. O app Expo Go mostra uma splash screen, que é o ícone do seu app sobre uma cor sólida de fundo. É uma emulação apenas para desenvolvimento, para ver como a splash screen provavelmente vai ficar. Porém, ela é limitada: por exemplo, você não consegue testar o `SplashScreen.setOptions` para animar a splash screen.

</Collapsible>

<Collapsible summary="Notificações push remotas">

Embora as [notificações in-app](/versions/latest/sdk/notifications/) estejam disponíveis no Expo Go, as notificações push remotas (ou seja, o envio de uma notificação push de um servidor para o app) não estão. Isso acontece porque o serviço de push deve estar ligado aos seus próprios certificados de notificação push. Embora seja possível fazer funcionar no Expo Go, isso costuma gerar confusão em builds de produção. Recomendamos testar as notificações push remotas em development builds, para garantir paridade de comportamento entre desenvolvimento e produção.

</Collapsible>

<Collapsible summary="Implementando App Links e Universal Links">

Tanto os [Android App Links](/linking/android-app-links/) quanto os [iOS Universal Links](/linking/ios-universal-links/) exigem uma associação de mão dupla entre o app nativo e o site. Em especial, exigem que o app nativo inclua a URL do site vinculado. Isso é impossível no Expo Go por causa da imutabilidade do código nativo mencionada acima.

</Collapsible>

<Collapsible summary="Abrir projetos com outras versões do SDK">

Cada build do Expo Go aceita uma versão do SDK. As versões do SDK do projeto e do Expo Go precisam ser iguais.

Em um aparelho Android, em um Android Emulator ou em um iOS Simulator, instale uma versão compatível em [expo.dev/go](https://expo.dev/go) ou use a [CLI `expo-go`](/develop/tools/#expo-go-cli).

Veja [Resolver incompatibilidade de versão do Expo Go](/troubleshooting/expo-go-version-mismatch/) para as instruções de cada plataforma.

</Collapsible>

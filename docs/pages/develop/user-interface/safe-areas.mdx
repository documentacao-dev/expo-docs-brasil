Criar uma safe area garante que o conteúdo da tela do app fique posicionado corretamente. Isso significa que ele não será sobreposto por notches, barras de status, indicadores de tela inicial e outros elementos de interface que fazem parte do hardware físico do dispositivo ou são controlados pelo sistema operacional. Quando o conteúdo é sobreposto, ele fica escondido atrás desses elementos.

Veja um exemplo de conteúdo de uma tela do app escondido pela barra de status no Android. No iOS, o mesmo conteúdo fica escondido pelos cantos arredondados, pelo notch e pela barra de status.

## Use a biblioteca `react-native-safe-area-context` \{#use-react-native-safe-area-context-library}

A [`react-native-safe-area-context`](https://github.com/AppAndFlow/react-native-safe-area-context) oferece uma API flexível para lidar com os insets da safe area dos dispositivos Android e iOS. Ela também traz o componente `SafeAreaView`, que você pode usar no lugar de um [`<View>`](https://reactnative.dev/docs/view) para considerar as safe areas automaticamente nos componentes de tela.

Usando a biblioteca, o resultado do exemplo anterior muda, pois o conteúdo passa a ser exibido dentro da safe area, como mostrado abaixo:

### Instalação \{#installation}

Você pode pular a instalação do `react-native-safe-area-context` se criou o projeto com [o template padrão](/get-started/create-a-project/). Essa biblioteca é instalada como peer dependency da biblioteca Expo Router. Caso contrário, instale-a executando o comando a seguir:

<Terminal
  cmd={{

    yarn: ['$ yarn expo install react-native-safe-area-context'],
    pnpm: ['$ pnpm expo install react-native-safe-area-context'],
    bun: ['$ bun expo install react-native-safe-area-context'],
  }}

### Uso \{#usage}

Você pode usar diretamente o [`SafeAreaView`](https://appandflow.github.io/react-native-safe-area-context/api/safe-area-view) para envolver o conteúdo do componente da tela. Ele é um `<View>` comum com os insets da safe area aplicados como padding ou margin extra.

```tsx src/app/index.tsx
import { Text } from 'react-native';
import { SafeAreaView } from 'react-native-safe-area-context';

export default function HomeScreen() {
  return (
    <SafeAreaView style={{ flex: 1 }}>
      <Text>Content is in safe area.</Text>
    </SafeAreaView>
  );
}
```

<Collapsible summary="Usando outro template do Expo e sem o Expo Router instalado?">

Importe e adicione o [`SafeAreaProvider`](https://appandflow.github.io/react-native-safe-area-context/api/safe-area-provider) ao arquivo do componente raiz (como o **App.tsx**) antes de usar o `SafeAreaView` no componente da tela.

{/* prettier-ignore */}
```tsx App.tsx
import { SafeAreaProvider } from 'react-native-safe-area-context';

export default function App() {
  return (
    <SafeAreaProvider>
      {/* Your app content */}
    </SafeAreaProvider>
  );
}
```

## Alternativa: hook `useSafeAreaInsets` \{#alternate-usesafeareainsets-hook}

Como alternativa ao `SafeAreaView`, você pode usar o hook [`useSafeAreaInsets`](https://appandflow.github.io/react-native-safe-area-context/api/use-safe-area-insets) no componente da tela. Ele dá acesso direto aos insets da safe area, permitindo aplicar padding em cada borda do `<View>` usando um inset desse hook.

O exemplo abaixo usa o hook `useSafeAreaInsets`. Ele aplica padding no topo de um `<View>` usando `insets.top`.

```tsx src/app/index.tsx
import { Text, View } from 'react-native';
import { useSafeAreaInsets } from 'react-native-safe-area-context';

export default function HomeScreen() {
  const insets = useSafeAreaInsets();

  return (
    <View style={{ flex: 1, paddingTop: insets.top }}>
      <Text>Content is in safe area.</Text>
    </View>
  );
}
```

O hook fornece os insets no seguinte objeto:

```ts
{
  top: number,
  right: number,
  bottom: number,
  left: number
}
```

## Informações adicionais \{#additional-information}

### Exemplo mínimo \{#minimal-example}

Abaixo está um exemplo mínimo funcional que usa o hook `useSafeAreaInsets` para aplicar padding no topo de uma view.

<SnackInline label="Usando react-native-safe-area-context" dependencies={['react-native-safe-area-context']}>

```tsx collapseHeight=320
import { Text, View } from 'react-native';
import { SafeAreaProvider, useSafeAreaInsets } from 'react-native-safe-area-context';

function HomeScreen() {
  const insets = useSafeAreaInsets();
  return (
    <View style={{ flex: 1, paddingTop: insets.top }}>
      <Text style={{ fontSize: 28 }}>Content is in safe area.</Text>
    </View>
  );
}

export default function App() {
  return (
    <SafeAreaProvider>
      <HomeScreen />
    </SafeAreaProvider>
  );
}
```

</SnackInline>

### Uso com React Navigation \{#usage-with-react-navigation}

Por padrão, o React Navigation oferece suporte a safe areas e usa o `react-native-safe-area-context` como peer dependency. Para mais informações, veja a [documentação do React Navigation](https://reactnavigation.org/docs/handling-safe-area/).

### Uso na web \{#usage-with-web}

Na web, use os valores CSS `env(safe-area-inset-*)` para o espaçamento da safe area. O navegador aplica esses valores na renderização no cliente, na renderização no servidor e na geração estática. O espaçamento de safe area feito com CSS não exige a biblioteca `react-native-safe-area-context`.

Com o Expo Router, crie o **src/safe-area.css** e e importe-o no [layout raiz](/router/basics/navigation-layouts/#root-layout) que você já tem:

```tsx src/app/_layout.tsx
import '../safe-area.css';
```

Aplique uma classe a um elemento em uma [rota específica para web](/router/advanced/platform-specific-modules/):

```tsx src/app/index.web.tsx
export default function HomeScreen() {
  return <main className="safe-area-content">Content is in the safe area.</main>;
}
```

No **src/safe-area.css**, defina o espaçamento da classe `safe-area-content`:

```css src/safe-area.css
.safe-area-content {
  padding-top: env(safe-area-inset-top, 0px);
  padding-right: env(safe-area-inset-right, 0px);
  padding-bottom: env(safe-area-inset-bottom, 0px);
  padding-left: env(safe-area-inset-left, 0px);
}
```

O navegador fornece as variáveis de ambiente `safe-area-inset-*`. Esses valores indicam a distância entre a respectiva borda da viewport e a safe area, mantendo o conteúdo longe de notches e cantos arredondados. A função `env()` é usada para ler esses valores. Veja a [referência de `env()` em CSS](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env) para mais detalhes.

O navegador atualiza esse espaçamento sem uma atualização de estado do React. Mantenha uma rota correspondente em **src/app/index.tsx** usando o `react-native-safe-area-context` para Android e iOS.

Exportações estáticas e de servidor incluem a folha de estilo no HTML inicial.

Em desenvolvimento, as [rotas assíncronas](/router/web/async-routes/) podem carregar o CSS do layout depois do conteúdo transmitido e causar um deslocamento de layout. Para contornar essa limitação do desenvolvimento, renderize as regras em um elemento `<style>` dentro do `<head>` do seu [componente HTML raiz](/router/web/static-rendering/#root-html). Use o **src/app/+html.tsx** para esse componente. Imports de CSS no **+html.tsx** não funcionam.

A partir do SDK 58, o Expo Router desativa as medições automáticas da safe area na web para preservar o conteúdo transmitido durante a hidratação. Não adicione outro `SafeAreaProvider` para restaurar essas medições. As atualizações dele podem interromper a hidratação e descartar o conteúdo transmitido pendente, mesmo se você fornecer `initialMetrics`.

Veja a [referência do safe-area context](/versions/latest/sdk/safe-area-context/#context) para o comportamento dos hooks e componentes. Os valores de CSS não alteram os números retornados por esses hooks.

Sem o Expo Router, o provider da biblioteca ainda oferece medições para a web. Se você usar os componentes ou hooks dela, configure o `SafeAreaProvider` como descrito na [seção de uso](#usage). O CSS continua sendo a abordagem recomendada para o espaçamento na web.

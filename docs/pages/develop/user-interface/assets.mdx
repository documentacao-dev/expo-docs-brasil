Um **asset estático** é um arquivo empacotado junto com o binário nativo do seu app. Esse tipo de arquivo não faz parte do bundle JavaScript do app, que contém o código. Tipos comuns de assets estáticos incluem imagens, vídeos, sons, arquivos de banco de dados para SQLite e fontes. Esses assets podem ser servidos localmente, a partir do seu projeto, ou remotamente, pela rede.

Este guia mostra as diferentes formas de carregar e usar assets estáticos no seu projeto e também traz informações sobre como otimizar e reduzir o tamanho dos assets.

## Servir um asset localmente \{#serve-an-asset-locally}

Quando um asset está armazenado no sistema de arquivos do projeto, ele pode ser incorporado ao binário do app no momento do build ou carregado em tempo de execução. Você pode importá-lo como um módulo JavaScript usando as instruções `require` ou `import`.

Por exemplo, para renderizar uma imagem chamada **example.png** no **App.js**, use `require` para importar a imagem do diretório **assets/images** do projeto e passe-a para o componente `<Image>`:

```tsx src/app/index.tsx
<Image source={require('./assets/images/example.png')} />
```

No exemplo acima, o bundler lê os metadados da imagem importada e fornece automaticamente a largura e a altura. Para mais informações, veja [Recursos de imagem estáticos](https://reactnative.dev/docs/images#static-image-resources).

Bibliotecas como `expo-image` e `expo-file-system` funcionam de forma parecida com o componente `<Image>` quando usadas com assets locais.

### Como os assets locais são servidos \{#how-are-assets-served-locally}

Os assets armazenados localmente são servidos via HTTP em desenvolvimento. Em apps de produção, eles são incluídos automaticamente no binário do app durante o build e servidos a partir do disco no dispositivo.

### Carregar um asset no build com o plugin de config `expo-asset` \{#load-an-asset-at-build-time-with-expo-asset-config-plugin}

Para carregar um asset no build, use o [plugin de config](/versions/latest/sdk/asset/#example-appjson-with-config-plugin) da biblioteca `expo-asset`. Esse plugin incorpora o arquivo do asset ao seu projeto nativo.

<Step label="1">

Instale a biblioteca `expo-asset`.

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-asset'],
    yarn: ['$ yarn expo install expo-asset'],
    pnpm: ['$ pnpm expo install expo-asset'],
    bun: ['$ bun expo install expo-asset'],
  }}
/>

</Step>

<Step label="2">

Adicione o plugin de config ao arquivo de [app config](/versions/latest/config/app/#plugins) do seu projeto. A configuração deve conter o caminho do arquivo do asset, usando a propriedade [`assets`](/versions/latest/sdk/asset/#configurable-properties), que recebe um array com um ou mais arquivos ou diretórios para vincular ao projeto nativo.

O caminho de cada arquivo de asset deve ser relativo à raiz do projeto, já que o arquivo de app config fica no diretório raiz do projeto.

```json app.json
{
  "expo": {
    "plugins": [
      [
        "expo-asset",
        {
          /* @info The path to the asset file is relative to the project's root. */
          "assets": ["./assets/images/example.png"]
          /* @end */
        }
      ]
    ]
  }
}
```

</Step>

<Step label="3">

Depois de incorporar o asset com o plugin de config, [crie um novo development build](/develop/development-builds/introduction/#how-would-you-like-to-build-your-development-build). Agora você pode importar e usar o asset no projeto sem usar `require` ou `import`.

Por exemplo, o **example.png** está vinculado pelo plugin de config acima. Você pode importá-lo diretamente no componente e usar o nome do recurso como URI. Observe que, ao renderizar assets sem usar `require`, é preciso informar explicitamente a largura e a altura.

```tsx src/app/index.tsx
import { Image } from 'expo-image';
/* @hide ... */ /* @end */

export default function HomeScreen() {
  return <Image source={{ uri: 'example' }} style={{ width: 100, height: 100 }} />;
}
```

</Step>

> **info** O plugin de config `expo-asset` aceita diferentes formatos de arquivo. Para mais informações sobre esses formatos, veja a [referência da API de Assets](/versions/latest/sdk/asset/#configurable-properties). Se você não encontrar um formato de arquivo aceito pelo plugin de config, pode usar o hook [`useAssets`](#load-an-asset-at-runtime-with-useassets-hook) para carregar o asset em tempo de execução.

### Carregar um asset em tempo de execução com o hook `useAssets` \{#load-an-asset-at-runtime-with-useassets-hook}

O hook `useAssets` da biblioteca `expo-asset` permite carregar assets de forma assíncrona. Ele baixa e armazena o asset localmente e, depois que o asset é carregado, retorna uma lista com as instâncias desse asset.

<Step label="1">

Instale a biblioteca `expo-asset`.

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-asset'],
    yarn: ['$ yarn expo install expo-asset'],
    pnpm: ['$ pnpm expo install expo-asset'],
    bun: ['$ bun expo install expo-asset'],
  }}
/>

</Step>

<Step label="2">

Importe o hook [`useAssets`](/versions/latest/sdk/asset/#useassetsmoduleids) da biblioteca `expo-asset` no componente da sua tela:

```tsx src/app/index.tsx
import { useAssets } from 'expo-asset';

export default function HomeScreen() {
  const [assets, error] = useAssets([
    require('path/to/example-1.jpg'),
    require('path/to/example-2.png'),
  ]);

  return assets ? <Image source={assets[0]} /> : null;
}
```

</Step>

## Servir um asset remotamente \{#serve-an-asset-remotely}

Quando um asset é servido remotamente, ele não é incluído no binário do app durante o build. Você pode usar a URL do recurso no seu projeto se ele estiver hospedado remotamente. Por exemplo, passe a URL para o componente `<Image>` para renderizar uma imagem remota:

```jsx App.js
import { Image } from 'expo-image';
/* @hide ... */ /* @end */

function App() {
  return (
    <Image source={{ uri: 'https://example.com/logo.png' }} style={{ width: 50, height: 50 }} />
  );
}
```

Não há garantia de que imagens servidas remotamente por uma URL da web estejam disponíveis, porque a conexão com a internet pode não estar disponível ou o asset pode ter sido removido.

Além disso, carregar assets remotamente exige que você informe os metadados do asset. No exemplo acima, como o bundler não consegue obter a largura e a altura da imagem, esses valores são passados explicitamente ao componente `<Image>`. Se você não fizer isso, a imagem assume o padrão de 0px por 0px.

## Informações adicionais \{#additional-information}

### Métodos de otimização manual \{#manual-optimization-methods}

#### Imagens \{#images}

Você pode comprimir imagens com as ferramentas a seguir:

- [`guetzli`](https://github.com/google/guetzli)
- [`pngcrush`](https://pmt.sourceforge.io/pngcrush/)
- [`optipng`](https://optipng.sourceforge.net/)

Alguns otimizadores de imagem são sem perda (lossless). Eles recodificam a imagem para deixá-la menor, sem nenhuma alteração ou perda nos pixels exibidos. Quando você precisa que cada pixel fique intacto em relação à imagem original, um otimizador sem perda e um formato sem perda, como o PNG, são boas escolhas.

Outros otimizadores de imagem são com perda (lossy). A imagem otimizada é diferente da original. Muitas vezes, os otimizadores com perda são mais eficientes, porque descartam informações visuais que reduzem o tamanho do arquivo, mas deixam a imagem praticamente idêntica para as pessoas. Ferramentas como o `imagemagick` podem usar algoritmos de comparação, como o [SSIM](https://en.wikipedia.org/wiki/Structural_similarity), para mostrar o quão parecidas duas imagens são. É bem comum que uma imagem otimizada com mais de 95% de semelhança com a original tenha bem menos de 95% do tamanho do arquivo original.

#### Outros assets \{#other-assets}

Para assets como GIFs, vídeos ou outros assets que não são código nem imagem, cabe a você otimizar e reduzir o tamanho desses arquivos.

> **Note**: GIFs são um formato muito ineficiente. Codecs de vídeo modernos conseguem arquivos bem menores e com melhor qualidade.

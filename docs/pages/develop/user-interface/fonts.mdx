Android e iOS vêm com o seu próprio conjunto de fontes da plataforma. Para oferecer uma experiência consistente ao usuário e reforçar a identidade visual do seu app, você pode usar fontes personalizadas.

Este guia cobre as diferentes formas de adicionar e carregar uma fonte personalizada no projeto e também traz informações adicionais sobre fontes.

## Adicione uma fonte personalizada

Há duas formas de adicionar uma fonte personalizada ao projeto:

- Adicione um arquivo de fonte nos seus assets locais. Por exemplo, um arquivo de fonte no diretório **assets/fonts**.
- Instale um pacote de Google Font. Por exemplo, instalando o pacote [`@expo-google-fonts/inter`](https://www.npmjs.com/package/@expo-google-fonts/inter).

### Formatos de fonte suportados

O Expo SDK oferece suporte oficial aos formatos de fonte OTF e TTF nas plataformas Android, iOS e web. Se a sua fonte estiver em outro formato, você precisa fazer uma configuração avançada para que esse formato funcione no projeto.

### Fontes variáveis

Uma fonte variável reúne vários estilos em um único arquivo. Em vez de incluir um arquivo para cada peso, você inclui um arquivo só e escolhe o estilo com as props de estilo `fontWeight` e `fontStyle`. Tanto o [config plugin](#with-expo-font-config-plugin) quanto o [hook `useFonts`](#with-usefonts-hook) aceitam fontes variáveis.

> **info** Android e iOS oferecem suporte a fontes variáveis a partir do SDK 58. Nas versões anteriores, use arquivos de fonte estáticos.

Cada plataforma decide de forma diferente quais estilos um arquivo oferece, então confira o arquivo antes de depender dele:

- **Android** lê o eixo `wght` e desenha a partir dele cada peso que `fontWeight` pode indicar, limitado ao intervalo que o eixo declara. Isso exige Android 10 ou mais recente. Nas versões anteriores, a fonte é renderizada no peso padrão, e o Android cria o negrito engrossando as letras.
- **iOS** lê as _instâncias nomeadas_ que o arquivo declara. Uma instância nomeada é um estilo que o designer da fonte nomeou e posicionou em cada eixo, como "Bold" ou "Condensed Light". O React Native seleciona a instância nomeada cujo peso está mais próximo do que você pediu. Um peso que nenhuma instância nomeada cobre fica fora de alcance. Se o arquivo não declara instâncias nomeadas, só o estilo padrão é renderizado.

Para `fontStyle: 'italic'`, o Android aplica o eixo `ital` da fonte no Android 15 e versões mais recentes. Nas versões anteriores, o Android cria o itálico inclinando as letras retas. O iOS usa as instâncias nomeadas em itálico do arquivo.

No React Native 0.88 (Expo SDK 58) e versões mais recentes, você também pode definir qualquer eixo diretamente em um componente com a prop de estilo [`fontVariationSettings`](https://reactnative.dev/docs/text-style-props), como `fontVariationSettings: "'wght' 650, 'wdth' 90"`. Ela funciona em `<Text>` e `<TextInput>` nas duas plataformas (Android 8 ou mais recente), e os eixos definidos ali têm prioridade sobre `fontWeight` e `fontStyle`.

Inspecione os eixos e as instâncias nomeadas de um arquivo com uma ferramenta como o [fontTools](https://fonttools.readthedocs.io/). Se um estilo de que você precisa estiver fora de alcance em uma plataforma, use o fontTools para [extrair essa configuração de eixos](https://fonttools.readthedocs.io/en/latest/varLib/instancer.html) e salvá-la como um arquivo de fonte estático separado.

### Como escolher entre OTF e TTF

Se a fonte que você está usando tem versões OTF e TTF, prefira OTF. Os arquivos **.otf** são menores que os **.ttf**. Às vezes, o OTF também renderiza um pouco melhor em certos contextos.

## Use um arquivo de fonte local

Copie o arquivo para o diretório **assets/fonts** do seu projeto.

> **info** O caminho **assets/fonts** é uma convenção comum em apps React Native para guardar arquivos de fonte. Você pode colocar esses arquivos em outro lugar, se seguir uma convenção própria.

Há duas formas de usar o arquivo de fonte local no projeto:

- Incorporar o arquivo de fonte com o [config plugin `expo-font`](/versions/latest/sdk/font/#configuration-in-app-config) (somente Android e iOS).
- Carregar o arquivo de fonte com o hook [`useFonts`](/versions/latest/sdk/font/#usefonts) em tempo de execução (Android, iOS e web).

### Com o config plugin `expo-font`

O config plugin `expo-font` permite incorporar um ou mais arquivos de fonte no código nativo do projeto. Ele aceita `ttf` e `otf` para Android e iOS, e `woff` e `woff2` só no iOS.

> **Note:** Config plugins só rodam nas plataformas nativas (Android e iOS). Para a web, use o [hook `useFonts`](#with-usefonts-hook).

Este é o método recomendado para adicionar fontes ao app, por causa dos seguintes benefícios:

- As fontes ficam disponíveis assim que o app inicia no dispositivo.
- Não é preciso código adicional para carregar as fontes de forma assíncrona quando o app inicia.
- As fontes ficam disponíveis de forma consistente em todos os dispositivos onde o app está instalado, porque estão empacotadas dentro do app.

Porém, esse método também tem algumas limitações:

- Não funciona com o Expo Go, já que ele exige [criar um development build](/develop/development-builds/introduction/#how-would-you-like-to-build-your-development-build).

Para incorporar uma fonte ao projeto, siga os passos abaixo:

<Step label="1">

Depois de adicionar o arquivo de fonte personalizado ao projeto, instale a biblioteca `expo-font`.

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-font'],
    yarn: ['$ yarn expo install expo-font'],
    pnpm: ['$ pnpm expo install expo-font'],
    bun: ['$ bun expo install expo-font'],
  }}
/>

</Step>

<Step label="2">

Adicione o config plugin ao arquivo de [app config](/versions/latest/config/app/#plugins). A configuração precisa conter o caminho do arquivo de fonte usando as propriedades [`fonts`, `android` ou `ios`](/versions/latest/sdk/font/#configurable-properties), que recebem um array com uma ou mais definições de fonte. O caminho de cada arquivo de fonte é relativo à raiz do projeto.

O exemplo abaixo mostra todas as formas válidas de especificar uma fonte: como um array de objetos que definem `fontFamily` e outras propriedades, ou como um array de caminhos para arquivos de fonte.

No Android, você pode especificar `fontFamily`, `weight` e, opcionalmente, `style` (o padrão é `"normal"`), o que incorpora as fontes como [recursos XML](https://developer.android.com/develop/ui/views/text-and-emoji/fonts-in-xml) nativos. Se você fornecer só os caminhos dos arquivos em um array, o nome do arquivo vira o nome da família da fonte no Android. O iOS sempre extrai o nome da família da própria fonte.

Se você pretende referenciar as fontes só pelo `fontFamily`, forneça um array de caminhos de fonte (veja `FiraSans-MediumItalic.ttf` abaixo) e siga a nossa [recomendação para nomear arquivos](#how-to-determine-which-font-family-name-to-use).

Se quiser referenciar as fontes usando uma combinação de `fontFamily`, `weight` e `style`, forneça um array de objetos (veja `Inter` abaixo).

Para uma [fonte variável](#variable-fonts) no Android, declare o caminho do arquivo em cada entrada de `fontDefinitions` ou, uma vez, ao lado de `fontFamily`, para não repetir o caminho. Cada definição precisa de um par `weight` e `style` que nenhuma outra definição da mesma família use, porque o Android resolve uma família por esse par.

```json app.json
{
  "expo": {
    "plugins": [
      [
        "expo-font",
        {
          "fonts": [
            /* @info Refer to this font using fontFamily: 'FiraSans-MediumItalic' */
            "./assets/fonts/FiraSans-MediumItalic.ttf"
            /* @end */
          ],
          "android": {
            "fonts": [
              {
                "fontFamily": "Inter",
                "fontDefinitions": [
                  {
                    /* @info Refer to this font using fontFamily: 'Inter', fontWeight: '700', fontStyle: 'italic' */
                    "path": "./assets/fonts/Inter-BoldItalic.ttf",
                    /* @end */
                    "weight": 700,
                    "style": "italic"
                  },
                  {
                    "path": "./assets/fonts/Inter-Bold.ttf",
                    "weight": 700
                  }
                ]
              },
              {
                "fontFamily": "Roboto Flex",
                /* @info One variable font file backs every definition below. */
                "path": "./assets/fonts/RobotoFlex.ttf",
                /* @end */
                "fontDefinitions": [
                  { "weight": 400 },
                  { "weight": 700 },
                  /* @info Refer to this font using fontFamily: 'Roboto Flex', fontWeight: '400', fontStyle: 'italic' */
                  { "weight": 400, "style": "italic", "axes": { "slnt": -10 } }
                  /* @end */
                ]
              }
            ]
          },
          "ios": {
            "fonts": [
              "./assets/fonts/Inter-Bold.ttf",
              "./assets/fonts/Inter-BoldItalic.ttf",
              "./assets/fonts/RobotoFlex.ttf"
            ]
          }
        }
      ]
    ]
  }
}
```

`style` seleciona o estilo que `fontStyle` corresponde, mas não inclina os glifos. Para obter um itálico a partir de um arquivo reto, defina um eixo de inclinação em `axes`, como `slnt` ou `ital`.

`axes` aceita qualquer [eixo de variação](https://learn.microsoft.com/en-us/typography/opentype/spec/dvaraxisreg) que a fonte declara, como `wdth` para um estilo condensado. As tags têm quatro caracteres e diferenciam maiúsculas de minúsculas. Os eixos registrados (`ital`, `opsz`, `slnt`, `wdth`, `wght`) são em minúsculas, e os eixos próprios de uma fonte são em maiúsculas, como `GRAD`. `weight` define `wght`, a menos que você sobrescreva isso em `axes`.

No iOS, `path` e `axes` não se aplicam. Liste o arquivo da fonte variável em `ios.fonts` como faria com uma fonte estática. Os estilos que você pode selecionar são as [instâncias nomeadas](#variable-fonts) que o arquivo declara. Para chegar a outras posições em um eixo, use a prop de estilo [`fontVariationSettings`](#variable-fonts) no React Native 0.88 ou mais recente.

</Step>

<Step label="3">

Depois de incorporar a fonte com o config plugin, crie um [novo development build](/develop/development-builds/introduction/#how-would-you-like-to-build-your-development-build) e instale-o no seu dispositivo, no Android Emulator ou no iOS Simulator.

Você pode usar a fonte com `<Text>` especificando a prop de estilo `fontFamily`. Os exemplos abaixo correspondem às fontes definidas na configuração acima.

```tsx
<Text style={{ fontFamily: 'Inter', fontWeight: '700' }}>Inter Bold</Text>
<Text style={{ fontFamily: 'Inter', fontWeight: '700', fontStyle: 'italic' }}>Inter Bold Italic</Text>
<Text style={{ fontFamily: 'FiraSans-MediumItalic' }}>Fira Sans Medium Italic</Text>
<Text style={{ fontFamily: 'Roboto Flex', fontWeight: '400', fontStyle: 'italic' }}>Roboto Flex Italic</Text>
```

</Step>

- **iOS:** veja [Adicionando uma fonte personalizada ao seu app](https://developer.apple.com/documentation/uikit/text_display_and_fonts/adding_a_custom_font_to_your_app) na documentação da Apple Developer.

#### Como descobrir qual nome de família de fonte usar

- Se você fornecer as fontes como um array de caminhos de arquivo (como descrito acima), no Android o nome do arquivo (sem a extensão) vira o nome da família da fonte. No iOS, o nome da família é lido do próprio arquivo de fonte. Recomendamos nomear o arquivo igual ao seu [nome PostScript](#what-is-postscript-name-of-a-font), para que o nome da família fique consistente nas duas plataformas.

- Se você usar a sintaxe de objeto, informe o "Family Name". Ele pode ser encontrado no app Font Book do macOS, em [fontdrop.info](https://fontdrop.info/) ou em outros programas.

<Collapsible summary="O que é o nome PostScript de um arquivo de fonte?">

O **nome PostScript** de um arquivo de fonte é um identificador único atribuído à fonte, seguindo o padrão PostScript da Adobe. Sistemas operacionais e apps usam esse nome para se referir à fonte. Ele não é o **nome de exibição** da fonte.

Por exemplo, o nome PostScript do arquivo da fonte Inter Black é `Inter-Black`.

### Com o hook `useFonts`

O hook `useFonts`, da biblioteca `expo-font`, permite carregar o arquivo de fonte de forma assíncrona. Esse hook acompanha o estado de carregamento e carrega a fonte quando o app é inicializado.

Ele funciona com todas as versões do Expo SDK e com o Expo Go. Para carregar uma fonte no projeto com o hook `useFonts`, siga os passos abaixo:

<Step label="1">

Depois de adicionar o arquivo de fonte personalizado ao projeto, instale as bibliotecas `expo-font` e `expo-splash-screen`.

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-font expo-splash-screen'],
    yarn: ['$ yarn expo install expo-font expo-splash-screen'],
    pnpm: ['$ pnpm expo install expo-font expo-splash-screen'],
    bun: ['$ bun expo install expo-font expo-splash-screen'],
  }}
/>

A biblioteca [`expo-splash-screen`](/versions/latest/sdk/splash-screen/) traz o componente `SplashScreen`, que você pode usar para impedir a renderização do app até que a fonte esteja carregada e pronta.

</Step>

<Step label="2">

Mapeie o arquivo de fonte usando o hook `useFonts` em um componente de nível superior, como o arquivo do layout raiz (**src/app/\_layout.tsx**) do projeto:

```tsx src/app/_layout.tsx
/* @info Import `useFonts` hook from `expo-font`. */ import { useFonts } from 'expo-font'; /* @end */
/* @info Import `SplashScreen` so that when the fonts are not loaded, we can continue to show `SplashScreen`. */ import * as SplashScreen from 'expo-splash-screen'; /* @end */
import {useEffect} from 'react';

/* @info This prevents `SplashScreen` from auto hiding while the fonts are in loading state. */
SplashScreen.preventAutoHideAsync();
/* @end */

export default function RootLayout() {
  /* @info Map the font file using `useFonts` hook. */
  const [loaded, error] = useFonts({
    'Inter-Black': require('./assets/fonts/Inter-Black.otf'),
    'Roboto Flex': require('./assets/fonts/RobotoFlex.ttf'),
  });
  /* @end */

  useEffect(() => {
    if (loaded || error) {
      /* @info After the custom fonts have loaded, we can hide the splash screen and display the app screen. */
      SplashScreen.hideAsync();
      /* @end */
    }
  }, [loaded, error]);

  if (!loaded && !error) {
    return null;
  }

  return (
    /* @hide ... */ /* @end */
  )
}
```

</Step>

<Step label="3">

Use a fonte no `<Text>` usando a prop de estilo `fontFamily` em um componente React:

```tsx
<Text style={{ fontFamily: 'Inter-Black' }}>Inter Black</Text>
```

Se o arquivo que você mapeou for uma [fonte variável](#variable-fonts), escolha um estilo com as props de estilo `fontWeight` e `fontStyle`:

```tsx
<Text style={{ fontFamily: 'Roboto Flex', fontWeight: '300' }}>Roboto Flex Light</Text>
<Text style={{ fontFamily: 'Roboto Flex', fontWeight: '700' }}>Roboto Flex Bold</Text>
```

`useFonts` lê apenas o eixo de peso. Para definir outro eixo, como `wdth` ou `slnt`, incorpore a fonte com o [config plugin](#with-expo-font-config-plugin) no Android, ou defina a prop de estilo [`fontVariationSettings`](#variable-fonts) no React Native 0.88 ou mais recente.

</Step>

#### Carregando vários pesos e estilos de uma mesma família de fonte

> **info** Carregar vários arquivos de fonte sob um mesmo nome de família está disponível a partir do SDK 58.

A sintaxe de mapa acima trata cada chave como uma família de fonte separada. Para carregar vários arquivos de fonte (por exemplo, os cortes regular, negrito e itálico) sob um único nome em `fontFamily`, passe ao `useFonts` um array de [`FontFamilyDefinition`](/versions/unversioned/sdk/font/#fontfamilydefinition) em vez de um mapa:

```tsx src/app/_layout.tsx
const [loaded, error] = useFonts([
  {
    fontFamily: 'Inter',
    fontDefinitions: [
      { path: require('./assets/fonts/Inter-Regular.otf'), weight: 400 },
      { path: require('./assets/fonts/Inter-Italic.otf'), weight: 400, style: 'italic' },
      { path: require('./assets/fonts/Inter-Bold.otf'), weight: 700 },
    ],
  },
]);
```

Depois, selecione um estilo com as props de estilo `fontWeight` e `fontStyle`:

```tsx
<Text style={{ fontFamily: 'Inter', fontWeight: '700' }}>Inter Bold</Text>
<Text style={{ fontFamily: 'Inter', fontWeight: '400', fontStyle: 'italic' }}>Inter Italic</Text>
```

Declare todos os estilos de uma família em uma única chamada. Uma `fontFamily` é carregada uma vez, então uma chamada posterior de `loadAsync` ou `useFonts` para um nome que já foi carregado não adiciona estilos a ela. Isso vale também entre os dois estilos de chamada: depois de `useFonts({ Inter: require('./assets/fonts/Inter-Regular.otf') })`, passar um array para `Inter` não carrega mais nada.

Declare `weight` e `style` em todos os estilos de uma família com vários estilos. A web precisa dos dois valores, e valores explícitos mantêm as três plataformas alinhadas. Um único arquivo de fonte variável é a exceção: deixe o `style` sem definir e deixe o `weight` sem definir ou declare um intervalo de pesos, como `'100 900'`. Assim, o Android instancia o eixo `wght` da fonte para cada `fontWeight`, em vez de fixá-la em um peso só.

Notas por plataforma:

- **Android** usa os valores `weight` e `style` declarados e, quando eles não são declarados, usa os valores do próprio arquivo de fonte. Um `weight` declarado fixa um estilo de fonte variável em um único peso, e o Android sintetiza os outros. Abaixo da API 29 (Android 10), só o estilo padrão é carregado, escolhido pelos valores declarados (o mais próximo do peso 400, reto). Fontes incorporadas com o [config plugin](#with-expo-font-config-plugin) usam os recursos XML de fonte do Android e não têm essa limitação.
- **iOS** combina os estilos pelos metadados de peso e estilo incorporados nos arquivos de fonte. Ele usa os valores `weight` e `style` declarados só para escolher o estilo padrão da família quando um arquivo não tem metadados legíveis.
- **Web** gera uma regra CSS `@font-face` para cada estilo, com os valores `weight` e `style` declarados. O CSS não consegue ler os metadados dentro de um arquivo de fonte, então um estilo que não declara `style` é renderizado como reto. Dois estilos de uma mesma família que deixam os mesmos valores sem declarar geram a mesma regra CSS, e o navegador renderiza a última.

## Use o Google Fonts

O Expo tem suporte de primeira classe a todas as fontes listadas no [Google Fonts](https://fonts.google.com/). Elas estão disponíveis pela biblioteca [`@expo-google-fonts`](https://github.com/expo/google-fonts). Com qualquer pacote de fonte dessa biblioteca, você integra rapidamente a fonte e as suas variações.

Há duas formas de usar uma Google Font no projeto:

- Incorporar a fonte instalada com o [config plugin `expo-font`](/versions/latest/sdk/font/#configuration-in-app-config).
- Carregar a fonte instalada com o hook [`useFonts`](/versions/latest/sdk/font/#usefonts) em tempo de execução, de forma assíncrona.

### Com o config plugin `expo-font`

> **Note:** Incorporar uma Google Font com o config plugin `expo-font` tem os mesmos benefícios e limitações de incorporar uma fonte personalizada própria. Veja [usando um arquivo de fonte local com o config plugin `expo-font`](#with-expo-font-config-plugin) para mais informações.

<Step label="1">

Instale o pacote de fonte. Por exemplo, para usar a fonte Inter Black, instale o pacote [`@expo-google-fonts/inter`](https://www.npmjs.com/package/@expo-google-fonts/inter) com o comando abaixo.

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-font @expo-google-fonts/inter'],
    yarn: ['$ yarn expo install expo-font @expo-google-fonts/inter'],
    pnpm: ['$ pnpm expo install expo-font @expo-google-fonts/inter'],
    bun: ['$ bun expo install expo-font @expo-google-fonts/inter'],
  }}
/>

</Step>

<Step label="2">

Adicione o config plugin ao arquivo de [app config](/versions/latest/config/app/#plugins). A configuração precisa conter o caminho do arquivo de fonte usando a propriedade [`fonts`](/versions/latest/sdk/font/#configurable-properties), que recebe um array com um ou mais arquivos de fonte. O caminho do arquivo de fonte é definido a partir do pacote de fonte dentro do diretório `node_modules`. Por exemplo, se você tem um pacote de fonte chamado `@expo-google-fonts/inter`, o nome do arquivo é **Inter_900Black.ttf**.

```json app.json
{
  "plugins": [
    [
      "expo-font",
      {
        /* @info The path to the font file is defined from the font package inside the node_modules directory. */
        "fonts": ["node_modules/@expo-google-fonts/inter/900Black/Inter_900Black.ttf"]
        /* @end */
      }
    ]
  ]
}
```

</Step>

<Step label="3">

Depois de incorporar a fonte com o config plugin, crie um [novo development build](/develop/development-builds/introduction/#how-would-you-like-to-build-your-development-build) e instale-o no seu dispositivo, no Android Emulator ou no iOS Simulator.

No Android, você pode usar o nome do arquivo da fonte. Por exemplo, `Inter_900Black`. No iOS, use o nome da fonte e do peso ([nome PostScript](#what-is-postscript-name-of-a-font)). O exemplo abaixo mostra como usar o [`Platform`](https://reactnative.dev/docs/platform-specific-code#platform-module) para selecionar o nome de família correto para cada plataforma:

{/* prettier-ignore */}
```tsx
import { Platform } from 'react-native';

// Inside a React component:
<Text
  style={{
    /* @info */
    fontFamily: Platform.select({
      android: 'Inter_900Black',
      ios: 'Inter-Black',
    }),
    /* @end */
  }}>
  Inter Black
</Text>
```

</Step>

### Com o hook `useFonts`

> **Note:** Carregar uma Google Font com o hook `useFonts` tem os mesmos benefícios e limitações de incorporar uma fonte personalizada própria. Veja [usando um arquivo de fonte local com o hook `useFonts`](#with-usefonts-hook) para mais informações.

Cada pacote de Google Fonts fornece o hook `useFonts` para carregar as fontes de forma assíncrona. Esse hook acompanha o estado de carregamento e carrega a fonte quando o app é inicializado. O pacote de fonte também importa o arquivo da fonte, então você não precisa importá-lo explicitamente.

<Step label="1">

Instale o pacote do Google Fonts, e as bibliotecas `expo-font` e `expo-splash-screen`.

<Terminal
  cmd={{
    npm: ['$ npx expo install @expo-google-fonts/inter expo-font expo-splash-screen'],
    yarn: ['$ yarn expo install @expo-google-fonts/inter expo-font expo-splash-screen'],
    pnpm: ['$ pnpm expo install @expo-google-fonts/inter expo-font expo-splash-screen'],
    bun: ['$ bun expo install @expo-google-fonts/inter expo-font expo-splash-screen'],
  }}
/>

A biblioteca [`expo-splash-screen`](/versions/latest/sdk/splash-screen/) traz o componente `SplashScreen`, que você pode usar para impedir a renderização do app até que a fonte esteja carregada e pronta.

</Step>

<Step label="2">

Depois de instalar o pacote de fonte, mapeie a fonte usando o hook `useFonts` em um componente de nível superior, como o arquivo do layout raiz (**src/app/\_layout.tsx**) do projeto:

```tsx src/app/_layout.tsx
// Rest of the import statements
/* @info Import `Inter_900Black` and `useFonts` hook from `@expo-google-fonts/inter`*/
import { Inter_900Black, useFonts } from '@expo-google-fonts/inter';
/* @end */
/* @info Import `SplashScreen` so that when the fonts are not loaded, we can continue to show `SplashScreen`. */
import * as SplashScreen from 'expo-splash-screen';
/* @end */
import {useEffect} from 'react';

/* @info This prevents `SplashScreen` from auto hiding while the fonts are in loading state. */
SplashScreen.preventAutoHideAsync();
/* @end */

export default function RootLayout() {
  /* @info Map the font file using `useFonts` hook. */
  const [loaded, error] = useFonts({
    Inter_900Black,
  });
  /* @end */

  useEffect(() => {
    if (loaded || error) {
      /* @info After the custom fonts have loaded, we can hide the splash screen and display the app screen. */
      SplashScreen.hideAsync();
      /* @end */
    }
  }, [loaded, error]);

  if (!loaded && !error) {
    return null;
  }

  return (
    /* @hide ... */ /* @end */
  )
}
```

</Step>

<Step label="3">

Use a fonte no `<Text>` usando a prop de estilo `fontFamily` em um componente React:

```tsx
<Text style={{ fontFamily: 'Inter_900Black' }}>Inter Black</Text>
```

</Step>

### Além de OTF e TTF

Se a sua fonte estiver em um formato diferente de OTF ou TTF, você precisa [personalizar a configuração do Metro bundler para incluí-la como um asset extra](/guides/customizing-metro#adding-more-file-extensions-to-assetexts) para que ela funcione. ### Fontes nativas da plataforma

Se você não quiser usar uma fonte personalizada especificando um `fontFamily`, será usada a fonte padrão da plataforma. Cada plataforma tem um conjunto de fontes integradas. No Android, a fonte padrão é a Roboto. No iOS, é a SF Pro.

A fonte padrão de uma plataforma costuma ser fácil de ler. Porém, não se surpreenda se a fonte padrão do sistema mudar para outra menos legível. Nesse caso, use a sua fonte personalizada para ter controle preciso sobre o que o usuário vê.

### Lidando com o carregamento inicial do `@expo/vector-icons`

Quando os ícones da biblioteca `@expo/vector-icons` são carregados pela primeira vez, eles aparecem como ícones invisíveis no app. Depois de carregados, ficam em cache para todos os usos seguintes do app. Para evitar mostrar ícones invisíveis no primeiro carregamento, faça o pré-carregamento durante a tela de carregamento inicial com o [`useFonts`](/versions/latest/sdk/font/#usefonts). Por exemplo:

```tsx src/app/_layout.tsx
import { useFonts } from 'expo-font';
import Ionicons from '@expo/vector-icons/Ionicons';

export default function RootLayout() {
  useFonts([require('./assets/fonts/Inter-Black.otf', Ionicons.font)]);

  return (
    /* @hide ... */ /* @end */
  )
}
```

Agora, você pode usar qualquer ícone da biblioteca `Ionicons` em um componente React:

```tsx
<Ionicons name="checkmark-circle" size={32} color="green" />
```

### Carregando uma fonte remota diretamente da web

> **warning** **Se você estiver carregando fontes remotas, garanta que elas são servidas de uma origem com CORS configurado corretamente**. Se isso não for feito, a fonte remota pode não carregar corretamente na plataforma web.

Carregar as fontes a partir de um asset local é a forma mais segura de carregar uma fonte no app. Quando as fontes são incluídas como assets locais, depois que você envia o app para as lojas, elas ficam empacotadas no download do app e estão disponíveis imediatamente. Assim, você não precisa se preocupar com CORS nem com outros possíveis problemas.

Porém, é possível carregar um arquivo de fonte diretamente da web substituindo o `require('./assets/fonts/FontName.otf')` pela URL da sua fonte, como mostrado no exemplo abaixo.

<SnackInline label="Usando uma fonte remota" dependencies={['expo-font']}>

```tsx
import { useFonts } from 'expo-font';
import { Text, View, StyleSheet } from 'react-native';

export default function App() {
  const [loaded, error] = useFonts({
    'Inter-SemiBoldItalic': 'https://rsms.me/inter/font-files/Inter-SemiBoldItalic.otf?v=3.12',
  });

  if (!loaded || !error) {
    return null;
  }

  return (
    <View style={styles.container}>
      <Text style={{ fontFamily: 'Inter-SemiBoldItalic', fontSize: 30 }}>Inter SemiBoldItalic</Text>
      <Text style={{ fontSize: 30 }}>Platform Default</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
  },
});
```

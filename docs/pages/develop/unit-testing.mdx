[Jest](https://jestjs.io) é o framework de testes unitários e de snapshot para JavaScript mais usado. Neste guia, você vai aprender a configurar o Jest no seu projeto, escrever um teste unitário, escrever um teste de snapshot e conhecer as boas práticas para organizar os seus testes ao usar o Jest com React Native.

Você também vai usar a biblioteca [`jest-expo`](https://github.com/expo/expo/tree/main/packages/jest-expo), um preset do Jest que faz o mock da parte nativa do Expo SDK e cuida da maior parte da configuração necessária no seu projeto Expo.

## Instalação e configuração

Depois de criar o seu projeto Expo, siga as instruções abaixo para instalar e configurar o `jest-expo` no seu projeto:

<Step label="1">

Instale o `jest-expo` e as outras dependências de desenvolvimento necessárias no seu projeto. Execute o comando a seguir na raiz do diretório do projeto:

<Tabs>

<Tab label="macOS/Linux">

<Terminal
  cmd={{
    npm: ['$ npx expo install jest-expo jest @types/jest --dev'],
    yarn: ['$ yarn expo install jest-expo jest @types/jest --dev'],
    pnpm: ['$ pnpm expo install jest-expo jest @types/jest --dev'],
    bun: ['$ bun expo install jest-expo jest @types/jest --dev'],
  }}
/>

</Tab>

<Tab label="Windows">

<Terminal
  cmd={{
    npm: ['$ npx expo install jest-expo jest @types/jest "--" --dev'],
    yarn: ['$ yarn expo install jest-expo jest @types/jest "--" --dev'],
    pnpm: ['$ pnpm expo install jest-expo jest @types/jest "--" --dev'],
    bun: ['$ bun expo install jest-expo jest @types/jest "--" --dev'],
  }}
/>

</Tab>

</Tabs>

> **Note:** Se o seu projeto não usa TypeScript, você pode pular a instalação do `@types/jest`.

Se o seu projeto usa TypeScript, adicione `"jest"` ao array `types` no seu **tsconfig.json** para habilitar as definições de tipos do Jest:

```json tsconfig.json
{
  "compilerOptions": {
    "types": ["jest"]
  }
}
```

</Step>

<Step label="2">

Abra o **package.json**, adicione um script para executar os testes e adicione o preset para usar a configuração base do `jest-expo`:

```json package.json
{
  "scripts": {
    "test": "jest --watchAll" /* @end */
    /* @hide ... */
  },
  "jest": {
    "preset": "jest-expo"
  }
}
```

</Step>

<Step label="3">

No **package.json**, adicione o `jest-expo` como preset para que a base da configuração do Jest seja criada:

```json package.json
{
  "jest": {
    "preset": "jest-expo"
  }
}
```

</Step>

<Collapsible summary={<>Additional configuration for using <CODE>transformIgnorePatterns</CODE></>}>

Você pode transpilar os node modules que o seu projeto usa configurando o [`transformIgnorePatterns`](https://jestjs.io/docs/configuration#transformignorepatterns-arraystring) no seu **package.json**. Essa propriedade recebe um padrão de regex como valor:

<Tabs>

<Tab label="npm/Yarn">

```json package.json
"jest": {
  "preset": "jest-expo",
  /* @info */
  "transformIgnorePatterns": [
    "node_modules/(?!((jest-)?react-native|@react-native(-community)?)|expo(nent)?|@expo(nent)?/.*|@expo-google-fonts/.*|react-navigation|@react-navigation/.*|@sentry/react-native|native-base|react-native-svg)"
  ]
  /* @end */
}
```

</Tab>

<Tab label="pnpm">

```json package.json
"jest": {
  "preset": "jest-expo",
  /* @info */
  "transformIgnorePatterns": [
    "node_modules/(?!(.pnpm|(jest-)?react-native|@react-native(-community)?|expo(nent)?|@expo(nent)?/.*|@expo-google-fonts/.*|react-navigation|@react-navigation/.*|@sentry/react-native|native-base|react-native-svg))"
  ]
  /* @end */
}
```

</Tab>

<Tab label="Bun">

```json package.json
"jest": {
  "preset": "jest-expo",
  /* @info */
  "transformIgnorePatterns": [
    "node_modules/(?!(.bun|(jest-)?react-native|@react-native(-community)?|expo(nent)?|@expo(nent)?/.*|@expo-google-fonts/.*|react-navigation|@react-navigation/.*|@sentry/react-native|native-base|react-native-svg))"
  ]
  /* @end */
}
```

</Tab>

</Tabs>

O Jest tem muitas opções de configuração, mas a configuração acima deve cobrir a maioria das suas necessidades. Mesmo assim, você sempre pode acrescentar padrões nessa lista. Para mais detalhes, veja [Configurando o Jest](https://jestjs.io/docs/configuration).

</Collapsible>

## Instale o React Native Testing Library

A [React Native Testing Library (`@testing-library/react-native`)](https://callstack.github.io/react-native-testing-library/) é uma solução leve para testar componentes do React Native. Ela oferece funções utilitárias e funciona com o Jest.

Para instalá-la, execute o comando:

<Tabs>

<Tab label="macOS/Linux">

<Terminal
  cmd={{
    npm: ['$ npx expo install @testing-library/react-native --dev'],
    yarn: ['$ yarn expo install @testing-library/react-native --dev'],
    pnpm: ['$ pnpm expo install @testing-library/react-native --dev'],
    bun: ['$ bun expo install @testing-library/react-native --dev'],
  }}
/>

</Tab>

<Tab label="Windows">

<Terminal
  cmd={{
    npm: ['$ npx expo install @testing-library/react-native "--" --dev'],
    yarn: ['$ yarn expo install @testing-library/react-native "--" --dev'],
    pnpm: ['$ pnpm expo install @testing-library/react-native "--" --dev'],
    bun: ['$ bun expo install @testing-library/react-native "--" --dev'],
  }}
/>

</Tab>

</Tabs>

> **warning** **[Descontinuado](/more/release-statuses/#deprecated):** o `@testing-library/react-native` substitui o `react-test-renderer`, que foi descontinuado porque não oferece suporte ao React 19 e versões superiores. Se você estiver usando o `react-test-renderer`, remova-o do seu projeto. Veja [a documentação do React para mais informações](https://react.dev/warnings/react-test-renderer).

## Teste unitário

Um teste unitário verifica a menor unidade de código, geralmente uma função. Para escrever o seu primeiro teste unitário, veja o exemplo a seguir:

<Step label="1">

Dentro do diretório **src/app** do seu projeto, crie um novo arquivo chamado **index.tsx** com o código a seguir para renderizar um componente simples:

```tsx index.tsx
import { PropsWithChildren } from 'react';
import { StyleSheet, Text, View } from 'react-native';

/* @info This is a custom component that will be used in the test. */
export const CustomText = ({ children }: PropsWithChildren) => <Text>{children}</Text>;
/* @end */

/* @info This component currently renders a welcome message on the app screen using the `CustomText` component. */
export default function HomeScreen() {
  return (
    <View style={styles.container}>
      <CustomText>Welcome!</CustomText>
    </View>
  );
}
/* @end */

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#fff',
    alignItems: 'center',
    justifyContent: 'center',
  },
});
```

</Step>

<Step label="2">

Crie um diretório **\_\_tests\_\_** na raiz do diretório do projeto. Se ele já existir no seu projeto, use o que já existe. Depois, crie um novo arquivo chamado **home-screen-test.tsx**. O preset `jest-expo` personaliza a configuração do Jest para também identificar como testes os arquivos com as extensões **-test.ts|tsx**.

Adicione o código de exemplo a seguir no **home-screen-test.tsx**:

```tsx home-screen-test.tsx
import { render } from '@testing-library/react-native';

import HomeScreen, { CustomText } from '@/app/index';

describe('<HomeScreen />', () => {
  test('Text renders correctly on HomeScreen', async () => {
    const { getByText } = await render(<HomeScreen />);

    getByText('Welcome!');
  });
});
```

No exemplo acima, a consulta `getByText` ajuda os seus testes a encontrar o elemento relevante na interface do app e a verificar se determinado elemento existe. A React Native Testing Library oferece essa consulta, e cada [variante de consulta](https://callstack.github.io/react-native-testing-library/docs/api/queries#query-variant) difere no tipo de retorno. Para mais exemplos e informações detalhadas da API, veja a [referência da API de Queries](https://callstack.github.io/react-native-testing-library/docs/api/queries) da React Native Testing Library.

</Step>

<Step label="3">

Execute o comando a seguir em um terminal para rodar o teste:

<Terminal
  cmd={{
    npm: ['$ npm run test'],
    yarn: ['$ yarn run test'],
    pnpm: ['$ pnpm run test'],
    bun: ['$ bun run test'],
  }}
/>

Você verá um teste passando.

</Step>

## Estruture os seus testes

Organizar os arquivos de teste é importante para facilitar a manutenção. Um padrão comum é criar um diretório **\_\_tests\_\_** e colocar todos os testes dentro dele.

Um exemplo de estrutura de testes ao lado do diretório **components** está abaixo:

<FileTree
  files={[
    '__tests__/themed-text-test.tsx',
    'src/components/themed-text.tsx',
    'src/components/themed-view.tsx',
  ]}
/>

Como alternativa, você pode ter vários subdiretórios **\_\_tests\_\_** para diferentes áreas do projeto. Por exemplo, crie um diretório de testes separado para **components** e assim por diante:

<FileTree
  files={[
    'src/components/themed-text.tsx',
    'src/components/__tests__/themed-text-test.tsx',
    'src/utils/index.tsx',
    'src/utils/__tests__/index-test.tsx',
  ]}
/>

Tudo depende de preferência, e cabe a você decidir como organizar o diretório do projeto.

## Teste de snapshot

> **info** **Nota:** Para testes de UI, recomendamos testes end-to-end em vez de testes unitários de snapshot. Veja o guia [Testes E2E com Maestro](/eas/workflows/examples/e2e-tests/).

Um [teste de snapshot](https://jestjs.io/docs/en/snapshot-testing) serve para garantir que a UI continue consistente, especialmente quando o projeto usa estilos globais compartilhados entre componentes.

Para adicionar um teste de snapshot para `<HomeScreen />`, inclua o trecho de código a seguir dentro do `describe()` no **home-screen-test.tsx**:

```tsx home-screen-test.tsx
describe('<HomeScreen />', () => {
  /* @hide ... */ /* @end */

  test('CustomText renders correctly', async () => {
    const tree = (await render(<CustomText>Some text</CustomText>)).toJSON();

    expect(tree).toMatchSnapshot();
  });
});
```

Execute o comando `npm run test` e você verá um snapshot criado dentro do diretório **\_\_tests\_\_\\\_\_snapshots\_\_** e dois testes passando.

## Relatórios de cobertura de código

Os relatórios de cobertura de código ajudam você a entender quanto do seu código está testado. Para ver o relatório de cobertura no seu projeto em formato HTML, no **package.json**, em `jest`, defina `collectCoverage` como true e use `collectCoverageFrom` para especificar a lista de arquivos a ignorar ao coletar a cobertura.

```json package.json
"jest": {
  ...
  "collectCoverage": true,
  "collectCoverageFrom": [
    "**/*.{ts,tsx,js,jsx}",
    "!**/coverage/**",
    "!**/node_modules/**",
    "!**/babel.config.js",
    "!**/expo-env.d.ts",
    "!**/.expo/**"
  ]
}
```

Execute `npm run test`. Um diretório **coverage** será criado no seu projeto. Encontre o **lcov-report/index.html**, abra-o em um navegador e veja o relatório de cobertura.

> Normalmente, não recomendamos enviar o arquivo **index.html** para o git. Adicione `coverage/**/*` ao arquivo **.gitignore** para evitar que ele seja rastreado.

## Fluxos do Jest (opcional)

Você também pode usar fluxos diferentes para executar os seus testes. Abaixo, alguns exemplos de scripts que você pode testar:

```json package.json
"scripts": {
  /* @info Active development of tests, watch files for changes, and re-runs all tests.*/
  "test": "jest --watch --coverage=false --changedSince=origin/main",
   /* @end */
  /* @info Debug, console.logs and only re-runs the changed file.*/
  "testDebug": "jest -o --watch --coverage=false",
   /* @end */
  /* @info Displays code coverage in CLI and updates the code coverage HTML.*/
  "testFinal": "jest",
  /* @end */
  /* @info When a screen or a component is updated, the test snapshots will throw a warning. This script updates them.*/
  "updateSnapshots": "jest -u --coverage=false"
   /* @end */
  /* @hide ... */ /* @end */
}
```

Para mais informações, veja [Opções da CLI](https://jestjs.io/docs/en/cli) na documentação do Jest.

## Migre os testes para o SDK 58

No SDK 58 e versões posteriores, o `jest-expo` exige o Jest 30. Ao atualizar um app existente, atualize o `jest` e o `@types/jest` junto com o `jest-expo`.

Para os testes do Expo Router, atualize também o `@testing-library/react-native` para a versão 14 ou posterior e siga o [guia de migração dos testes do Router](/router/migrate/sdk-57-to-58/#update-router-tests).
